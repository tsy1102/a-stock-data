# ARCHITECTURE_THEORY.md — 架构公理层

> **本文件是本仓库的架构宪法（Theory of the System）。**
> 建立日期：2026-09-03
> 建立动因：项目经多轮次、多执行者增量修改，已出现**增生式架构（accretion architecture）**——
> 每个局部决策单独看都合理，但累积结果无人能完整解释，知识传递断裂，后期维护成本递增。
> 本文件的存在目的：**让每一次修改都能从公理推导出来，而不是从现状反推出来。**

---

## 0. 如何使用本文件

### 0.1 修改前（强制）

任何涉及数据层、契约层、缓存层的修改，动手前必须回答：

1. 本次修改依据/违反哪条公理？
2. 若违反——**必须**在 `docs/DEBT_LEDGER.md` 登记一条债（含偿还计划），否则不允许合入。
3. 若依据——是否需要同步更新本文件或 `AGENTS.md`？

### 0.2 与既有文档的关系

| 文件 | 层级 | 职责 |
|---|---|---|
| **本文件** | **理论层（Why）** | 不可协商的公理。回答"系统应该是什么样" |
| `docs/architecture.md` | 结构层（What） | 模块结构与调用关系现状 |
| `AGENTS.md` | 规约层（How） | 操作规约、高风险文件清单、验证循环 |
| `docs/field_dict.md` | 事实层（Fact） | 字段口径的实测权威结论 |
| `docs/DEBT_LEDGER.md` | **偏离层（Debt）** | 现状对公理的偏离台账，**显式化** |
| `scripts/verify_*.py` | 执行层（Gate） | 公理的可自动化验证部分 |

> **铁律**：理论层 > 结构层 > 规约层。当现状与本文件冲突时，**现状是错的**（无论它存在多久）。
> 这不是说要立刻重构——而是必须**登记为债**，见 A8。

## 1. 系统本体：什么是"统一层"

### 1.1 统一层是一个两层网关，不是一个大对象

```
生产脚本 (main.py / get_*_report.py / sc_report_runner.py)
      │
      ├── Tier1 门面 ─── get_canonical_stock_data()  [core/data_provider.py]
      │                  · 核心 86 字段归一化契约 CanonicalStockData
      │                  · 源选择 + fallback + 单位归一化 + field_sources 溯源
      │                  · 所有报告/策略引擎共用的"横向数据"
      │
      └── Tier2 适配器 ── sc_datasource / sc_fuyao / tdx_client.tdx_get_*
                          · 专精深水数据：CYQ 筹码、F10 财务、涨停梯队、
                            龙虎榜、行业 L2、宏观流向、竞价盘口
                          · 已含 @cached 缓存 + 单位归一化 + sc_network 令牌桶限流
                          · 报告特有的"纵向数据"
      │
原始客户端 ─── _get_tdx_client() / sc_network.em_get / sc_fuyao._fuyao_raw / 裸 requests·httpx
              ↑ 仅允许出现在 stock_common/ 与 core/tdx_client.py 内部
```

### 1.2 关键边界：不要把专精数据塞进 CanonicalStockData

把 CYQ / F10 / 龙虎榜塞进 `CanonicalStockData` 会造出 **god-object**：
86 字段契约被 6 个报告 + 策略引擎消费，混入报告特有数据会过度耦合，
且 fallback 一致性反而更难做（而这正是统一层要解决的原始问题）。

> **Tier2 适配器就是统一层的"专精面"，它不是绕过统一层。**
> 统一层的价值 = 归一化 + 缓存 + 限流 + 溯源，这四件事 Tier2 都已做。

## 2. 公理（Axioms）

> 公理是**不可协商**的。违反不等于不能做——但必须在债务台账显式登记。

### A1 — 数据访问收口（Access Chokepoint）

生产脚本获取外部数据，必须经过 Tier1 或 Tier2 的**公开函数**。
原始客户端（`_get_tdx_client()`、`sc_network.em_get`/`tencent_get`/`_quick_request`、
`sc_fuyao._fuyao_raw`、裸 `requests`/`httpx`）**仅允许**在 `stock_common/` 与
`core/tdx_client.py` 内部出现。

- **理由**：集中治理源选择、限流、缓存、可观测。分散直连 = 风控失效 + 口径不一。
- **自动化验证**：`scripts/verify_data_access.py`
- **已知偏离**：DEBT-001、DEBT-002

### A2 — 单一事实源 / 无冗余别名（Single Source of Truth）

每一个业务语义在契约中**有且仅有一个**权威字段、一个权威口径。
禁止：两个字段数值恒等（冗余别名）；同一语义跨源取不同单位。

- **理由**：冗余别名会让下游误以为是独立口径，从而产生**假的交叉验证**。
- **自动化验证**：待建 `verify_redundant_alias.py`
- **已知偏离**：无（DEBT-003 `pe_more` ≡ `pe_ttm`、DEBT-004 `pe_static`/`pe_lyr` 双键已于 V17.0.25 偿还，见 DEBT_LEDGER.md）

### A3 — 边界归一化（Normalize at Boundary）

单位与口径必须在进入 `CanonicalStockData` **之前**统一。
契约内部不允许存在"同语义两种单位"的字段。字段注释**必须写明单位**。

- **理由**：契约是消费方的唯一依赖，单位歧义会静默放大 10 倍级错误。
- **已知偏离**：DEBT-005（腾讯 [6]/[7] 688 段=股 vs 其余=手，已由
  `_tencent_volume_divisor` 收敛，属已解决但需保持警惕）

### A4 — 缓存只存非空 + 财报事件锁（Cache Integrity）

① 只缓存非空结果（空结果写盘会投毒整个 TTL）；
② 财报类缓存 Key 必须含 `report_date`（报告期切换瞬时刷新）；
③ 新增网络接口**必须自带缓存**（`sc_network` 只有令牌桶+熔断，无数据缓存）。

- **理由**：push2 主域触限恢复实测 20+ 小时；空结果缓存会导致整日数据缺失。
- **自动化验证**：`sc_kline_cache` 写入守卫（已落地）
- **已知偏离**：DEBT-006（`get_em_quote_full` 主域有意不缓存）

### A5 — 契约无孤儿（No Orphan Fields）

契约字段必须至少有一个消费方。新增字段必须同时更新：
**字典 → 契约 → 消费方** 三处；若暂不接消费方，**必须**在台账登记为"预留"并注明用途。

- **理由**：只加不用的字段会让契约失去权威性（无法区分"重要但未接"和"废弃"）。
- **自动化验证**：待建孤儿字段检测
- **已知偏离**：DEBT-007（`avg_price`/`beta`/`bid_ask_net` 已入契约，零消费方）

### A6 — 缺失即缺失（Absence ≠ Zero）

0 不是中性值，常是极值。缺失数据必须**不参与计算**，不得用 `x or 0` 降级。

- **理由**：把缺失降级为 0 会让"无数据"伪装成"极小值"，扭曲排序与阈值判定。

### A7 — 文档与代码同真（Doc-Code Coherence）

字典/文档的"定案"结论必须与代码一致。字典变更必须同步代码，代码变更必须同步字典。

- **理由**：本项目已 4 次因"注释说已定案但实际未生效"而翻车。
- **自动化验证**：`scripts/verify_sync_check.py`（HARD 1–4 闸门）
- **已知偏离**：无（DEBT-008 med 报告 `pe_more` 假交叉验证已于 2026-09-03 偿还）

### A8 — 理论优先于便利 / 禁止静默迁就（Theory over Expediency）★元公理

> **本条约束的是"修改行为本身"，是最重要的一条。**

当"最小化修订"会与 A1–A7 冲突时，执行者**必须二选一**：

1. **按公理改**（哪怕改动面扩大）；或
2. **在 `docs/DEBT_LEDGER.md` 登记偏离**，写明真实原因 + 偿还计划 + 到期日。

**绝对禁止**：静默迁就——明知违反公理，却因为"改动大/风险高"而不改、也不记账。

- **理由**：静默迁就是增生式架构的唯一成因。显式债务是可偿还的，隐形债务是不可理解的。
- **健康指标**：台账条目数应**单调下降**。若持续增长，说明理论未被遵守。

## 3. 执行的机制化保证

| 机制 | 载体 | 何时用 |
|---|---|---|
| 公理 | 本文件 | 修改前判断依据 |
| 债务台账 | `docs/DEBT_LEDGER.md` | 每次"选择不改"时登记 |
| 架构决策记录 | `docs/adr/NNNN-*.md` | 非显然的架构决策（含"决定不改"） |
| 自动化闸门 | `scripts/verify_*.py` | 每次提交前 |
| 项目记忆 | `.workbuddy-ai/memory/MEMORY.md` | 长期事实沉淀 |

### 3.1 反模式清单（见到即应登记为债）

| 反模式 | 表现 | 对应公理 |
|---|---|---|
| 双写兼容 | 同一语义出两个键（新旧并存） | A2 |
| 追溯性自洽 | 把历史偶然结构重新包装成"设计" | A1 |
| 只改定义不改消费方 | 加了注释说明已废弃，但下游仍按旧语义用 | A2/A7 |
| 孤儿字段 | 加进契约就当完成，无人消费 | A5 |
| 语义漂移 | 模块的实际职责已变，名字/文档未变（如 FIELD_SPECS） | A7 |
| 静默降级 | `x or 0` / 空结果写缓存 | A6/A4 |
