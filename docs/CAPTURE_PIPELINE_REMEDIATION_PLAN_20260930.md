# 采集流水线整改计划（2026-09-30）

## 实施状态

**状态：已完成。** 未发起真实数据源请求；专项回归与仓库离线验证结果见本文件末尾。

## 目标

采集器的职责是按主字典登记的源持续保存原始字段，供后续跨日、跨源破解使用。因此每个源都必须有可追溯的原始结果；请求失败、数据缺项、被限流、未到可用时段和预期跳过必须能区分。整改保持当前 `raw_{source}.json` 的成功数据结构；若现有 scheme 与实际采集端不符，则同步纠正。独立源不因字段重合而合并，也不触发真实网络采集。

## 已确认的问题

1. `assess_result()` 只识别 `__error__` / `__skipped__`，部分采集器返回 `error`、`*_error` 或交易所专用错误键时会被记为成功。
2. 对 `stocks={}`、缺失请求股票、缺少必需的源级分组等空结果没有统一完整度检查。
3. `collect_eltdx()` 对逐股 `shortline_indicators` 异常直接 `continue`，导致重要字段静默缺失；盘前 helper 未就绪也没有明确的“尚未采到”状态。
4. `ulist239` / `slist` 丢失 HTTP 域、状态码、封禁和尝试次数等请求诊断；若干 Eastmoney 路径没有显式单次请求约束。
5. 默认完整性判断只检查 raw 文件是否存在，失败/部分文件也会被当成完整快照；退役占位源又没有 raw 文件，导致该规则对完整运行不可靠。
6. `market_phase` 根据目标数据日期而非本次实际采集时刻计算，含义与数据日期混在一起。
7. `axdata` 实际读取本地 ZHB/AxData 短线指标，却被标为 `em.stock_get`，会污染源独立性判断。

## 分阶段实施

### 阶段一：采集结果契约与完整度（已完成）

- 扩展源级结果评估，兼容识别现有错误标记，不要求所有旧 raw 文件迁移。
- 为逐股源核对预期股票代码集合，记录 `expected / received / missing`；空响应和缺失代码必须使源状态为 `partial` 或 `failed`。
- 为已知市场级源声明最低容器/类别要求；在可证明应有结果的路径上拒绝缺失或 `None` 响应，并保留可合法为空的列表/容器。
- 区分错误、预期跳过与时段性 deferred；deferred 在本次采集健康摘要中可见且不能记为完整成功。
- 纠正 `axdata` 的 scheme，使采集元数据与其本地短线指标真实来源一致，并同步治理脚本回退映射。

### 阶段二：错误可见性和来源请求保护（已完成）

- 保持采集串行执行和 `sc_network` 既有限流器，不在采集层增加并发或更快的重试。
- 涉及的 Eastmoney 直连采集请求显式使用单次尝试；记录域、错误类型、HTTP 状态和尝试次数，去掉会丢失诊断的通用错误文案。其余适配器继续使用自身限流/重试配置。
- 失败源不做无条件立即重试；仅使用已定义的安全回退路径，识别到封禁后停止继续轰击同一受限域。
- `market_sources` 的独立子源分别捕获异常，单个接口失败不跳过同组其他接口；旧错误键统一纳入健康判断。

### 阶段三：eltdx 与时段状态（已完成）

- 对每只股票记录 shortline 的成功、跳过或错误；保留 BSE 既有安全跳过规则。
- 开盘前 shortline/global helper 未就绪时标记为 deferred，不伪装成数据源故障或完整成功。
- 元数据保留 `data_date`（目标数据日），新增/校正 `capture_market_phase`（实际采集时段）；不改变按数据日命名的目录。
- 在来源元数据中记录采集器已知的真实 as-of 日期；未知时不伪造日期，沿用日期选择器的显式回退规则。

### 阶段四：幂等与增量重采（已完成）

- 完整运行只在本次应采的 producer 均有 raw 文件且元数据状态完整时才跳过。
- `unwired` / `deprecated` 作为明确状态，不要求对应 raw 文件；失败、partial、deferred 源允许定向重跑。
- 覆盖/盘中转盘后刷新只处理本次目标源，保留其他源文件与 `--only` 元数据合并行为。
- 全量幂等判断重新读取既有 `meta.json`；`--only` 会执行指定采集器，不会被已有快照短路。

### 阶段五：回归与文档（已完成）

- 给结果评估、逐股覆盖率、Eastmoney 单次请求与诊断、eltdx deferred、独立子源隔离、幂等重跑增加离线模拟测试。
- 按仓库约定运行采集器专项测试，再运行离线全套测试；执行语法、格式、类型、数据访问/字典同步闸门中适用于本次改动的检查。
- 更新 `scripts/README.md`、`docs/field_verification/README.md` 与 `CHANGELOG.md`，明确采集状态含义和限流行为。

## 约束与验收

- 不改变成功 raw 数据的既有字段结构、字段索引或目录命名；只纠正经代码调用链证实错误的来源 scheme。
- 不把两个独立源因字段重合而合并；原始结果必须保留真实采集来源。
- 保持串行与各源现有限流；Eastmoney 单端点每个逻辑采样最多一次，不因失败扩大请求量。
- 离线测试证明：空结果/缺股票/旧错误键不能标成功；预期跳过与 deferred 可区分；失败快照不会阻止重采；成功完整快照仍幂等跳过。
- 全流程不得产生任何真实数据源请求。
