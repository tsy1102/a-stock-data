### DEBT-013 — make_valid_if 的 min_size off-by-one（静默降低缓存命中）

| 项 | 内容 |
|---|---|
| **违反公理** | A7（文档代码同真）/ A4（缓存有效性） |
| **位置** | `core/stock_cache.py:666`（`make_valid_if.validator` 第 2 项长度校验） |
| **原状** | 判据为 `len(r) <= min_size` → `min_size=1` 实为「要求 **≥2** 条」。而全仓 5 处调用点注释写的都是「**至少 1** 条 / 至少 1 只股票才缓存」 |
| **危害** | 不产生错误数据，属**静默失效**：恰好 1 条记录的结果**永不入缓存** → 每次都重新打网络。在 push2 主域上即**白付风控成本**。影响 5 个调用点：`data_provider.get_market_snapshot`、`sc_datasource` 两处 `dragon_tiger`、`ths_hot_reason`、`get_em_board_members` |
| **发现途径** | 实现 DEBT-012 时给 `get_em_board_members` 加 `@cached(min_size=1)` 后写「二次调用应命中缓存」测试**转红**（em_get 被调 2 次）→ 反查 validator 发现 |
| **偿还** | 改为 `_min_len = max(1, min_size); if len(r) < _min_len: return False`。语义两点：**空容器恒拒绝**（保持 `min_size=0` 的默认行为不变，否则会波及所有 `make_valid_if()` 默认调用点如 financial/balance_sheet/industry_compare），且 `min_size=N` 表示「至少 N 条」 |
| **验证** | `tests/core/test_core_cache.py` 新增 11 例参数化边界断言（`min_size=0/1/2` × 空/1条/2条 + None + 全零 dict），钉死语义防止改回 |
| **教训** | **这是「测试先于重构」的又一次收益**：若按原计划直接加缓存而不写断言，这个 off-by-one 会让 DEBT-012 的缓存**实际只覆盖 ≥2 条成分股的板块**，1 条的不缓存——表面上"缓存加好了"，实际部分失效且不报错 |
| **状态** | `RESOLVED`（2026-09-04） |
