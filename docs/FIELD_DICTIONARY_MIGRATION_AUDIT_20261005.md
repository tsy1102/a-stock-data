## 3. 属性与状态差异的处理口径

原字典的部分章节将字段写在来源家族、接口章节或共享表格下，不能可靠推出每一个 token 对应的来源和完整路径。逐源模型因此不把章节级结论直接复制到所有同名字段。比较原文抽取视图与新的逐源记录时，**847 条共有身份记录至少有一个展示属性不同**：canonical 231 条、meaning 304 条、section 641 条、status 615 条、status_raw 284 条、unit 123 条（各属性计数可重叠）。这些是粒度/归属差异，不是字段身份缺失；原文全文与旧注册表聚合值均按上节留存，状态未被静默覆盖。

逐源状态解析共 2,469 条：

| 解析类别 | 数量 | 处理 |
|---|---:|---|
| `matched` | 884 | 原文与注册表结论可逐源匹配 |
| `registry_status_only_single_source` | 938 | 保留单源注册表状态，不从其他来源外推 |
| `aggregate_status_scope_unresolved` | 513 | 旧状态仍在聚合快照中，但无法安全归属到具体源路径；按未验证处理 |
| `status_conflict` | 69 | 两侧状态冲突，列入复核队列，不作为锚 |
| `reference_status_conflict` | 22 | 原文字段证据内部有冲突，列入复核队列，不作为锚 |
| `status_missing` | 43 | 新补入的原文关系没有可确认状态，不推断字段含义或状态 |

当前逐源状态为 verified 828、unverified 1,549、candidate 1、conflict 91、disproved 0。计数粒度与重整前聚合状态不同，不应作简单增减比较。腾讯 `[86]` 的旧聚合状态 `disproved` 与原文另一条 `verified` 声明相冲突，因此当前记录为 `reference_status_conflict`；两侧原始状态和证据均保留，字段不能成为碰撞锚。
