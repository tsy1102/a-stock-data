# 项目大体检（2026-10-15）

## 结论

项目的核心分层仍然清楚：`main.py` 调度五大报告，报告 Runner 负责流水线，Tier 1 门面统一核心字段，Tier 2 适配器承接专项数据，底层客户端留在数据层。当前证据不支持大规模搬迁目录或重写统一层；本轮聚焦修复已确认缺陷、清理静态冗余、校正文档，并补足回归覆盖。

本轮发现并修复了两个会影响结果的缺陷：合法的零股息率被误当成缺失值；东财行业磁盘缓存命中时只恢复行业映射，成分股映射留在另一个模块状态中。还修正一个静态检查中的未定义类型名，并清理确认未使用的导入和空操作。

## 检查范围

按当前 Git 清单统计：529 个跟踪文件，包括 214 个 Python 文件、78 个测试模块和 259 个 Markdown 文件。检查覆盖五大报告入口、调度器、统一数据层、数据适配器、采集与碰撞脚本、字段字典生成/登记流程、测试分层、依赖声明、项目入口文档及本地文档链接。

本轮为离线审查和回归，没有运行采集脚本或请求外部数据源。

## 架构判断与后续建议

- 保留现有 Tier 1/Tier 2 数据访问边界。五大报告的不同批量源路由是按数据负载划分的，不建议仅为文件数量统一抽象或迁移目录。
- 报告正文的端到端 Markdown 渲染覆盖仍有限。现有用例验证流水线、章节保留和关键内容；后续可逐步为五大报告增加稳定的输出契约测试，优先覆盖用户可见字段、告警和缺失值展示。
- `get_fund_flow_weighted` 已在代码中标记弃用且仓库内没有业务调用，但仍通过 `stock_common` 导出；为避免破坏外部脚本，本轮保留该兼容入口。Vulture 的唯一剩余提示是它的 `tdx_data` 参数未使用。若要删除该参数或接口，应先完成外部调用迁移。
- 碰撞研究状态和来源交叉表体积较大：`collision_research_state.json` 约 36.3 MiB，`axdata_interface_crosswalk.json` 约 15.4 MiB。它们保存后续字段破解和接口核验需要的历史状态，不应按普通缓存清理。可另行评估 Git LFS 或可校验的压缩归档，但必须保留读取兼容与校验路径。

## 保留的历史文件

本轮没有删除跟踪文件。名称带有 `bak` 或 `tmp` 的旧注册表也不是可直接丢弃的临时副本：核对发现，旧注册表中有 1,820 条来源与字段身份组合，614 条未出现在当前注册表；`_reg_tmp_test.json` 也包含当前文件没有的历史登记信息。删除会丢失溯源证据，故继续保留并视为历史档案，而非当前权威数据。

大体积的原始行情样本、历史适配器快照和本地依赖 wheel 同样保留：它们分别用于复核字段、理解迁移前实现和复现固定依赖。当前权威规则仍以代码、主字典及其生成登记为准。
