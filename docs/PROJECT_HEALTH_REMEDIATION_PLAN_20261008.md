## 分阶段实施

### 阶段 1：运行时和依赖约束对齐

- 将项目最低 Python 版本统一为 AxData 0.1.4 可支持的版本；保留 Python 3.12 作为推荐和本轮验证环境。
- 将 ELTDX 固定到本项目实际完成回归的版本；未回归的新版本不进入开放依赖范围。
- 修复开发依赖中的 YAML 类型存根缺失，并消除 MyPy 对同一模块的双重导入路径。
- 明确安装与启动说明，避免元数据、README、开发依赖和 PowerShell 包装器各自给出不同口径。

**验收**：依赖解析与 `pip check` 通过；项目元数据和文档的 Python 版本口径一致；MyPy 不再报告已知两项错误。

### 阶段 2：腾讯逐笔完整性与限流重试

- 对照 Simonlin 上游 v3.10.1，给逐笔返回值增加 `frame.attrs["complete"]` 的三态契约：可确认完整、确认不完整、当前无法确认。
- 保留现有 `missing_seq`、成交额字段和异常契约；盘后核对仅使用取数前快照时间及快照盘后金额字段，严格处理缺字段、盘中和边界时刻。
- 在通用网络层提供向后兼容的、可显式选择的请求重试策略；腾讯逐笔连接复用，重试连接/握手/响应头超时、429 与 5xx，不重试 403，不因本改动扩大其他数据源的重试范围。
- 为完整性三态、金额容差、盘后边界和每种重试状态补充离线测试；联网测试仍保持显式 opt-in。

**验收**：针对新行为的离线回归通过；默认其他请求调用方的既有契约不变；403 不产生同请求重试；逐笔缺尾/无字段/未到核验时点不会误报为完整。

### 阶段 3：字段口径、字典缺口与源映射治理

- 依据实际 Schema、字段规格和 ELTDX 扩展字段重新定义计数术语，修正 README、架构文档、模块说明与仓库规约中互相矛盾的 34/38/86/113 口径。
- 保持主字典为字段事实源；只补有采集证据、代码契约或上游权威说明支持的字段元数据。
- 为已验证但缺 canonical name / meaning 的条目生成可复核缺口清单或改进现有生成报告；不猜测、不改变其 verified 状态。
- 保持未确认的五组上游仓库映射为待确认状态，说明其不会阻止其他整改，但需要用户提供关系证据后才能闭环。

**验收**：字典生成检查和 parity 通过；文档计数与脚本实测一致；未产生无证据字段定义或上游映射。

### 阶段 4：死代码、接口行为与静态检查

- 修复 `tdx_get_board_members(sort_by_change=...)` 无效参数：TDX 与 Eastmoney fallback 均按涨跌幅降序，关闭选项时保留源顺序；对应两个离线测试通过。
- 保留 `get_fund_flow_weighted` 的导出兼容桩：确认项目内没有活跃调用，函数已明确标为废弃且不伪装为计算成功。保留 `chinabond_yield_curve` 明确占位：宏观上下文通过它呈现曲线不可用状态，采集探针记录该能力；未把空返回描述为真实中债数据。`HTTP_TIMEOUT_SECONDS` 已接入通用请求超时默认值，不再是未使用常量。
- 规范 `scripts` 包导入，保留 `python scripts/collide.py` 直接运行能力；对旧日期命名破解实验从活动 MyPy 检查中排除。Black 使用 `force-exclude` 跳过显式传入的归档脚本路径；没有批量重排历史脚本。
- 修正真实网络测试默认闸门：默认全量模式显式排除 `real_network`；本地 fixture 在没有显式环境变量时跳过标记测试；`-Mode real` 只在子进程期间启用并恢复调用环境。流式错误响应在重试前关闭。
- 为以上行为增加离线回归测试并更新 changelog。

**验收**：行为变化有调用方和测试证据；MyPy 达到既定目标；活动代码 Black 检查通过；历史归档不被无差别重排。
