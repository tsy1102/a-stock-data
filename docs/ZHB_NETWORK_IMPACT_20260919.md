## 一、与现有项目内容是否冲突？

**结论：基本无硬冲突；1 处完整性陷阱（ilong 缺基准指数）须按"补充"而非"替换"接入。**

| 新解析器 | 现有项目对应物 | 关系 | 冲突？ |
|---|---|---|---|
| `tdxbk.cfg` 板块简称(58) | `spblock.dat`(35 大板块) + `tdxzs3.cfg`(467 申万) | 范围互斥、0 重叠：`tdxbk`=概念板块全称→简称；`spblock`=指数/大板块；`tdxzs3`=申万行业 | **互补，无冲突** |
| `tend_std.cfg` 概念树(100组/201概念) | `tdxchain.cfg`（V15.1 已重写为板块代码→名称，无成员） | 概念分组层 vs 板块映射层，不同维度 | **互补，无冲突** |
| `addedcode_bj`+`tdxbjmore` 北交所元数据(351) | `tdxstat.cfg`(349 只 92 前缀代码) | 351 vs 349，仅多 2 只，代码已全覆盖 | **一致，互补** |
| `ilong.dat` 指数名(566) | 项目**此前无任何离线指数字典**（`zhb_client.py:1376` 自证） | 首个指数名源，无既有字典可冲突 | **无既有冲突，但自身残缺** |

### ⚠️ ilong 完整性陷阱（关键）
`ilong.dat` 第一列为**指数公司代码**（62=中证、1=上交所…），第二列为 `CES100/930912/000985/H11001` 等**中证/细分/跨境/债券/ESG 指数**，**不含五大 A 股基准指数**：
- 缺失：`000001`(上证)、`399001`(深证成指)、`399006`(创业板指)、`000300`(沪深300)、`000905`(中证500)。
- 实测 9 个常见代码（含 HSI/SPX/DJI/N225）全部缺失。
- 若把 `index_names` 当作**唯一**指数名源，五大基准指数将"漏名"（仅显示代码）。**必须作补充 + fallback 到代码显示**，不得改写为"联网替代"。

## 二、能否替代联网取数 / 降低网络消耗？

**结论：新解析器基本不降低网络消耗；它们多为"离线补充"或"新能力"，未触及真正的网络消耗项。**

### 逐项判定
| 新解析器 | 当前是否联网取数？ | 能否替代/降网？ |
|---|---|---|
| `tdxbk` 板块简称 | 板块**名称**早已本地（spblock/tdxzs3） | **不降网**（仅展示富化） |
| `tend_std` 概念树 | 概念**分类**此前无本地源，但概念**成员**走 push2/eastmoney | **不降网**（分类补充，成员仍联网） |
| `hspy` 拼音助记码(22) | 项目原本**无拼音能力、无对应网络取数** | **纯新增能力，无网可替**（且仅 22 条，覆盖极小） |
| `addedcode_bj/tdxbjmore` 北交所元数据 | 市场代码早已本地（tdxstat 8055 全代码） | **不降网**（元数据补充） |
| `hqrule` 交易规则(11条) | 涨跌停阈值原是**代码硬编码**（非网络） | **不降网**（替代硬编码，提升可维护性） |
| `ilong` 指数名 | 项目**无网络取指数名**（指数仅本地 TDX 行情，名称此前不展示/显示代码） | 唯一源但**残缺**，只能作补充，**无对应网络取数可替** |

### 真正的网络消耗项（新解析器一个都没碰）
1. **个股名称**：`data_provider.py:700` 注明 name 优先级 `push2/tencent/tdx > ZHB`。ZHB 离线名因历史 bug（`zhb_client.py:316`，已修）但 `profile.dat` 仅 1651/8055 名，`unified_name_map` 覆盖 ~30%，故个股名**仍主要耗腾讯/push2 网络**。
2. **板块成分股（概念板块）**：`get_em_board_members`(eastmoney) / push2，`board_members` 缓存 15min。ZHB 仅含 35 大板块成员（`spblock`），**覆盖不到概念板块成员**。
3. **实时行情/估值/资金流**：push2/腾讯/东财/同花顺（大头，本就超出 ZHB 文件内容范畴）。

## 三、现有 ZHB 究竟降了多少网络？（澄清用户疑问）

**现有 ZHB 已大幅降低两类网络消耗，新文件边际贡献很小：**

- ✅ **全市场统计快照**：`tdxstat`/`tdxstat2`(8055 只) 本地 → val 全市场扫描 100% 本地命中、零 TCP/HTTP 兜底（市盈率/涨跌幅/52周高低/封单额等）。
- ✅ **35 大板块成分股**：`spblock.dat` 本地 → 中证2000/沪深港通等免网络。
- ✅ **申万行业/产业链名称**：`tdxzs3`/`tdxchain` 本地。
- ⚠️ **个股名称**：仅 ~30% 本地（profile.dat 容量瓶颈），其余仍联网。
- ❌ **概念板块成员 / 实时行情**：仍联网。

**新五项 = 展示增强 + 新能力（拼音/概念树/板块简称/北交所元数据/动态规则），未改变上述网络依赖结构。**

## 四、结论与建议

1. **冲突**：无硬冲突；`ilong` 须按"补充+fallback 代码"接入，避免漏名回归。
2. **网络消耗**：新解析器**不降低**网络；现有 ZHB 已承担了"全市场快照/大板块成员/申万名称"的本地化，新文件是补充层。
3. **若真要再降网络，唯一可落地的 ZHB 杠杆是强化"个股名"离线解析**：
   - 把 `profile.dat + relation.dat + tdxpkmore.cfg + pttab.dat` 的 `unified_name_map` 从 ~30% 提覆盖（这是 **EXISTING ZHB**，非本次新增），可让个股名少打腾讯/push2。
   - 必要性：个股名是 `get_canonical_stock_data` 高频路径，覆盖提升对网络节流最直接。
4. **建议落地动作**（待授权再改代码）：
   - `ilong.index_names` 接入时强制 `name or code` fallback；
   - 五个新属性维持"离线补充/展示增强"语义，不改写为"联网替代"标签。
