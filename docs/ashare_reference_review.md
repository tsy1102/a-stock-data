# Ashare 参考仓库研究 & 本项目改进规划

> 调研对象：https://github.com/mpquant/Ashare （含其配套指标库 https://github.com/mpquant/MyTT）
> 日期：2026-09-11 ｜ 性质：**只做分析与规划，未改动任何生产代码**
> 证据口径：仓库源码逐行阅读 + 本项目源码对照 grep + **今日 curl 实测**（三处端点现场验证）

## 0. 结论摘要（先看这个）

**Ashare 与本项目不在同一抽象层，可借鉴的是「点」不是「面」。**

| 维度 | Ashare | 本项目 | 判定 |
| :--- | :--- | :--- | :--- |
| 定位 | 极简行情**取数便利库**（~60 行单文件） | 多源私有协议**字段逆向 + 数据可信度工程** | 目标不同，不可整体照搬 |
| 对外接口 | 1 个 `get_price()` | `get_canonical_stock_data()` 86 字段契约 + `field_sources` | 本项目更严格，理念已一致 |
| 源数量 | 2（新浪主 + 腾讯备，try/except 热切换） | 23 源，Tier2 适配器 + 分域限流 | 本项目更完备 |
| 字段规模 | 6 列 DataFrame | 2252 字段 / 23 源（field×source 配对 3260，详见 `docs/field_verification/field_registry.json`） | 本项目远超 |
| 指标库 | 配套 MyTT（~25 指标 + ~35 核心函数） | `sc_technical.py`：MACD/RSI/BOLL/KDJ/MA/CYQ/形态 | **MyTT 是真正的富矿** |

**净结论：3 项可直接落地（2 项零风险）、1 套指标库值得移植、1 条理念可采纳、2 条须明确拒绝。**

- ✅ **可直接借鉴（已实测验证）**：
  1. **新浪纯 JSON host** —— 项目现用 jsonp host 需正则剥壳，纯 JSON host 数据逐字一致但更干净；
  2. **新浪 `ma=5`** —— 项目传 `ma=no`，**白丢 2 个字段**（`ma_price5` / `ma_volume5`）；
  3. **新浪 `scale=1200/7200`** —— 实测返回周线/月线，字典只登记到 `240`，**缺口 2 个枚举值**。
- ✅ **值得移植**：MyTT 的 **0级/1级核心函数库 + ~25 个指标**（纯 numpy/pandas，零新依赖），可补齐项目技术面分析。
- ✅ **理念可采纳 1 条**：备用源「**输出等价性契约**」——把"降级不改变语义"从人肉约定升级为可断言的不变式。
- ❌ **须明确拒绝 2 条**：裸 `except:` 静默降级（违反 A8）、`fields=[]` 死参数（违反 A5）。

## 1. Ashare 仓库画像

### 1.1 规模与结构

| 项 | 值 |
| :--- | :--- |
| 核心文件 | `Ashare.py`（**单文件，约 60 行**） |
| 其他文件 | `MyTT.py`（指标库，独立仓库）、`Demo1.py` / `Demo2.py`、`img/`、`.github/` |
| 最近更新 | `Ashare.py` 2025-12-24；`MyTT.py` 2025-08-02 |
| 依赖 | `requests` + `pandas`（**仅此两个**） |
| 设计目标 | "简单 轻量 便携 开源"；`from Ashare import *` 随用随走 |

### 1.2 唯一对外函数

```python
get_price(code, end_date='', count=10, frequency='1d', fields=[])
```

- `frequency`：`1d`/`1w`/`1M`（日/周/月）与 `1m`/`5m`/`15m`/`30m`/`60m`（分钟）
- 返回：`DataFrame`，索引=时间，列=`open, close, high, low, volume`（**固定 6 列**）
- 代码格式兼容：`sh600519` / `600519.XSHG` / `600519` 三种写法互认

### 1.3 双核热备机制（Ashare 的核心卖点）

```python
if frequency in ['1d','1w','1M']:
    try:    return get_price_sina(...)    # 主力
    except: return get_price_day_tx(...)  # 备用
```

一主一备、`try/except` 自动切换。**注意：这是本项目 A8 明令禁止的写法**（裸 `except` 无日志、无降级记录），见 §5.4。

### 1.4 使用的三个端点

| # | 用途 | 端点 |
| --: | :--- | :--- |
| 1 | 新浪全周期（主力） | `money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData` |
| 2 | 腾讯日/周/月（备用） | `web.ifzq.gtimg.cn/appstock/app/fqkline/get?param={code},{unit},,{end_date},{count},qfq` |
| 3 | 腾讯分钟线 | `ifzq.gtimg.cn/appstock/app/kline/mkline?param={code},m{ts},,{count}` |

### 2.2 实测证据 A：新浪两个 host 的数据一致性

```
A. money.finance.sina.com.cn/.../json_v2.php/CN_MarketData.getKLineData?scale=240&ma=no
   → [{"day":"2026-09-09","open":"1305.010","high":"1309.300","low":"1286.680","close":"1290.880","volume":"3222611"}, ...]
   ✅ 纯 JSON 数组，无包装、无前缀

C. quotes.sina.cn/cn/api/jsonp_v2.php/var/CN_MarketDataService.getKLineData?scale=240&ma=no
   → /*<script>location.href='//sina.com';</script>*/
     var([{"day":"2026-09-09","open":"1305.010",...}])
   ⚠️ jsonp 包装 + 防盗链前缀，必须正则剥壳（生产代码正是这么做的）
```

**数据逐字一致**（2026-09-09 茅台：`1305.010 / 1309.300 / 1286.680 / 1290.880 / 3222611`）。
→ 生产代码用了一个**更麻烦**的 host。改用纯 JSON host 可**删掉正则剥壳逻辑**，降低脆弱性。

> 附带发现：字典 §12.2 L1185 登记的 URL 是纯 JSON host，**生产代码却没按字典实现** —— 这是 A7（文档代码同真）的一处待闭合缺口。

### 2.3 实测证据 B：新浪 `scale` 全映射（字典缺口 2 个枚举）

| scale | 含义 | 实测结果 | 字典登记 |
| --: | :--- | :--- | :--- |
| 5 / 15 / 30 / 60 | 5/15/30/60 分钟 | — | ✅ L1186 已登记 |
| 240 | 日线 | ✅ 日线（09-09/09-10/09-11） | ✅ L1186 已登记 |
| **1200** | **周线** | ✅ **实测返回周线**（08-28 / 09-04 / 09-11） | ❌ **缺登记** |
| **7200** | **月线** | ✅ **实测返回月线**（07-31 / 08-31 / 09-11） | ❌ **缺登记** |

→ Ashare 用 `frequency.replace('1d','240m').replace('1w','1200m').replace('1M','7200m')` 一次性给出全映射，
**实测成立**，可直接用于补齐字典 §12.2。

### 2.4 实测证据 C：新浪 `ma` 参数（项目白丢 2 个字段）

```
ma=no → [{"day":"...","open":"...","high":"...","low":"...","close":"...","volume":"..."}]          6 字段
ma=5  → [{"day":"...","open":"...","high":"...","low":"...","close":"...","volume":"...",
          "ma_price5":1306.264,"ma_volume5":2786513}]                                               8 字段
```

生产代码传 `ma="no"`（`_eastmoney.py:1681`），**主动丢弃 `ma_price5` / `ma_volume5`**。
Ashare 传 `ma=5`，零额外成本多拿 2 个字段。→ **字段层面唯一可直接捡的现成收益**。

### 2.5 实测证据 D：腾讯 `mkline` 结构（分钟线真缺口）

```
GET https://ifzq.gtimg.cn/appstock/app/kline/mkline?param=sh600519,m5,,3

{"code":0,"msg":"","data":{"sh600519":{
   "qt":  {"sh600519":[ ...88 个元素... ]},        ← 完整实时快照(与项目现有腾讯 88 字段同构)
   "m5":  [["202609111450","1276.28","1275.90","1277.45","1275.90","719.00",{},"0.58"],
           ["202609111455","1276.01","1276.46","1277.00","1275.57","780.00",{},"0.62"],
           ["202609111500","1276.47","1275.16","1277.58","1275.16","1203.00",{},"0.96"]],
   "prec": 1285.13                                 ← 昨收
}}}
```

- 每行 **8 列**：`[时间(YYYYMMDDHHMM), 开, 收, 高, 低, 成交量(手), {}, ?]`
- **第 7 列恒为 `{}`**（空对象）、**第 8 列语义未定**（实测 0.58 / 0.62 / 0.96，量级与换手率/均价均不符）
  → Ashare 的做法是**直接丢弃**（命名 `n1`/`n2` 后不取）。本项目应登记为 ⚠️ 待破解（遵守 A6「缺失≠0」与"不猜"纪律）。
- **附带价值**：`qt` 节点含 **88 字段完整实时快照**，一次请求同时拿到分钟 K 线 + 实时行情。

## 3. 字段层面结论

### 3.1 Ashare 自身**不提供新字段**

Ashare 只输出 6 列固定 DataFrame（`open/close/high/low/volume`），**没有自有字段体系**。
它的价值在**端点发现**与**参数用法**，不在字段。

### 3.2 可直接捡的字段（3 项，全部已实测）

| 字段/枚举 | 来源 | 现状 | 收益 |
| :--- | :--- | :--- | :--- |
| `ma_price5` | 新浪 `ma=5` | 项目传 `ma=no`，丢弃 | 免费多 1 字段 |
| `ma_volume5` | 新浪 `ma=5` | 同上 | 免费多 1 字段 |
| `scale=1200` / `scale=7200` | 新浪 | 字典缺登记 | 补齐周线/月线取数口径 |

### 3.3 真正的富矿：MyTT 指标库（项目 `sc_technical.py` 缺口 ~25 项）

**项目已有（7 类）**：MACD、RSI、BOLL、KDJ、MA(5/10/20/60/120)、成交量分析、CYQ 筹码分布、K 线形态

**MyTT 有而项目没有（25 个指标）**：

| 类别 | 指标 |
| :--- | :--- |
| 波动/风险 | **ATR**（真实波幅）、**KTN**（肯特纳通道）、**XSII**（薛斯通道 II） |
| 趋势/动能 | **DMI**（PDI/MDI/ADX/ADXR）、**TRIX**、**ROC**、**MTM**、**DPO**、**EXPMA**、**BBI** |
| 量价 | **OBV**（能量潮）、**MFI**（资金流量）、**VR**（容量比率）、**EMV**（简易波动） |
| 情绪/摆动 | **CCI**、**BIAS**（乖离率）、**WR**（威廉）、**PSY**（心理线）、**BRAR**（ARBR）、**CR** |
| 通道/突破 | **TAQ**（唐安奇/海龟）、**ASI**（振动升降）、**MASS**（梅斯线）、**DFMA**（平行线差） |

**MyTT 的 0级/1级核心函数（~35 个，项目无同构抽象）**：
`REF` `DIFF` `STD` `SUM` `HHV` `LLV` `HHVBARS` `LLVBARS` `SMA` `WMA` `DMA` `AVEDEV` `SLOPE` `FORCAST`
`LAST` `COUNT` `EVERY` `EXIST` `FILTER` `BARSLAST` `BARSLASTCOUNT` `BARSSINCEN` `CROSS` `LONGCROSS`
`VALUEWHEN` `BETWEEN` `TOPRANGE` `LOWRANGE` `CONST` `IF` `MAX` `MIN` `ABS` `LN` `POW` `SQRT` `SIN` `COS` `TAN`

> 这些函数是**通达信/同花顺公式语言的原语**，且实现全部基于 `numpy`/`pandas` 向量化、**无循环**（SMA/DMA 除外）。
> 项目 `sc_technical.py` 是平铺式实现，缺少这层原语抽象 —— 补齐后可"用公式写指标"而非"用 Python 手搓指标"。

## 4. 理念层面评估（能否采用）

| # | Ashare 理念 | 项目现状 | 判定 |

| 7 | 裸 `except:` 静默降级 | A8 明令禁止静默迁就 | ❌ **明确拒绝** |
| 8 | `fields=[]` 声明但**从未使用**（死参数） | A5 契约无孤儿 | ❌ **明确拒绝**（负面教材） |

## 5. 须明确拒绝的部分（避免"照搬即负债"）

### 5.1 裸 `except:` 静默降级

```python
try:    return get_price_sina(...)
except: return get_price_day_tx(...)      # ← 吞掉一切异常，无日志、无降级记录
```

Ashare 作为"便利库"可以这样写；**本项目不行**：A8 要求任何降级必须显式（记录 `field_sources` 或登记债务）。
若引入此写法，会直接破坏"数据可信度工程"的立身之本。

### 5.2 `fields=[]` 死参数（A5 负面教材）

`get_price(code, end_date='', count=10, frequency='1d', fields=[])` 中的 `fields` 参数在函数体内
**零引用** —— 声明了但从不使用。这正是本项目 A5（契约无孤儿）要消灭的形态。

### 5.3 静默的列裁剪

`get_price_min_tx` 里 `df=df[['time','open','close','high','low','volume']]` 把 `n1`/`n2` 两列
**直接丢弃且无任何记录**。本项目纪律是「字段即使恒空/未破解也要登记」（用户核心要求），
正确做法是登记为 ⚠️ 待破解而非丢弃。

### 5.4 整体照搬单文件架构

Ashare 的"单文件极简"是其**定位优势**，但本项目要维护 86 字段契约 + 22 源适配 + 双闸门，
复杂度是**必要成本**。照搬会与 A1（数据访问收口）直接冲突。

## 6. 改进规划（分优先级，未执行）

> 所有条目均为**规划**，本次未改动任何生产代码。每条给出：动作 / 涉及文件 / 验收 / 风险。

### P0-A｜字典补齐新浪 `scale` 枚举（**零风险，建议先做**）

- **动作**：`docs/field_dict.md` §12.2 L1186 的 `scale=5/15/30/60/240` 补为
  `5/15/30/60/240(日)/1200(周)/7200(月)`，附今日实测证据（周线 08-28/09-04/09-11；月线 07-31/08-31/09-11）。
- **验收**：A7 闸门 HARD 0；字典与 Ashare 全映射一致。
- **风险**：无（纯文档）。

### P0-B｜移植 MyTT 的 0级/1级核心函数库为 `sc_ta_core.py`（**零新依赖**）

- **动作**：新建 `stock_common/sc_ta_core.py`，移植 ~35 个原语（`REF/DIFF/STD/SUM/HHV/LLV/SMA/WMA/DMA/AVEDEV/SLOPE/FORCAST/LAST/COUNT/EVERY/EXIST/FILTER/BARSLAST/CROSS/LONGCROSS/VALUEWHEN/BETWEEN/...`），
  纯 `numpy`/`pandas`，**逐函数标注来源与许可证**（MyTT 为开源，需核对 LICENSE 并保留出处）。
- **验收**：新增单元测试，对每个原语用**手算基准**验证（含边界：空序列、长度不足、含 NaN）；
  与现有 `sc_technical.py` 的 MACD/RSI/BOLL/KDJ 做**交叉一致性断言**（同一输入应得同量级结果）。
- **风险**：中（需保证与现有指标口径不冲突；建议**并行存在**而非替换，待交叉验证通过后再收敛）。

### P1-A｜L3 新浪降级改用纯 JSON host（消除正则剥壳）

- **动作**：`stock_common/sc_datasource/_eastmoney.py:1678` 的 L3 改用
  `money.finance.sina.com.cn/quotes_service/api/json_v2.php/CN_MarketData.getKLineData`（**与字典 L1185 一致**），
  直接 `json.loads(r.text)`，**删除** `re.search(r"\((.*)\)", ...)` 剥壳逻辑。
- **验收**：`get_index_kline_closes` 对 `sh000001`/`sz399106` 返回值与改造前**逐字一致**（今日已实测两 host 同值）；
  保留 jsonp host 作为 **L3b** 备用（不删，只降级）。
- **风险**：低。附带**闭合一处 A7 缺口**（字典写纯 JSON、代码写 jsonp 的不一致）。

### P1-B｜新增腾讯 `mkline` 分钟线取数（补齐唯一真缺口端点）

- **动作**：`stock_common/sc_datasource/_misc.py` 新增 `get_tencent_minute_kline(code, freq='m5', count=N)`，
  解析 `data[code].m5` 8 列 → 前 6 列（时间/开/收/高/低/量）+ `prec` 昨收；
  **第 7/8 列登记为 ⚠️ 待破解**（不丢弃、不猜测）。
- **验收**：新增单元测试（结构断言 + 时间戳格式 `YYYYMMDDHHMM` + 列数 8）；
  与新浪同周期（`scale=5/15/30/60`）做**跨源对撞**（对撞铁律：精度对齐 + 命中率分层），
  命中率 ≥18/20 才升 L1，否则维持 L2/待破解。
- **风险**：中（新源需走 `sc_network` 分域限流，遵守 A1；不得直连）。
- **前置判断**：项目 `get_fuyao_kline` **已支持 `1d/1w/1m/5m/15m/30m/60m` 但零消费** ——
  引入 mkline 前应先确认：是「fuyao 分钟线不可用」还是「从未接入」。
  **建议先做可行性评估，避免新增与既有能力重复的源。**

### P1-C｜新浪 `ma` 参数改为 `ma=5`，捡回 2 字段

## 9. 附：Ashare 值得记录的两个实现细节

1. **`end_date` 的 count 膨胀启发式**（新浪历史回溯）：
   ```python
   unit = 4 if frequency=='1200m' else 29 if frequency=='7200m' else 1
   count = count + (datetime.now() - end_date).days // unit
   ```
   按**自然日**膨胀请求根数以保证覆盖足够**交易日**（周线用 4、月线用 29）。项目 L3 无 `end_date` 支持，
   若将来需要"指定结束日期的历史区间"，可参考此启发式（注意：这是**近似**，不是精确交易日历 —— 项目有 `stock_calendar`，应优先用精确日历）。

2. **末根 K 线用实时价修正**（腾讯分钟线）：
   ```python
   df['close'][-1] = float(st['data'][code]['qt'][code][3])
   ```
   分钟线最后一根尚未收盘时，用**同一响应** `qt` 节点的实时价覆盖其 close。
   项目若引入 mkline，需注意此细节（否则末根 close 会滞后）。
