审计脚本此前把 `cninfo` / `reports` / `em_kline_f61` 硬编码为空集，导致**明明采到了却报「无数据」**。本日按各源真实结构补齐提取器：

| 源 | 真实结构 | 修复 |
| :--- | :--- | :--- |
| cninfo | `stocks[code] = list[dict]`（互动易问答） | 全样本键并集 |

| em_kline_f61 | `stocks[code].klines_all = "日期,开,收,高,低,量,额,振幅,涨跌幅,涨跌额,换手率"` | 按段数生成 `f51..f61` |
| 全局 | `CAP` 硬编码 `20260904` | **参数化**：`audit_field_completeness.py <CAP_DATE> [<OUT_DATE>]` |

**发现的工具精度问题（已定位，未改，登记备查）**：`registered_field_sets` 的继承条件为 `k <= lv`（含同级），
导致**未匹配的同级 `####` 章节会继承前一个同级章节的源归属**。实测证据：`#### 12.8.4 东财 reportapi`
原未映射任何源 → 其 25 个令牌被记到 `#### 12.8.3` 的 datacenter 名下（datacenter reg 由 62 虚增至 87）。
本日因给 reports 补了映射而顺带修正（datacenter 真实 reg=62，raw 23/23 仍 0 缺口）。
**未直接改为 `k < lv`**：§12.8.3.1、§12.10.x 等「编号是子节、层级却是同级」的章节依赖该行为，
贸然改会打破 v3 已修复的 datacenter/levistock 继承。

## 四、thsdk 包名撞车（本日发现并处置）

`stock_common/sc_ths.py:63` 需要 `from thsdk import THS`（同花顺官方 C 库 SDK，非 PyPI 公开分发）。
PyPI 上的 `thsdk`（2.0.2，summary="Python SDK for financial market data"）是**同名不同库，不导出 `THS`**。

- 装上它的后果：报错由 `No module named 'thsdk'` 变为 `cannot import name 'THS' from 'thsdk'`，
  且 pip 会误报依赖已满足 —— 属 A8 禁止的「静默迁就」。
- **处置**：已卸载，并在 `requirements.txt` 该行写下撞车警告与正确安装方式（官方 wheel 本地安装）。
- 缺失属预期：相关功能自动降级，**回归 526 passed 不受影响**。
