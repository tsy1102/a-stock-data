## 1. 先回答用户的根本疑问（因果倒置纠正）

用户假设：*今天统一中文名 → 统一层今天才学到"这些中文意思统一" → 之前没在统一层实现。*

**这个因果链是反的。** 真实顺序是：

1. 统一层（`get_canonical_stock_data`）从第一天起就把多源英文键收拢成一个英文键：
   - push2 `f43` + 腾讯 `tx[3]` + fuyao `last_price` → 统一键 `price`（`_quotes.py:408`、各适配器）
   - push2 `f162` + ulist `f9` + 腾讯 `tx[52]` → `pe_dynamic`（`_quotes.py:531`）
   - `rt_quote.get('high_52w') or zhb_dict.get('high_52w')` → 把两个源并进 `high_52w`（`data_provider.py:1136`）
2. 写这些映射的人**本来就懂语义**（知道 f43=现价），才手写成 `("f43","price")`。字典只是被参考的"规格书"，**运行时从不解析中文名**（全仓无 `field_dict.py` 被 import）。
3. 反而是**字典**今天才追上代码的统一度——今天之前，字典对同一字段写了"当前价/最新价/现价"三套中文名（这正是本次统一修掉的不一致）。

→ **统一层一直就是统一的（英文键层）；是字典中文名今天才洗干净跟代码对齐。** 今天的工作**没有**给代码增加任何新等价知识，因此**不可能**"今天才让统一层学会某等价"。

## 5. 关键判定：今日字典工作是否"揭露"了新缺口？

**否（但暴露了 spec 自身准确性问题，见 §9）。** 理由：

1. 今日字典工作 = 纯中文名归一（当前价→现价、封板资金→封单额、PE 半角→全角等），**未改动任何"源A≡源B"的等价关系**。f43≡f2≡last_price 在今日之前既已在字典写明、也已在代码硬编码。

→ 用户假设"统一层今天才第一次知道这些等价、之前没实现"在事实上不成立；但"spec 表是否如实反映实现"的问题，由 §9 的注入动作解决。

## 9. §12.8.12e 注入「统一层接线」列后暴露的两类 spec↔实现分叉

注入第 5 列时，逐字段把"spec 对照列声明的源"与"canonical 实际消费源"比对，发现 **spec 表自身**有两类准确性问题（不影响统一层运行，但会让读者误判）：

### 9.1 spec 对照列漏列 canonical 实际消费的源（4 处）
canonical 确实消费了这些源，但 spec 对照列的"各源字段对照"却没写：

| 规范中文名 | canonical 实际消费（代码实证） | spec 对照列遗漏 |
|---|---|---|
| 涨停价 | push2 `f51`（`limit_up`） | 只写腾讯[47]/THS 69/push2ex ztp，**漏 push2 f51** |
| 跌停价 | push2 `f52`（`limit_down`） | 只写腾讯[48]/THS 70，**漏 push2 f52** |
| 委差 | 腾讯[86]（`bid_ask_net`） | 只写 push2 f192/腾讯[50]/THS 395720，**漏腾讯[86]** |
| 均价 | 腾讯[85]（`avg_price`） | 只写腾讯[51]/TDX快照 average_price，**漏腾讯[85]** |

→ 这 4 处若照 spec 字面理解，会以为"涨停价/跌停价/委差/均价"没进统一层，实则已接（只是 spec 漏记源键）。第 5 列已用 `⚠️spec对照漏列` 标注。

### 9.2 spec 列了但 canonical 无对应字段（真实缺口，9 处）
这些语义在 spec 注册表有规范名 + 多源对照，但 **CanonicalStockData 契约（sc_schema.py:450-559 共 86 字段）根本没有该字段**，统一层无法透传，只能走外部路径：

| 规范中文名 | canonical 现状 | 外部路径 |
|---|---|---|
| 封单额 | 无（仅 `bid1_vol` 买一量，sht 报告据之计算） | ZHB/fuyao/push2ex/TDX快照/开盘啦 |
| 委比% | 无（仅 `bid_ask_net` 委差） | push2/腾讯/THS/TDX快照 |
| 内盘 | 无 | 腾讯/TDX快照 |
| 外盘 | 无 | 腾讯/TDX快照 |
| 涨速% | 无 | THS/push2ex/开盘啦 |
| 连板天数 | 无（仅 `streak_days` 连涨连跌） | push2ex/fuyao/同花顺 |
| 总资产 | **✅ 已接入 canonical (V17.1, `total_assets`)** | TDX财务 0x0010 `zongzichan`/10→元；外部: THS/fuyao |
| 净资产 | **✅ 已接入 canonical (V17.1, `net_assets`)** | TDX财务 0x0010 `jingzichan`/10→元；外部: THS/fuyao |
| 昨日/前日成交额·封单额 | 无（ZHB 私有衍生，未升格 canonical） | ZHB |

→ 这 9 处是 spec 领先于实现的真实缺口。是否要补齐进 canonical 是独立决策（补则 5 大脚本可直接 `cdata.xxx` 消费，但会膨胀 86 字段契约 + 需补适配器映射）。本审计**仅透明化，不擅自扩展契约**。
