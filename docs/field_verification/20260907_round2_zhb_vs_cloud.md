# 第二轮 TDX 云碰撞实测：ZHB 实时列 × 云主力分解（2026-09-07）

> **定位声明（与 §12.8.12f 一致）**：本报告的云数据来自 `mcp__tdx-connector`（通达信云/TQLEX），
> 仅作 **AI 字段对撞 / 短线参考** 使用，**不进入项目运行时取数路径**。项目真正 TDX 源为 `easy_tdx`（本地 TCP，见 `requirements.txt`）。
> 本报告服务「字段口径确认 + 短线主力行为源发现」，无任何代码改动。

## 0. 目的与靶子
用户判断：云连接器的「可视化字段名 + 数值」可作 oracle，倒推未破解字段的数字归属。
第二轮原假设：**用云 `tdx_quotes` ProInfo（主力净流入/超大单/大单分解）作 oracle，对撞 ZHB 实时列，
尝试给 ZHB 未知列（Col[9] 负数、特征编码列等）赋名**——用户认为该类主力分解数据对短线判断极重要。

## 1. ZHB 实时数据结构（靶子侧）
经 `core/zhb_client.py`（tdxstat2，21 列）与 `raw_zhb.json` 实测枚举，ZHB 全列如下（关键语义已破译）：

| 列 | 字段 | 语义 | 单位 |
|---|---|---|---|
| Col[9] | `main_net_buy_hands` | **早盘竞价量**（非主力净买入量，misnomer） | 手 |
| Col[11] | `auction_amount` | 开盘金额/竞价额（9:25 集合竞价） | 万元 |
| Col[14] | `main_net_buy_amount` | **开盘金额/竞价额**（非主力净流入，misnomer） | 万元 |
| Col[16] | `cum_buy` | 累计买入额 | 万元 |
| Col[17] | `cum_sell` | 累计卖出额 | 万元 |
| Col[18] | `net_inflow` | 净流入额（ ambiguous，需二次确认） | 万元 |
| …其余 | 涨停/连板/封单/特征编码等 | 打板维度 | — |

**决定性结论**：ZHB 的 21 列中 **不含任何「主力净流入 / 超大单 / 大单 / 主买」分解字段**。
其 `main_net_buy_*` 在 `zhb_client.py:915-928` 文档已自证 = 竞价额/竞价量（misnomer）。

→ **原假设结构层面即被证伪：ZHB 无主力分解列，无靶可撞。** 这不是「撞不上」，是「靶子不存在」。

## 2. 云 oracle：每日资金流向表（zjlx）— 真正的短线主力分解源
因 ZHB 无靶，转向云连接器本身提供的**权威主力分解源**。实测 `tdx_api_data(TdxSharePCCW.tdxf10_gg_jyds, fixedTag=zjlx)`：

- **盘前可得**（不依赖盘中窗口，与 ProInfo 盘中才出不同）——适合盘前/盘后短线复盘。
- 返回 9 列命名表（Headers 显式给出），含**逐日**历史（茅台 50 行，2026-08-10→2026-09-04）：

| Header | 含义 | 短线用途 |
|---|---|---|
| 主力净额金额(元) | 主力净流入 | 主力方向 |
| 主力净额占比(%) | 主力占比 | 主力强度 |
| 超大单净买入金额(元) | 超大单(≥50万?) 净买 | 机构意图 |
| 大单净买入金额(元) | 大单净买 | 大户意图 |
| 主买净额金额(元) | 主动性买入净额 | 真实买盘压力 |

**茅台锚点（2026-09-04 收盘）**：
```
主力净额 = 444,347,136 元   占比  7.38%
超大单净买入 = 175,498,496 元   占比 2.91%
大单净买入   = 268,848,640 元   占比 4.46%
主买净额     = 1,245,833,984 元   占比 20.69%
```

### 2.1 云内交叉印证（极强）
09-04 盘中 `tdx_quotes` ProInfo 的 `主力资金净流入 = 444,347,136 元`
== zjlx 表 2026-09-04 `主力净额金额 = 444,347,136 元`。

→ 两个独立云通道（实时 ProInfo vs 每日 zjlx 表）**同一日期数值严格相等**，
证明 zjlx 的「主力净额」与 ProInfo 的「主力资金净流入」是**同一口径**，互为校验。

### 2.2 附赠发现：精确复权因子历史
zjlx 响应附带 `adjustment_factor` 表：`精确复权因子` + `精确复权常数`，**回测至 2002-07-25**。
这正是此前标注的「精确复权因子历史」补源点——权威前复权序列，回测复权用。

## 3. 与项目现状的差距（短线价值落点）
| 维度 | 项目当前 | 云 zjlx |
|---|---|---|
| 主力净流入 | 仅东财 `f137` 单值 | 主力净额 + 超大单 + 大单 + 主买 四元分解 |
| 可用性 | 盘后（push2 盘中熔断时缺失） | 盘前/盘后均可得（历史表） |
| 短线主力行为 | 无分解，无法读「机构 vs 大户」 | 超大单/大单分离，经典短线读 |

→ 云 zjlx 的**四元主力分解**正是用户短线判断缺失的那块。但其为云连接器（非项目源），
**要落地到项目运行时**，需找**本地可装依赖**提供同等分解：
- `easy_tdx` 行情解码**不含**主力分解（仅 s_vol/b_vol/rise_speed）；
- 东财 L2 资金流接口（超大单/大单分解）是否为项目可装依赖 → **待下次调查**（不在本轮范围）。

## 4. 结论
1. **ZHB 无主力分解字段** → 原「对撞 ZHB 列」假设证伪，无靶可撞（证据充分，非失败）。
2. **云 zjlx 每日资金流向表**是可靠的盘前/盘后**短线主力四元分解 oracle**，且云内双通道（ProInfo vs zjlx）数值严格一致。
3. **精确复权因子历史**随 zjlx 响应附带，可作回测复权补源。
4. 落地路径：云源仅作对撞/参考；若要项目运行时获得四元分解，需调查东财 L2 资金流本地源（下次）。
