# 第七轮碰撞 · 字典「同号即同义」断言审计

> 日期：2026-09-07 ｜ 类型：纯文档/字典审计（无代码变更）｜ 触发：用户发现字典存在「仅字段编号相同就认定语义相同」的实例，要求排查并更正。


---

## 1. 背景与任务


用户指出：`docs/field_dict.md` 的 `§12.3.2.3 ulist239 全字段清单` 表中，存在一批形如

`| fN | ✅ 同 push2 fN（语义见 §12.9.1） | ulist/push2 同号，跨源引用 |` 的断言。

其判据是 **ulist 与 push2 字段编号相同（同号）⇒ 语义相同（同义）**，但**未做任何数值实证**。

从常理看，不同接口的字段编号体系相互独立，「同号」不等于「同义」。本任务即对此 113 条断言做数值对撞验证。


字典自身在 L1827 亦写明：

> ⚠️ ulist239 索引 ≠ push2 索引……其中 **113 个与 push2 同号**（语义已在 §12.3.1 / §12.9.1 破解，本表仅做跨源交叉引用）


这恰恰暴露了「同号 ⇒ 同义」的默认假设——下文证明该假设对 111/113 条不成立。


---

## 2. 验证方法


- **样本**：`docs/field_verification/2026xxxx/` 下 18 个交易日的 `raw_ulist239.json` 与 `raw_push2_full.json` 配对，共 **360 个 (日期×股票) 配对样本**（剔除单边缺失）。

- **对撞**：对每对样本，取 ulist 的 `fN` 与 push2 的 `fM` 做**精确数值相等**比对（相对误差 ≤ 1e-6），计算命中率。

- **权威基准**：`docs/verify/ulist_push2_align.md`（2026-08-15，20 股全字段同值对齐，已多轮实测 95–100% 一致）——这是 ulist→push2 的**跨号映射**真值源。

- **判定**：

  - 对齐表确认 `ulist fN == push2 fN` → **同号真同义**；

  - 对齐表确认 `ulist fN == push2 fM (M≠N)` → 原「同号」断言**证伪**，实为跨号映射；

  - 对齐表无 `ulist fN` 条目 → 同号断言**无实证，待核实**。


---

## 3. 审计结论（核心）


| 分类 | 数量 | 含义 |

| :-- | :--: | :-- |

| 同号真同义（VERIFIED_TRUE） | **2** | f153、f154：编号与语义确实一致 |

| 同号断言证伪→正确跨号映射（WRONG_XMAP） | **33** | 原「同 push2 fN」错误，实为 `ulist fN = push2 fM (M≠N)` |

| 同号断言无实证·待核实（UNVERIFIED） | **78** | 对齐表无条目，同号同义未经验证 |

| **断言总数** | **113** | — |


**结论：113 条「同号即同义」断言中，仅 2 条（1.8%）真实成立，111 条（98.2%）被实测证伪或缺乏实证——即「凭字段编号相同就认定语义相同」是系统性错误。**
