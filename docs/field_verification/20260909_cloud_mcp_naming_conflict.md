**日期**：2026-09-09｜**执行者**：字段字典定案 AI 助手
**触发**：今日突破性采用云 MCP（腾讯 qt / 通达信 get_more_info / 东方财富 push2 + 妙想 mx-ds）获取大量官方/自然语言字段名，需核查：① 多源官方中文名是否互相冲突；② 是否与字典既有「规范中文名」冲突；③ 若有，设计统一规则。
**数据来源标注**：通达信官方 `get_more_info` 与 `func_*.cfg` 1924 字段表（`docs/verify/tdx_func_fields.md`）、腾讯 `qt.gtimg.cn`（`docs/field_verification/vendor_field_tables.md` §2）、东方财富 push2 社区表 + 妙想 mx-ds（`docs/field_verification/vendor_field_tables.md` §3、本轮 mx-ds 命名对撞报告）、东财客户端 A–G 表头（`docs/verify/em_tableheader_ids.md`）、TDX 云 JSON 命名字段（`docs/field_dict.md` §12.8.12e 云映射块）。

## 0. 结论摘要

1. **多源官方中文名并非完全一致**——在行情/估值类字段（总市值、流通市值、市净率、量比、内外盘、涨停/跌停价、换手率%、股息率%）三源高度一致；但在 **主力资金流、净资产/股东权益、PE 口径、% 后缀** 四处存在实质性分歧。
2. **与字典既存 canonical 的冲突有限且可定位**：字典 2026-09-06 重大改定建立的「规范中文名」表已基本统一大多数语义；残留缺口为：(a) 主力净流入 的同义异名未全量登记进「主力净买入额」别名列；(b) 「净资产」与「股东权益合计」的范围歧义（母公司 vs 合并）未在表中显式拆解；(c) 通达信 `pe_ttm` 误称「动」的已知反转已由铁律二覆盖。
3. **设计统一规则「云 MCP 命名 Oracle 仲裁规则 R0–R6」**（见 §4），核心思想：**字典规范中文名永远是 single source of truth；任何云 MCP 官方名只是命名 oracle，分歧时按「财报科目翻转后的优先级 + 口径 qualifier 强制 + 同义异名全量归档 + 厂商名不可盲信」仲裁**。已据规则落地字典修订（见 §5）。

## 2. 冲突清单（按严重度）

### 🔴 A. 主力资金流「五名同义」——对撞脚本假阴性高危
同一概念在 5+ 处中文名不同：
- 东财：主力净流入额 / 主力净额 / 主力净买额（G1=主力净流入）
- 通达信 get_more_info：`Zjl_HB`=主力净流入、`Zjl`=主买净额
- TDX 云：`ProInfo.主力资金净流入（元）`
- 同花顺：主力净买额
- 字典 canonical：**主力净买入额**

**风险**：若对撞/采集脚本按中文名精确匹配，仅识别其一会漏掉其余四源，产生假阴性。
**现有处置**：字典已用「主力净买入额」聚合，但别名列未登记 通达信 `Zjl_HB/Zjl` 与 TDX云 `主力资金净流入`，本轮已补（见 §5 EDIT-A）。

### 🔴 B. 净资产 vs 股东权益合计 —— 范围（母公司/合并）歧义
- 通达信 `JZC`/`jingzichan`=净资产 → **实测值 2512.5 亿 = ulist f58 = 归属母公司股东权益合计**（母公司口径）。
- 东财/mx-ds `股东权益合计` → **实测值 2620.9 亿 = ulist f135 = 全部股东权益（含少数股东）**（合并口径）。
- 二者差≈108 亿（少数股东权益），数值不可互代。
- **字典现状**：line 3096 将「净资产 ≡ 股东权益」并列；f135 行用「股东权益合计/净资产」双名——裸「净资产」会同时命中 f58 与 f135，造成碰撞假阳性。
**本轮处置**：拆为两个 canonical（见 §5 EDIT-B/C）。

### 🔴 C. PE 口径命名反转（通达信 pe_ttm 称「动」）
- 通达信官方把 `pe_ttm` 命名为「市盈率（动）」，但本项目定案口径为：动=最新报告期年化(f162)、TTM=滚动(f164)。
- 已被字典 **铁律二** 覆盖（项目口径优先，通达信名仅作别名）。无需新增规则，但 R3 须把「通达信 市盈率（动）≡ f164 别名」登记以防误读。

### ⚠️ D. % 后缀 / 单位 qualifier 系统性差异
- 委比：T信 `Wtb`=委比（无%），EM/TX=委比%（有%）。
- 毛利率：T信 `XSM`=毛利率%，EM/mx-ds=销售毛利率（TTM）。
- 处置：canonical 一律带 `%`（委比% / 换手率% / 毛利率% / 股息率%）；厂商名无 `%` 者降为别名（铁律五 + R5）。

### 🔴 E. 通达信 1924 表内部命名自相矛盾
- `MGSY`(func_gx_fxspj101)=每股收益、`eps`=每股收益，但 `mgsy`(func_reits101)=**净利润**。
- 教训：厂商官方名也不可盲信，名称相同未必语义相同（与「同号异义」同源风险）。R6 强制「名称仅作线索，须数值二级复核」。

### ✅ F. 一致字段（三源无冲突，作确认）
总市值 / 流通市值 / 市净率 / 量比 / 内外盘 / 涨停跌停价 / 换手率% / 股息率% / 总资产 / 净利润 / 营业收入 / 每股收益（除 E 例外）在三源中中文名一致，云 MCP  influx 起到**确认**而非**颠覆**作用。

## 4. 统一规则设计：云 MCP 命名 Oracle 仲裁规则（补丁 · 2026-09-09）

> 下列规则为 2026-09-06 重大改定 + 铁律一~五 的**补充补丁**，不替代原规则。

**R0 — 单一事实源原则**：字典 §12.8.12e「规范中文名」表永远是 single source of truth。任何云 MCP（腾讯 qt / 通达信 get_more_info / 东财 push2 / 东财 mx-ds / TDX 云）返回的官方/自然语言中文名，一律视为「命名 oracle」，只用于辅助赋予或校正 canonical，绝不自动成为 canonical。

**R1 — 三方一致即确认**：当 ≥2 个独立云的官方中文名对某语义指向同一中文词且无口径冲突 → 直接采纳为 canonical（如总市值/流通市值/市净率/量比/内外盘/涨停跌停价/换手率%/股息率% 已三源确认）。

**R2 — 名称分歧仲裁（扩展 2026-09-06 优先级）**：
- **R2a — 财报科目优先级翻转**：通达信 1924 表（func_*.cfg）为行情/公式函数命名表，**实证不含资产负债表/利润表/现金流量表明细行**（grep `tdx_func_fields.md` 无 未分配利润/流动负债合计/股东权益合计/流动资产合计/销售毛利率）。故财报科目字段命名优先级应为 `同花顺 tableheader → 东财 mx-ds 自然语言名 → 东财 A–G`；**通达信仅在确有具名函数（JZC净资产/ZZC总资产/PB市净率/XSM毛利率%/GXL股息率%）时介入**。即财报科目不再因「通达信第一」而优先，通达信沉默处直接落东财/mx-ds。
- **R2b — mx-ds 自然语言名升格**：东方财富妙想（mx-ds）返回的是东财官方自然语言命名（未分配利润/销售毛利率(TTM)/流动负债合计/归属于母公司股东权益合计/股东权益合计/股息率(TTM)），权威性与东财客户端 A–G 表头同级，视作「东财官方中文名」来源，优先级等同既有 ③，登记时「依据」列注明 `mx-ds`。

**R3 — 同义异名强制全量归档（直击用户原痛点）**：凡同一 canonical 在不同云有不同中文叫法，必须全部登记进「各源字段对照」列作为别名，且**碰撞/采集脚本须支持「按 canonical 名 + 任一别名」双重匹配**，避免裸名精确匹配造成的假阴性。已厘清须补登的异名族：
- 主力净买入额 ≡ {东财 G1 主力净流入, 东财 主力净流入额/主力净额/主力净买额, 通达信 get_more_info 主力净流入(Zjl_HB)/主买净额(Zjl), TDX云 主力资金净流入（元）, 同花顺 主力净买额}（注：ZHB `main_net_buy` 实为竞价额，misnomer，不并入）。
- 净资产（母公司）≠ 股东权益合计（合并）：二者拆为独立 canonical（R4）。
- 市盈率（TTM）≡ {东财 f164, 腾讯[39], 同花顺, 通达信 pe_ttm(但 T信误称「动」)}；通达信「市盈率（动）」仅作 f164 别名，语义锁定 f162。
- 销售毛利率% ≡ {东财 F30 销售毛利率, 通达信 XSM 毛利率%}。

**R4 — 合并/母公司口径强制 qualifier（消除 净资产/股东权益 歧义）**：凡「股东权益/净资产」类字段，canonical 名必须显式带 **（合并）** 或 **（母公司）** 后缀，禁止裸用「净资产/股东权益」：
- f58 = **净资产（母公司）** ≡ 归属母公司股东权益合计（T信 `jing_zichan` 实测 2512.5 亿）。
- f135 = **股东权益合计（合并）** ≡ 全部股东权益（mx-ds `股东权益合计` 实测 2620.9 亿）。
- 理由：二者差=少数股东权益，数值不可互代；裸「净资产」会同时命中 f58 与 f135 致碰撞假阳性。

**R5 — 比率/单位 qualifier 一致性（扩展 铁律五 ⑤）**：
- 百分率字段 canonical 一律带 `%`（换手率% / 委比% / 振幅% / 毛利率% / 股息率% / 净资产收益率%）；厂商名无 `%` 者（T信 `Wtb` 委比、`HSL` 换手率%、EM `B14` 委比%）全部降为别名。
- PE/ROE/EPS 必带口径（动/静/TTM，加权/扣非/报告期）。
- 市值/股本/财报额必带单位（亿/元/万股），见铁律三。

**R6 — 厂商内部命名不可盲信（防 通达信 mgsy 型 bug）**：
- 通达信 1924 表自身存在 `mgsy`(func_reits101)=净利润 与 `MGSY`(func_gx_fxspj101)=每股收益 的自相矛盾。
- 规则：对任何仅靠「名称相同」定案的字段，必须再用一组数值对撞（双样本/跨源）复核；名称仅作线索，不单独定 L1。与既有「L1 两终止器（同源精确对撞 / 厂商官方字段表）」一致——厂商表也须「数值复核」二级校验。
