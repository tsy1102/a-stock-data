# mak 脚本专项审查（same-methodology 复审，2026-09-10）

## 0. 结构总览

mak 非"编号策略引擎"（如 val 的 23 策略），而是**双引擎 + 八章节扫描报告**：

- **引擎一 · 全市场异动扫描**（`check_stock` + 并行 ThreadPoolExecutor max_workers=3）
  - 偏离触发规则：**3 套窗口** —— 3日（卡异动/已触发）、10日（严重/严重预警）、20日（严重）。
  - 输出分级：`卡异动` / `已触发` / `严重` / `严重预警`。
- **引擎二 · 行业轮动**（`get_all_sectors` + `compute_rotation_scores` + `generate_sector_report`）
  - 输出章节：**A 情绪看板 / B 涨停池 / B+ 涨停天梯 / C 板块-异动集中度 / 近3日异动回溯 / D 行业轮动强度 / E TOP10板块深度 / F 资金流验证**。

**数据依赖清单**（取数端点）：

| 来源 | 函数/接口 | 用途 | 时效 | 风险 |
|------|-----------|------|------|------|

## 1. 冗余分析（有无冗余）

### 1.1 章节级冗余（结论：低—中，以"不同视角"为主，可辩护）

| 现象 | 跨章节 | 判定 |
|------|--------|------|
| 涨停信息 | A（涨跌幅口径计数）/ B（limit_pool 多源）/ B+（fuyao 连板天梯）/ E（板块龙头涨停梯队）/ check_stock（涨停=极端偏离） | **多视角覆盖**，非纯重复；但用户视角下"涨停"在 4+ 处出现，存在**呈现冗余** |
| 资金流 | A（全市场主力净流入 ulist f62）/ F（板块主力净流入）/ 北向（外资口径） | **不同粒度**（市场/板块/外资），可辩护 |
| 偏离触发 | 单只票可同时触发 3日"已触发" + 10日"严重" + 20日"严重" → 同票多行 | **分层严重度设计**，但同一次异动在 3 行重复呈现，存在去重空间 |
| 同花顺交叉验证（原 G 段移入） | 仅 1650-1665 一处 | **死重**：因 401 反爬恒空，实际永不渲染（见 §2.2） |

**判定**：与 val 不同（val 因子集中度 44% 动量重叠），mak 八章节主题正交（情绪/涨停/天梯/集聚/轮动/深度/资金），**结构性冗余低**。主要冗余是"涨停/资金多源呈现"与"同花顺死重段"。

### 1.2 取数级冗余（结论：低，且以"交叉校验"为目的，正向）

- 涨停数：**TDX 异动 + limit_pool 多源（财联社/KPL/复盘啦 三源互校）+ 腾讯实时涨跌幅** 三路交叉校验 —— 这是**健壮性冗余**（val 审查推崇的做法），非浪费。
- 主力净额：**ulist f62（主）+ ZHB 竞价额（兜底，明确标注非主力）** —— 分层兜底，且已显式区分口径，无静默混淆。

## 2. 字典更新导致的取数失真 / 难度加大（核心问题）

### 2.1 主力净额失真 —— ⚠️ mak **已提前修复**，当前无失真（与 val 关键差异）

val 审查发现 `main_net_buy_amount` 实为**竞价额**而非主力净流入（V17.0 实锤）。mak 对此的处理**领先于 val**：

- L779-784：`# 不再用 ZHB main_net_buy_amount（实为竞价额恒正）` —— 缺失时保持 0，不误计入板块资金流。
- L1320-1346：全市场主力净流入改用 **ulist f62 带符号净额**，ZHB 竞价额仅作兜底且标注 `⚠️非主力`。
- L1905-1906：F 段虚涨判定明确"需有 ulist f62 批量数据才能判断"，杜绝用恒正竞价额伪造净流出。

**结论**：mak 对"竞价额=主力净"这一字典语义澄清**已吸收**，当前无失真。这是 mak 相对 val 的**正面差异**。

### 2.2 同花顺强势股（401 反爬）—— ⚠️ 字典整合抬高取数难度，段恒空（与 val 同根因）

- `get_ths_hot_raw` 底层 = `http://zx.10jqka.com.cn/event/api/getharden/...`（HTTP 网页接口）。
- 字典多轮修订后 **thsdk TCP 已移除（V17.0.29），仅剩 HTTP 网页**（401 反爬）→ **系统性空出**。
- mak 影响：`_ths_pool = await get_ths_hot_pool(today_str)`（L1650）—— 与 val 的 01/03/07/08/15 依赖 `hot_pool` **完全相同根因**。
- mak 处理较 val **更优雅**：`if _ths_pool:` 守卫 → 空则整段跳过，**不产出误导空表**（val 当时是策略静默空出但仍占坑）。代价：损失"同花顺独家交叉验证"这一增量视角。

**结论**：字典驱动的来源整合（thsdk→HTTP）**确实加大了 mak 的取数难度**，导致该交叉验证段恒空。建议标注"数据源受限"而非静默空，保留可追溯性。

### 2.3 龙虎榜 / 北向（盘后 datacenter）—— 盘前恒空，已优雅降级

- `get_recent_dragon_tiger(3)`（L1683）→ C 段补全；盘前/盘中恒空，`_extra_dt_codes = set()` 优雅跳过。
- `get_hsgt_macro_flow`（L1202）→ A 段；**已有 `data_quality` 守卫**（invalid/partial_hgt_only/degraded 三态声明），不展示错误数字。
- 与 val 16/17/22（北向/龙虎榜/业绩预告）盘后恒空**同根因**，但 mak 已建守卫，失真风险低。

### 2.4 fuyao 依赖 —— 缺 key 静默空（与 val 同模式）

- fuyao 用于 B+ 连板天梯（L1628）、F 跌停明细（L1518）、A 竞价风向标（L1251），均 `try/except` 包裹。
- 缺 key（未启用 `is_fuyao_enabled()`）时整段静默空 —— 与 val 25（PS低估值 fuyao key 缺失静默空）**同模式**。建议显式标注"未启用"而非静默。

### 2.5 其他字典变更字段 —— mak **绝缘**（不受影响）

val 数据结构审计发现 `avg_price`/`bid_ask_net`/`entrust_ratio`/`bid2`/`ask2`/`资金流四档` 等字段语义变更。经 grep 确认 **mak 不消费上述任一字段**（仅消费 `main_net_inflow_wan` / `main_net_buy_amount` / `change_pct` / `ret_3d/10d/20d` / `turnover` / `amount_yi` / `up/down_count`）。

**结论**：mak 核心异动/轮动逻辑建立在**鲁棒字段**（涨跌幅、偏离、换手、成交额、涨跌家数）之上，对字典字段语义漂移**绝缘度高**——这是 mak 失真风险远低于 val 的根本原因。

## 4. 审查结论与建议

### 4.1 冗余
- **结构性冗余低**：八章节主题正交，多源取数以交叉校验为目的（正向）。
- **呈现冗余**：涨停信息跨 4+ 章节、单票 3日/10日/20日偏离多行重复 —— 建议评估"偏离触发去重"（同票合并为复合严重度行）与"涨停多视角收敛"。
- **死重段**：同花顺交叉验证段因 401 反爬恒空 —— 建议标注"数据源受限"或降级为可选。

### 4.2 字典更新影响
- **未造成 mak 取数失真**：唯一敏感字段 `main_net_buy_amount` 已修复；其他变更字段 mak 不消费。
- **确实加大了取数难度**（同花顺 HTTP 401 反爬），但 mak 优雅降级，无误导输出。
- 与 val 共享三类根因（同花顺反爬 / 盘后 datacenter / fuyao 缺 key），mak 的守卫更完善。

### 4.3 建议（非强制，待用户确认）
1. 同花顺交叉验证段：空时显式输出"数据源受限（同花顺反爬）"而非静默跳过，提升可追溯性。
2. fuyao 未启用时：相关段标注"竞价/连板数据未启用"而非静默空。
3. 偏离触发：评估 3日/10日/20日同票多行合并为分层严重度，减少重复呈现。
4. 维持现状：ulist f62 主力净额主链路 + ZHB 竞价额兜底口径标注（已正确）。
