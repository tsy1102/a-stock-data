`gu_dong_ren_shu_raw_float` 样本值为 600519=`278,364`、601288=`567,189`、920508=`4,148`。其中茅台和殷图网联三季报披露的期末普通股股东数分别为 278,364 和 4,148，与 raw 完全相同；农行 raw 值与其报告披露的期末股东数也相符。该字段目前支持“报告期末普通股股东数量”这一候选解释，不代表每日实时股东数。

`zong_xian_jin_liu_raw_float` 的三个样本不是直接等于财报“现金及现金等价物净增加额”这一最终行。它们更接近经营、投资和筹资三类活动净现金流之和，亦即未加入汇率影响的数值：

这三组对照支持“现金流活动净额合计（未计汇率影响）”这一研究假设，并提示不能直接把它映射成最终现金及现金等价物变动额。由于上游文档没有给出该 raw 字段的明确公式，本项仍未正式定案。

## 保留的歧义

- `zhu_ying_li_run_raw_float` 数值在茅台和殷图网联对应“营业成本”，在农行对应“营业支出”。这说明它与经营成本/支出项目接近，但财报列项按行业不同；现有证据不足以给它一个不带限定的统一官方标签，也不足以确认其完整会计范围。不要把它和 `ying_ye_li_run_raw_float`（营业利润候选）混为一谈。
- 当前对照只使用三只股票的同一季报期；字段数值虽跨消费、银行和科技公司吻合，但这不证明所有 ELTDX 市场、所有股票或每个报告期间都没有结构差异。
- 固定版 ELTDX v3.3.2 的[7709 财务基础信息接口文档](https://github.com/electkismet/eltdx/blob/v3.3.2/docs/methods/7709-%E8%B4%A2%E5%8A%A1%E5%9F%BA%E7%A1%80%E4%BF%A1%E6%81%AF.md#L93-L132)已逐项说明这些字段：两项法人股是万股口径；主营收入、营业利润、总现金流是千元口径；股东人数为原始人数值。此前“这些字段未逐项给出单位”的说法不准确，现以该固定版本接口文档更正。该文档定义的是 ELTDX 自身输出模型；由于 ELTDX 是第三方协议库，仍须与发行人公开报告及实际样本交叉核验，不能单凭仓库文档替代项目的定案要求。
- 本轮没有解决注册表中其余 ELTDX 财务字段，特别是资产负债表项目；没有把今天的采集目录日期误用作财务数据期间。

## 当前结论与下一步

当前样本支持的候选：`gu_dong_ren_shu_raw_float`、`zhu_ying_shou_ru_raw_float`、`ying_ye_li_run_raw_float` 及表中列出的其他财务路径。`zong_xian_jin_liu_raw_float` 仍缺上游公式确认；`fa_qi_ren_fa_ren_gu_raw_float` 与 `fa_ren_gu_raw_float` 有明显的名称/数值矛盾，须先核实协议字段身份；`zhu_ying_li_run_raw_float` 的跨行业会计列名称及统一范围也保留歧义。

这些是本轮研究结论，不是字段注册状态变化。后续正式定案时，应以完整来源身份、v3.3.2 的 0x0010 raw 契约、不同报告期和更多股票复核，并分别处理语义和单位；本轮没有改写字段注册表、主字典、碰撞候选审阅状态或运行时代码。

## 拼音候选与历史报告期复核补充

本节明确保留这六个字段的拼音/英文候选：`fa_qi_ren_fa_ren_gu_raw_float`＝发起人法人股 / promoter legal-person shares；`fa_ren_gu_raw_float`＝法人股 / legal-person shares；`gu_dong_ren_shu_raw_float`＝股东人数 / number of shareholders；`zhu_ying_shou_ru_raw_float`＝主营收入 / main-business revenue；`ying_ye_li_run_raw_float`＝营业利润 / operating profit；`zong_xian_jin_liu_raw_float`＝总现金流 / total cash flow。候选先由字段名提出，随后独立核对协议、原始值、单位和报告期间；不能因数值命中把候选改名。

### 拼音候选与生产者文档基线

核对 ELTDX 固定标签 `v3.3.2`（提交 `646c7a5d53cae3c243a1d6b705188fe9880a3e03`）后，接口专页直接给出这六个字段的中文释义：`发起人法人股`、`法人股`、`股东人数`、`主营收入 / 营业收入`、`营业利润`、`总现金流`；并将前两项标为万股、后三个金额项标为千元。它确认了拼音猜测的方向，也补齐了 ELTDX 输出层的单位说明。

同时，v3.3.2 的 [FinanceRecord 模型](https://github.com/electkismet/eltdx/blob/v3.3.2/src/eltdx/models/corporate.py#L207-L249)与[0x0010 Rust 解码器](https://github.com/electkismet/eltdx/blob/v3.3.2/crates/eltdx-protocol/src/commands/corporate.rs#L449-L508)显示，这些名字是解码器按固定顺序赋给协议数值槽的模型字段；服务端响应本身没有携带这些中文标签。因此，接口文档是该第三方库输出字段的直接契约证据，不等于东财对 0x0010 槽位语义的官方定义。项目应保留拼音和生产者文档中的释义作为强候选，同时将它们与公开财报的值、期间、单位及矛盾分别核查，不能把任何一层单独当作无条件定案。

### 通达信官方财务指标与双客户端历史核对

通达信官方量化文档的 [`get_financial_data`](https://help.tdx.com.cn/quant/docs/markdown/TdxQuant.md/mindoc-1h10m001ic888.html)字段表把 `FN242` 定义为股东人数、`FN74` 定义为营业收入、`FN86` 定义为营业利润；现金流量表另列经营/投资/筹资活动净额（`FN107` / `FN119` / `FN128`）及现金及现金等价物净增加额（`FN131`）。公式系统文档也将 `FINANCE(20)` 和 `FINANCE(23)` 分别定义为营业收入和营业利润。它们为语义及现金流边界提供了提供方侧参照，但这是另一套财务接口，没有直接声明这些指标与 0x0010 的逐槽对应关系，故只作为交叉参照。

逐一比较保留期内 17 个 `raw_tdx.json` / `raw_eltdx.json` 快照（2026-10-15 至 2026-11-10，共 340 只股票记录），先要求股票代码与各自 `updated_date` 相同，再比较字段值。339 条同日期记录中，六条路径全部符合下列转换，逐项均为 339/339，无值差异；去重后覆盖 43 个 `(股票, updated_date)` 组合，重复快照中的值保持稳定：

| `raw_tdx.finance_info` | `raw_eltdx.finance_batch[]` | 关系 |
|---|---|---|
| `fajirenfarengu` | `fa_qi_ren_fa_ren_gu_raw_float` | 数值相同 |
| `farengu` | `fa_ren_gu_raw_float` | 数值相同 |
| `gudongrenshu` | `gu_dong_ren_shu_raw_float` | 数值相同 |
| `zhuyingshouru` | `zhu_ying_shou_ru_raw_float` | 左值 = 右值 × 10,000 |
| `yingyelirun` | `ying_ye_li_run_raw_float` | 左值 = 右值 × 10,000 |
| `zongxianjinliu` | `zong_xian_jin_liu_raw_float` | 左值 = 右值 × 10,000 |

金额项的比例与旧 TDX 路径“角”和 ELTDX 文档“千元”的单位关系一致。双客户端属于同一 TDX 来源族；此核对证明解析路径和尺度关系一致，不增加独立来源数，也不证明槽位语义本身正确。唯一未配对记录是 600675 在 2026-10-30：旧 TDX 的 `updated_date=2026-10-30`，ELTDX 为 `2026-10-29`，两项法人股值也不同；从 2026-11-02 起两者都更新为 2026-10-30 并重新一致。该行按来源日期差异排除，不算值差异或独立证据。

这项核对强化了六个拼音/英文候选确实指向同一组协议槽位，但没有消除槽位语义冲突：前两槽在两种客户端里都出现与股本单位不相称、却与上年同期财务值吻合的数值；因此仍须区分“字段标签定义”与“当前服务端槽位实际承载的数据”，不能把单个客户端改名或把原拼音候选抹掉。
