## 官方资料与身份边界

[通达信 TdxQuant 官方接口字段文档](https://help.tdx.com.cn/quant/docs/markdown/mindoc-1hjbidnohpjn4/mindoc-1hlir5r0t9hgc.html)分别列出 `get_more_info_batch`、`get_stock_info_batch` 的具名返回字段，例如 `ZTDate_Recent`、`RecentHGDate`、`J_yycb`、`J_yyly` 和 `J_gdrs`。文档没有给出这些 API 字段与本地 `tipinfo.dat` 第 `[17]`、`[18]` 列之间的位置映射。接口返回字段名不能直接当成本地文件的列号定义。

这两个身份属于 `tipinfo.dat`。同样的数字索引出现在 `ZHB-tdxstat` 或 `ZHB-tdxstat2` 时，表示其他文件中的位置字段；不能把那些路径已验证的含义转移到 `ZHB-tipinfo`。`core/zhb_client.py` 也没有把 `[17]`、`[18]` 输出成运行时键。

## 结论与未决项

- 已证实：在当前保留期全部 16 个归档中，`tipinfo.dat` 的 `[17]`、`[18]` 都是存在但为空的列。
- 未证实：两列的业务语义、是否为预留列、是否只在特殊条件下填值，以及是否已永久停用。
- 处理：两条路径继续保持 `unverified`；不因观察期全空而标为已证伪，也不根据别的 ZHB 文件同号索引赋予语义。
- 后续可推进的证据：明确说明 `tipinfo.dat` 列位置的官方格式/上游定义，或在保留期内出现可核验的非空原始样本。继续重复扫描相同空值不会增加语义证据。
