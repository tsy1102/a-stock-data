# 字段破解与证据分析方法

本文说明如何提出、验证和排除字段候选；不另行定义碰撞阈值、数据日期规则或注册表状态。

字段猜测还应优先使用实际数据提供方的官方文档和官网股票页面标签/历史值作主动核验；先按来源谱系确认提供方，不以 SDK 或包装仓库代替来源。新浪、同花顺等第三方页面仅在其为登记来源或官方页面缺少可比资料时作为次级佐证。网页结果用于检验候选，不替代原始来源路径映射、日期/单位对齐及既有定案门槛；每日执行与留证要求见 [`PUBLIC_WEB_VERIFICATION.md`](PUBLIC_WEB_VERIFICATION.md)。

| 问题 | 唯一执行依据 |

| 数值、比例、有效样本及来源资格门槛 | [`scripts/collision_rules.py`](../../scripts/collision_rules.py)；[`COLLISION_RULES.md`](COLLISION_RULES.md) 是生成镜像 |
| 日期域、快照择优和样本资格 | [`scripts/collision_dates.py`](../../scripts/collision_dates.py)、[`scripts/temporal_policy.py`](../../scripts/temporal_policy.py)、[`temporal_policy.json`](temporal_policy.json) |
| 每日采集和归档核对 | [`DAILY_RUNBOOK.md`](DAILY_RUNBOOK.md) |
| 碰撞报告完整性和候选审阅 | [`COLLISION_REPORT_REVIEW.md`](COLLISION_REPORT_REVIEW.md) |

代码与说明冲突时，先核对当前代码、测试和生成来源；按用户当前要求修正文档或规则。不要把旧示例、旧报告数字或历史事故说明当作当前执行条件。

## 数据边界与日期

- 遵守根目录 [`AGENTS.md`](../../AGENTS.md) 中的样本保留起点。更早报告仅可在其被明确引用时作历史说明，不能恢复为当前样本。
- 分开记录 `capture_date` / `run_date`、行情 `data_date`、逐源采集时间、来源 `as_of_date` 和事件 `event_date`。采集目录按目标 `data_date` 命名，同日重跑复用目录；行情样本仍按来源有效交易日处理，公告、新闻按事件自然日处理。目录名和本机采集时间都不能代替来源有效日期。
- 对保留的日期化 ZHB 缓存，`zhb_YYYYMMDD.zip` 文件名中的日期是数据日期。解析器将其用于 `ZhbData.date`，采集产物中的 `zhb_date` 是下游副本；若包内 `tdxstat.cfg` 日期冲突，以日期化文件名为准并保留告警。首次下载使用通用文件名时，当前解析器会从包内容取得日期，再保存为日期化缓存文件，行为见 `core/zhb_client.py` 及 `tests/data/test_data_zhb.py`。
- 来源日期缺失或相互矛盾时，按运行时资格规则排除或降级该样本并记录原因；不得用采集目录日、相邻目录或“通常是 T-1”推算。日期真实性与字段语义是两个独立结论。
- 同一来源、同一有效日期的重复采集不是多日独立证据。财务值还要区分报告期；同一报告期重复观察只能增加覆盖，不能冒充报告期切换。

## 来源关系优先核验

- “仓库相同/不同”描述代码托管关系，“同源/独立”描述底层数据提供方；两者不能互相推导。包装仓库可以汇集多个提供方，一个提供方也可以被多个客户端仓库调用。
- 碰撞报告的“来源/接口重叠审阅”按 `(runtime source, 完整规范 code path)` 汇总共同样本，只在双方来源实际 `as_of_date`、日期域和市场阶段对齐后比较。强匹配路径要求至少 3 个证券、3 个不同样本键日期、5 个信息样本；每个共同样本的来源日期须有可确认出处，双方样本覆盖相同，且没有值差异、未对齐样本或恒定低信息路径。报告分别列样本键日期与来源日期，避免把二者混作一个日期。
- 该审阅先回答“当前范围内是否有重复取数/部分重叠”，不回答字段业务含义或底层提供方身份。只有共同路径集合、唯一字段、缺失覆盖、备用路由和定期复验都核实后，才可以暂停重复采集；报告不自动停采。
- 完整路径相同但观测值不同，先核对来源日期、市场阶段、参数、单位、更新策略和适配器变换；路径相同也不保证不同接口返回同一语义。
- 对 `market_sources`、`fuyao` 这类复合采集器，按 `CAPTURE_UNIT_CATALOG` 的接口单元读取 `meta.json.capture_units`；用 `audit_capture_unit_history.py` 比较 catalog 输出路径出现情况、结构指纹、日期形状字段、采集器调用耗时、逻辑调用数和跨数据日的字段值指纹。这里的逻辑调用数不是实际 HTTP 请求数，缓存命中、底层重试和传输错误须另查；适配器可能将传输失败归一为空结果，`empty` 不能证明上游成功返回空数据。输出路径出现情况也不等同注册表完整字段覆盖。报告中“请求数据日”不能替代响应 `as_of_date`；未确认来源日期时，变化率只能作为调查线索。同一有效来源数据日的重复请求只增加同日尝试记录，不增加独立日期数。
- 将来评估某单元降频或退役时，须另行形成可复核结论：确认接口身份和完整字段契约；覆盖所有登记路径并列出独有/缺失字段；在日期合格的共同样本上检验替代或补充关系；按字段时效策略观察值变化、数据延迟及财报/事件等刷新窗口；核查适配器参数、限流/失败状态、备用来源和切换后恢复方案。单靠连续数日值相同、路径重叠或来源包装名称不构成退役证据；审计脚本和采集器都不自动更改频率或停用接口。

## 官方锚优先

- 先处理通达信和同花顺已有官方定义、且项目适配器可以精确追溯到官方字段的路径。顺序为：官方接口/协议定义 → 项目请求与适配器映射 → 原始响应路径 → 可比样本抽核。碰撞报告优先展示有官方契约锚命中的目标。
- 官方定义与项目完整路径精确对应时，直接走 `source_contract` 定案该来源字段；不要求先得到 L1，也不要求另一个来源同义。字段语义定案后，跨源映射仍需单独核验。
- 公开仓库或 SDK 的字段名用于找接口、解析映射和提出候选，不代替官方定义。若两个接口被证明调用同一提供方，也不能把同源重复值当作独立来源证据。

## 选择证据路径

先确认完整来源路径、字段身份、适配器映射和可用日期，再根据候选选取最直接的验证方法；不要求每个字段机械地遍历所有方法。

- 对未知字段先保留原始完整路径，再按名称逐词拆解拼音，并给出一个或多个中文直译及英文业务术语候选；名称不透明时记录多种可能，不强行选一个。随后用上游字段文档、发行人官网标签与历史值、单位和日期对齐、公式结构及跨源样本逐项检验。名称猜测与样本数值冲突时，必须并列记录为矛盾，继续检查协议偏移、字段顺序、解码器/适配器映射、单位、报告期和合并/母公司口径；不得因数值巧合直接覆盖名称候选，但也不得只因与名称或第三方文档冲突而丢弃可复核的实证。满足下方来源内实证条件时，应按观测结果定案并保留冲突记录。

| 方法 | 能回答的问题 | 不能单独证明的内容 |
|---|---|---|
| 官方接口或协议契约 | 某来源的精确路径、字段含义、单位、版本和适用范围 | 与另一来源等价、底层来源独立 |
| 跨源数值对撞 | 两个逐源字段是否存在符合当前运行规则的数值关系 | 名称相似、来源独立性或仅凭一次巧合的语义结论 |
| 公式、单位和结构校验 | 字段是否符合可复算关系或已知单位变换 | 未核实输入、日期或量纲时的正式定义 |
| 时间序列、全市场分布、配置文件和客户端资料 | 生成候选、检查变化规律或定位定义材料 | 自动通过 L1/L1-U 或写入主字典 |
| 相关性、字段名、排列位置和覆盖缺口 | 确定后续调查方向 | 字段语义或跨源等价 |

跨源关系和单源定义是两条证据路径。权威契约可以定义一个来源的字段，但不会因此建立跨源 `mappings` 或证明来源独立。反之，没有有效对撞命中也不等于字段已证伪：先检查覆盖、有效日期、空值、单位和来源谱系，再选择能验证该候选的独立证据。

同完整字段路径的来源重叠审阅会把精确相等与舍入近似分开：近似只作独立调查线索，不计强匹配或重复路由证据。确认采集替代关系前还要检查每个接口的完整契约覆盖、独有路径、失败回退和复验策略；报告本身不会停用来源。

### 分类轴与晋级

- `level` 中的 `L1`、`L1-U`、`L1-C`、`L4` 是兼容的碰撞结果代码，不是逐级晋级状态。报告同时使用 `match_class` 表示观测关系类型、`evidence_basis` 表示证据来源、`adjudication_progress` 表示候选、诊断或已登记关系复验状态；这些轴不互相替代。
- `E3` 是历史来源内实证记录的兼容标记，不与 `L1-L4` 排在同一条等级线上。评估新结论时看精确来源路径、证据依据、样本覆盖、反例和结论适用范围，不以“升到 E3/L1”作为额外步骤。
- 字段语义按证据进度处理：待分析 → 有候选 → 项目路径与上游定义已对应 → 在适用范围内 verified。官方契约和精确路径证据完整时可以直接定案；跨源字段关系和采集路由关系分别登记，不能由字段 verified 自动推出。
- 人工候选处置 `unreviewed`、`accepted_for_adjudication`、`rejected` 等是审阅台账状态；`accepted_for_adjudication` 只开放正式裁决入口，不等于已验证。主注册表对精确来源路径的状态或映射才是最终状态。
- L1/L1-U 自动匹配门槛只约束跨源数值关系候选。它不限制官方契约来源内定案，也不自动写入注册表。

### 低信息字段与日期值

- 碰撞报告把当前没有变化能力的路径分入低信息队列：无观测、全空/空白、恒零或其他恒定值。这些路径暂不参加普通数值碰撞，出现新有效值后重新评估；恒定样本不等于字段无意义，零、缺键、空值和失败仍须分别记录。
- 对至少 3 个非空观测且其中至少 80% 可解析为合法 `YYYYMMDD` 或 `YYYY-MM-DD` 的字段，标记为日期值候选。日期值字段按日期对照，不做单位比例、近似舍入或数值公式猜测；报告列出完整路径、编码、股票、样本键日期、来源 `as_of_date` 和规范化值样例。
- 日期值候选必须核实真实业务角色：上市日、记录更新日、报告期、披露/事件日、生效日或来源数据日。日期形状只帮助识别类型；不得把字段值、采集目录日、采集时间和来源 `as_of_date` 混为一谈。

### 来源内实证何时足以定案

- `L1/L1-U` 的多日门槛用于自动跨源候选，不能作为来源内字段释义的额外门槛。若提供方官方接口/协议明确给出字段释义，且项目采集路径已精确映射到该官方字段，来源契约本身即可确认该来源路径；公开财报/官方页面的逐值核验用于加强或发现冲突，不再附加固定股票数、采集日数或报告期数门槛。
- 对需要用发行人财报实证确认的字段，先证明项目的精确采集路径对应待核值，再按报告期、合并/母公司口径、单位及有依据的精度对齐，核对全部已采集且有可比正式报告的股票。若官方字段释义与财报行项目一致、全部可比样本吻合且没有反例，足以将该完整来源路径定为已验证；不得因样本未达到固定家数、缺少第二个报告期或缺少重复采集日而搁置。样本数影响结论的适用范围和置信度，须如实记录；只有具体指出样本不足以区分的替代解释时，才可继续保持未决。
- 来源内实证不限于财务字段。官方接口在同一原始记录中并列提供评级数值与名称、枚举代码与标签等明确关系时，若项目适配器对精确路径是原样映射，且完整可比留存样本无矛盾，配合官方详情页/公告抽核即可走 `empirical_source_semantics` 路径确认该来源字段；需列明空值/未返回记录和观察到的取值范围，不外推未出现的取值。历史 registry 的 `E3` 保留作兼容标记，不是新增门槛。
- 第二个报告期/交易日只在需要识别字段变化周期、日期语义、刷新规则或区分仍然可行的替代解释时才是必要证据。稳定的财报项目可用同一报告期内的横向样本核验；报告数值、缺值和未覆盖股票都必须如实列出，不能只挑命中样本。
- 包装仓库或 SDK 的字段表不是底层提供方的官方契约。若其标签与官方财报实测相冲突，先核实原始路径和解码映射；在官方财报明确列出对应项目、全部可比采集样本吻合且无反例时，按实际财报项目定案，并把包装层标签记为冲突证据。不得把追查标签冲突根因当作语义定案的前置条件。该结论仅适用于核验过的完整来源路径，不自动建立跨源映射。
- 精确命中与语义近似命中要分开表述。容差优先依据单位换算、页面展示刻度或浮点/上游量化精度；若残差不能归因到具体舍入机制，但全部可比采集样本都稳定贴合同一个官方项目、差值相对项目规模很小且有区分力的替代项目不匹配，仍可人工定案该来源路径的指标语义。须写出样本覆盖、逐样本误差、最大相对差和未解释残差，不得声称逐值相等或武断归因于舍入。`candidate_triage.approximate_matches` 的宽松筛查窗口本身不能作为定案容差；仅凭少数近似命中或存在同样吻合的替代项目时仍不足。

## 防止假阳性与假阴性

- `0`、`null`、缺键、失败和接口未返回是不同状态。双方相同的占位值不能充当信息命中；一侧有效非零而另一侧为零属于失配。具体计数以运行时规则为准。
- 对连续数值先核对单位、精度和计算口径；枚举码、整数和连续值的精确比较策略由 `collision_rules.py` 统一决定。`candidate_triage.approximate_matches` 是独立的舍入近似筛查层：0.5% 相对差或 0.01 原单位绝对差只用于产生研究线索，不计 L1/L1-U、不表示字段等价，也不直接进入注册表裁决。须按来源页面确认单位、显示精度和有效日期，并保留误差公式及反例；已知单位换算仍走比值证据路径。
- 注册表中 `verified` 的来源路径无论元数据是否完整，都会退出破解目标；缺失含义/单位或运行时身份歧义保留在 `field_metadata_gaps.md` 等复核视图中，未解决前不作为碰撞锚。
- 相关性和公式拟合用于排序候选；要检查有效样本、不同日期、股票覆盖、来源独立性、反例及完整报告。相关系数高、同序号或同字段名都不是裁决条件。
- “没有匹配”要区分源覆盖不足、日期不合格、共同缺失、数值失配和真正的反例。报告未完整或候选明细无法对账时，结论保持未完成。
- 主动调查采用可证伪假设：说明若候选为真应看到什么，选择最小且安全的核验；官方资料可公开获取时按来源限制和项目限流规则查证。无需为形式完整而执行与字段无关的历史样本扫描。

## 形成结论与维护项目

1. 在完整候选报告中核对 `report_completeness`、候选身份、有效日期和所有明细；具体命令及分页规则见 [`COLLISION_REPORT_REVIEW.md`](COLLISION_REPORT_REVIEW.md)。
2. 将每个候选记录为可继续验证、证据不足、来源/日期无效、需外部契约、已证伪或重复关系，并引用可复核的报告、原始样本或上游定位。
3. 按 [`ADJUDICATION_WORKFLOW.md`](ADJUDICATION_WORKFLOW.md) 预览和应用裁决，再检查生成视图、注册表 parity 与相关回归。机器候选或审阅记录本身不改变主字典。
4. 定案字段继续采集，作为后续对照锚。字段语义确认不自动改变采集源优先级、限流、五大报告路由或冗余退出状态；这些变更须单独依据实际消费方和来源证据审查。
