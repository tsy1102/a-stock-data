### ⚠️ 核心铁律: ZHB 数据日期 = 最近交易日快照（非机械 T-1, 2026-08-27 固化 / 2026-08-27 修正）

> **ZHB 本地包 = 最后一个已收盘交易日(最近交易日)的快照**, 不是机械地等于"运行日前一天"。
> - **交易日运行(盘中/盘后)**: ZHB 仍是昨日(T-1)收盘数据, 落后于当日 reports(当日报告的
>   涨停池/天梯/行情= T 日实时) → 此时"T-1"成立, 不能拿当日报告对撞当日 ZHB。
> - **休市日运行(周末/节假日)**: 无 T 日新数据, ZHB 日期 = 最近交易日 = 任何报告实际分析的
>   数据日(如周六采集=周五收盘) → 与"当日(休市日)报告"对撞**有效**, "T-1"措辞反而误导
>   (因无 T 日可比, ZHB 日期即报告数据日)。
> **对撞破解的硬规则是"按交易日日期对齐", 不是"按日历 T 禁止同日比"**: 用 ZHB(zhb_date=D)
> 对撞**交易日 D 当日报告**; 若对撞运行日 T 且 T≠D, 须验证字段是否已刷新到 T(涨停族
> type/lianban/count 实测为 T 日盘中值)。
> (2026-08-27 初犯: 交易日用 8/27 天梯对撞 8/27 采集 ZHB(8/26)得 type 0/20 假阴性——因
> ZHB 仍是 T-1。休市日不存在此陷阱, 因 ZHB 日期=报告数据日。)

**正确对撞矩阵（按 zhb_date 对齐, 而非按日历 T）**：
| 采集场景 | ZHB 数据日期(zhb_date) | 应对撞的 reports |
|---|---|---|
| 交易日采集 | 最近交易日 = T-1(前一日) | **T-1 当日报告**(该日涨停池/天梯/连板) |
| 休市日采集(如周六) | 最近交易日 = 周五 | **周五报告**(=该休市日报告实际分析的数据日) |
| 连续采集次日 | zhb_date 推进到新最近交易日 | 对应该 zhb_date 的报告 |

- **核心逻辑**: 连续采集下, "今日最新 ZHB(T-1)" 正好等于 "昨日报告的数据日"——
  用 8/27 采集的 ZHB(8/26 数据) 对撞 8/26 报告, 或对撞 8/27 报告(因 ZHB 涨停族等
  实时字段实际已刷新到今日盘中)——**两条路径都可, 但必须标注所用报告日期**
- **操作规范**:
  1. 每次对撞**先打印 `raw_zhb.json` 的 `zhb_date`** 与所用报告文件名/日期
  2. 若 ZHB 日期(D)≠运行日 T(即 T 为交易日且 ZHB 仍滞后), 优先对撞 **D 当日报告**(日期严格对齐);
     若 D==运行日 T(休市日场景, ZHB 日期=报告数据日), 直接对撞当日报告即可
  3. 若对撞当日报告, 需**验证字段是否实时刷新**(如涨停族 type/lianban/count 实测
     为当日盘中值, 虽快照 date=T-1)——逐字段验证, 不可假设
  4. 结论标注所用 ZHB 日期 + 报告日期(如 "8/27 采集ZHB(8/26) + 8/26报告")
- **例证(2026-08-27 V17.0.10)**: type(Col33)=连板数 的破解正是靠"8/27 采集 ZHB +
  8/27 天梯"得到 20/20 完全匹配; 若误用 8/26 报告则 0/20 全错

## 〇·二、对撞判定标准（用户定义，2026-08-29 固化 / 唯一权威定义）

> **对撞 = 扫描同一日期、不同源返回的「相同数字」的字段。**
> 若其中某一个字段已经被破解，则可**反推**与之同值的未知字段 = 那个已破解字段。

**对用户定义的规则，这就是全部内容，没有第二条。**
唯一证据只有一项：**逐股数值相等**。除此之外（序号、字段名、排列位置、相关性）都**不是**判定证据。

### 边界澄清（助手补充，⚠️ 不是规则，2026-08-29 因表述不当被纠正）

- **序号（列号 / 键名 `fNN` / `[N]` / 数组下标）只是字段的一种表现形式，不是字段本身。**
  - 不能因为两源序号**一致**，就默认它们是同一字段；
  - 也不能因为序号**不一致**，就默认它们不是同一字段；
  - 更不能单独因为"字段名或序号一致"就默认不同源的该序号代表同一个字段。
  - "同序号 = 同字段"只能是对撞成立后的**结果**，绝不能当作推理的**前提**。
- 实测反例（用来说明边界，本身不是规则）：push2 `f85`=流通股本(股)、`f86`=收盘时间戳，
  而腾讯 `[85]`/`[86]` 与二者完全不同 → 这两源**不可按序号互相当锚**（锚定必须走数值对撞）。
- ⚠️ **2026-08-29 事故**：助手曾把上面这条边界澄清写成"**同序号 ≠ 同字段**"并标注为"用户设定的规则"。
  **该表述已撤回**——用户从未设定这样一条规则。用户设定的只有开头那段"相同数字"规则；
  序号相关的一切都属于**对该规则边界的说明**，不是独立规则。

### 日期域、快照择优与历史目录（2026-09-30）

所有采集日期必须区分以下口径，不能把它们都压成一个“日期”：

| 日期 | 含义 | 用途 |
|:--|:--|:--|
| `capture_date` / `run_date` | 采集器实际运行的自然日 | 保留采集溯源；事件源自然日窗口以记录日期为准 |
| `data_date` | 采集数据所属日期，并带 `data_date_domain` | 行情源必须是交易所交易日；纯新闻/公告采集允许自然日 |
| 来源 `as_of_date` | 源本身声明的数据截止日；ZHB 使用 `zhb_date` | 作为该源样本的有效日期，优先于目录名 |
| `run_datetime` / `start` | 实际采集时刻 | 识别盘中样本、比较重复快照质量 |

- 行情窗口按**不同有效交易日**计数，使用项目交易日历并纳入 ZHB 补充假期缓存；不把目录数量或周末调休工作日当成交易日数。
- 新闻、公告和互动问答按每条记录的发布时间/事件时间使用自然日；它们与 `T:YYYYMMDD` 行情样本分开，以 `C:YYYYMMDD` 标识，不能跨日期域误配。
- 目录名表示采集归档位置，应保留作溯源。旧版周末/休市日目录若没有 `data_date`，可把其**行情快照**按交易日历归并到此前最近交易日，并留下告警；若显式 `data_date` 是休市日，则跳过该源并告警。不得删除或原地改名，以免丢失采集时间及事件数据。
- 同一来源、同一有效日期出现多份快照时，按盘后完整性、来源状态、有效记录数、日期来源和采集时间择优；报告必须记录择优与折叠告警。盘中或采集时段未知的行情快照可用于观察性候选，但不计入 L1。
- L1/L1-U 每个独立日期至少需要 **18 个有效配对样本**、日命中率至少 18/20，并覆盖至少 3 个不同有效日。已知镜像/别名归为同一证据来源族，同源字段不得组成跨源定案对。
- 日期无效或晚于报告日、源失败/缺失、盘中/未知时段、阶段元数据与采集时刻矛盾、重复 ZHB `zhb_date` 等情况必须在报告中可见；不能静默当作新的一天或静默覆盖。

### 执行门槛（务必逐条遵守）

1. **门槛**：逐股精确值相等 **≥8/20** 才可宣告"同一字段"。
2. **容差分级（按字段类型区分，2026-09-03 修订）**：
   - **整数/枚举/常量码**（状态位、板级码、固定常量如 100）：精确相等（rel_tol=1e-9，防浮点）→ 可判同一字段。绝不套用小数容差，否则相邻码值（如板级 23 vs 24）会误撞。
   - **连续小数值**（价格/成交额/市值/比率/涨幅等）：用**舍入感知容差**（见下「精度对齐对撞 · 通用修订」）→ 仍属「逐股数值相等」范畴，**不是** 1% 同族（比后者严格 2+ 数量级）。
   - 1% 容差命中（对连续值）→ **只能证明"同族"**（同属价格类/股本类），**不能**证明同一字段。
3. **相关性 ≠ 对撞**。相关性只能作为辅助筛选，**永远不能单独作为破解结论**（见下）。
4. **多日复核（2026-08-29 晚增补，PART G 实战固化）**：
   - 有连续采集数据时，任何"对撞命中"必须在 **≥3 个独立采集日重复出现**才可作为候选；
     单日命中一律视为巧合（实测案例：0813 腾讯[85]/[86] 全 0 占位，对 0 值字段造出 19-20/20
     满值假命中，多日一剔除即消失）。
   - 扫描前必须先做**数据质量盘点**：剔除"目标字段全 0/全 None"的采集日（占位零值空撞）、
     跳过采集失败股（键存在但无 fields）。
   - 扫描器必须**排除同源对**（同一响应行内的字段对齐不是跨源对撞证据）。

### 🔴 精度对齐对撞（2026-09-01 新增，血的教训）

**事故**：用 `rel_tol=1e-9` 精确相等做 fuyao（官方锚）× push2 财务字段对撞，
**24 个财务锚只命中 1 个**，假阴性率 96%。差点据此得出"push2 财务字段与 fuyao 不同源"的**假结论**。

**根因**：不同源**发布精度不同**——

| 源 | 财务字段精度 | 实例 |
|:---|:---|:---|
| push2 | **10~12 位全精度** | `f186=89.5552128279`、`f185=-1.951594855028`、`f190` 12 位 |
| fuyao（锚） | **4~6 位小数** | `sale_gross_margin=89.5552`、`-1.951595` |

⚠️ 本字典长期把 `f186` 记作 `89.56`（四舍五入后的**显示值**），照此建锚必然全军覆没。

**规则**：当锚源与目标源发布精度不同时，判据改为——

```
|a − b| ≤ max(5e-5, |a| · 5e-6)      # 允许锚源末位（4~6 位小数）舍入差
```

仍属「**逐股数值相等**」范畴，**不是**相关性、**不是** 1% 容差同族（比后者严格 3 个数量级）。
修正后命中由 1/24 → **6/24**，且全部 20/20 或 19/20。

> **通用要求**：接入任何新锚源前，先抽查其**小数位分布**（如 push2：f184/f186/f187/f188 为 10 位、
> f185/f190 为 12 位、f103/f173 为 2 位），据此设定对齐容差，**不可一律用 1e-9**。

### 🔴 精度对齐对撞 · 通用修订（2026-09-03，舍入感知容差）

**事故（补充）**：上条公式只覆盖"push2 10~12 位 vs fuyao 4~6 位"这一种财务精度差。
实战更普遍的是**连续小数值的源间小数位差**：同一价格字段，A 源报 **2 位小数**、B 源报 **5 位小数**
（如 `12.34` vs `12.34567`）。若仍用 `rel_tol=1e-9` 严格逐位相等，差值 `0.00567` 远超 1e-9 →
**真同字段的对撞失败（假阴性）**——其害与 2026-09-01 财务事故同构，只是量级更常态。

**根因**：不同源**发布/显示精度不同**（2 位 / 5 位 / 全精度），不是字段不同。逐位数字相等是
**显示层巧合**，跨源对撞不能用它当判据。

**规则（通用·按字段类型，2026-09-03 铁律①修订核心）**：

1. **整数/枚举/常量码** → 仍 `rel_tol=1e-9` 严格相等（防相邻码误撞，见容差分级）。
2. **连续小数值** → 用**舍入感知容差**，以**较粗精度源（小数位更少）的舍入单位**为判等上限：

```
ulp(x) = 10^(−d_x)            # d_x = 该源此值的实际小数位（反映发布精度）
|a − b| ≤ max(ulp_a, ulp_b)   # 允许细精度源多出的小数位；较粗源主导容差
```

   - 实例：价格 A=`12.34`（2 位，ulp=1e-2）、B=`12.34567`（5 位，ulp=1e-5）
     → `|12.34 − 12.34567| = 5.67e-3 ≤ 1e-2` → **判同一字段**（✅ 真同字段，不是巧合）。
   - 与上一条财务公式 `max(5e-5, |a|·5e-6)` **完全兼容**：财务场景下 fuyao 4~6 位
     （ulp≈1e-4~1e-6）即落入该区间，二者同构——统一用本通用式即覆盖财务与价格两类。
   - **判等本质不变**：仍是「逐股数值相等」范畴（差值 ≤ 粗精度源一个舍入单位），
     **不是**相关性、**不是** 1% 容差同族（比后者严格 2+ 数量级）。
   - **实现提示**：引擎端若由 float 反推小数位，先 `round(x, 8)` 消除浮点噪声再数小数位；
     或直接按"源×字段类"精度表（fuyao 价格 2 位 / push2 价格 5+ 位 / zhb 码整数）查表取 `ulp` 更稳。
     两值均整数（d=0）时退化为 `1e-9` 严格相等，避免 23 vs 24 这类相邻码误撞。

> 🔴 **铁律①修订一句话**：跨源对撞**不要求逐位数字严格相等**；只要两值之差 ≤ **较粗精度源的舍入单位**，
> 即视为同一字段的数值相等。整数/枚举码除外（仍须逐位严格相等）。

### 🔴 命中率分层（2026-09-01 新增）

**事故**：初版引擎把 `20/20` 与 `8/20` 同等判为「定案」，把盘后**买一价/卖一价**误判为「现价」。

**规则**：

| 命中率 | 判定 | 理由 |
|:---|:---|:---|
| **≥18/20** 且每个 miss 均可解释 | ✅ **L1 定案** | 真同字段的 miss 应可归因（停牌、口径、占位、滞后） |
| **8~17/20** | ⚠️ **存疑·不定案**，须专项复核 | 价格族/量族彼此本就在 1% 内互近，中等命中率多为**自然巧合** |

**实测反例**（初版误判、分层后正确剔除）：

| 锚 | 目标 | 命中 | 真相 |
|:---|:---|:---|:---|
| `snapshot.last_price` | tx[9] 买一价 / sina[6] / tdx bid1 | 16/20 | 盘后买一价常等于收盘价 → 巧合 |
| `snapshot.last_price` | tx[19] 卖一价 / sina[7] / tdx ask1 | 11/20 | 同上 |
| `snapshot.last_price` | **f43 / tx[3] / sina[3]** | **20/20** | ✅ 真同字段 |

> **配套铁律：miss 必须先查口径与规则，再判巧合。**
> 实测：`tx[47]` 涨停价按统一 `×1.1` 计算仅 9~10/20（看似巧合），
> 改为**按板块幅度**（主板 10% / 创业板·科创板 20% / 北交所 30%）后 **20/20**。
> 同理 `tx[6]` 成交量按统一"手"仅 15/20，改为**按代码段**（688→股，其余→手）后 **20/20**。

### 🔴 比值族对撞（单位换算定案 L1-U，2026-09-01 新增）

同一字段跨源**单位不同**时（股/手、元/万元、%/小数），数值不相等但**比值是常数**。
这比「1% 容差同族」强得多——属「逐股数值定比」范畴。

**判据（四条全过）**：

```
① 比值离散度 CV = std/mean < 1e-4  （0.01%，比 1% 容差严格 2 个数量级）
② 比值 ∈ {100, 1000, 10000, 10, 0.1, 0.01, 0.001, 1e6, 1e8}（容差 0.5%）
③ 命中 ≥18/20
④ ≥3 个独立采集日重复
```

**实例**：`fuyao snapshot.volume ÷ push2 f47 = 100.0000`（6 日 × 20/20，min 99.9930 / max 100.0013）
→ 双向互证 **f47 单位=手、fuyao 单位=股**。

### ⚠️ 财务锚的"独立性"≠ 采集日数（2026-09-01 新增）

**财务指标在同一报告期内是常量**，因此在 5 个采集日重复命中**不构成独立证据**（是同一个常数）。

**真独立性来自【报告期切换】**。规则：

- **行情类锚**（价格/量/额/市值）：逐日变化 → 多日 = 真独立，要求 **≥3 日**。
- **财务类锚**（ROE/增长率/利润率…）：要求 **≥3 日 且 跨 ≥2 个不同报告期**。

**黄金事件窗口**：fuyao `fin_report` 在 **20260825 由 `2026-1` 切换为 `2026-2`**，
0824~0828 期间两期并存（不同股切换节奏不同）——这是**验证财务映射真伪的最佳窗口**，
仅凭"多日命中"无法排除"两个不同量级的常量被错配"。

### ⚠️ 相关性陷阱与强制流程（2026-08-29 血的教训）

**事故**: 腾讯[86] 与 level-1 委差 Pearson **r=+0.965**，一度被判为"[86]=委差 L2"。
实际是 **601288（农业银行）单点绑架**——其量级比其余 19 股大 2 个数量级，同时主导了两个变量的方差。

| 检验 | 结果 | 判定 |
|---|---|---|
| Pearson（全样本 n=20） | +0.965 | 假强相关 |
| **Spearman ρ**（秩相关，抗离群） | **−0.012** | 相关性不存在 |
| **留一法 Pearson**（剔除 601288） | **−0.863** | **符号翻转** |
| 符号一致率 | 12/20 | 弱 |
| 对撞精确 / 1% 容差 | **0/20 / 0/20** | 完全不满足 |

→ **结论撤回，[86] 恢复 ❓未知。**

**强制流程**（任何"字段 A ≈ 字段 B"的判定，三条**必须全过**，缺一不可）：
1. **对撞**：逐股精确值相等 ≥8/20（1% 容差仅可标注"同族"）。
2. **相关性**（辅助）：Pearson 与 Spearman **同号**，且 **|Spearman| > 0.6**。
3. **留一法**：剔除任一样本后相关系数**不翻号**。

**相关性只能用来"生成候选"，不能用来"定案"。**

### ⚠️ 对撞是终判，主动法（非对撞）是生成候选与方向核实的必需前置（2026-09-03 反思）

**用户批评（2026-09-03）**：近期破解把"数据对撞"当成**唯一标准**，丢失了早期会主动使用的
拼音/英文猜测、自行计算推断、配置直解、表头对照、K线时间序列等主观能动性方法——
只因跨源对撞假阴性（未知字段在其它源全空、命中 0）就直接判"未知/收口"，从不主动去证实或证伪。

**定位重述（铁律级）**：
1. **对撞是定案终判**（四铁律：精确 ≥18/20 / 命中率分层 / 比值族 / 多日复核）——没有数值精确对撞，不得写 L1/L2 定案。
2. **但主动法（非对撞）是定案前的必需前置**，三类职责不可替代：
   - **生成候选**：相关性 / 序位相邻 / 覆盖三角 / 表头拼音英文 / 配置直解 → 列出"可能是什么"。
   - **方向核实（证真）**：自行计算（K线自算 Beta / 衍生价 / 代理量）可在无官方字段表时给出**独立定量证据**，坐实"是什么族/什么量级"。
   - **证伪（排除）**：自行计算也能**否定**错误候选（如 [86] 符号(收>开)与 [86]>0 仅 3/6 一致 → 否定"日内净买"）。
3. **禁止"对撞假阴性即收口"**：跨源未知全空导致对撞命中 0，只能判"暂无对撞证据"，
   **不能**替代主动法。应转用思路④⑥⑦（自算/配置直解）给出候选与置信方向，标注 L3/L4 并显式写"待对撞终判"。

**2026-09-03 实证（scratch/proactive_crack_20260903.py，纯非对撞法）**：
| 未知 | 主动法 | 结论 | 对撞法能否得此结论 |
|---|---|---|---|
| 腾讯 [56] | 887只800日K线自构等权市场代理，自算 Beta | Pearson([56],自算Beta)=**0.908** → 坐实 Beta 族 | ❌ 跨源未知全空、命中 0，从未定量确认 |

→ 本窗口证明：主动法把 [56] 从"L4 维持未定案"**升级为 Beta 族高置信**、为 [85]/[86]/[22] 给出命名候选与方向，
而这些是碰撞法（因源覆盖盲区）**永远得不到**的。对撞仍是终判，但**不再是对撞假阴性→直接收口**。

### 通用引擎的候选方法输出（2026-09-30）

`collide.py` 除精确/比值对撞外，还输出不具定案效力的候选：

- **语义标签**：比较来源字段标签的可解释词元；只提示查表/查配置的方向。
- **公式关系**：检测跨样本稳定的仿射关系 `right ≈ a × left + b`，保留系数和拟合样本。
- **逐股时间序列**：比较同一股票跨有效交易日的变化关系，并要求多只股票方向一致。
- **稳健相关**：Pearson 与 Spearman 同号、Spearman 达门槛，且留一法不翻号。

每项候选都必须附有效样本数、样本日期、股票代码示例和两侧来源。相关、公式或标签相似都只是生成候选；只有满足独立来源、每日样本量、多日和精确/比值规则后，才允许输出 L1/L1-U。
