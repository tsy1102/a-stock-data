> 来源：2026-08-12~14 破解实战沉淀的候选生成与证据分析方法。
> 跨源语义等价按运行时碰撞规则裁决；单源字段定义可另走权威上游契约流程。命名、表头、公式、统计和相关性用于生成或排除候选，不能自行晋级。

### ⚠️ 核心铁律: ZHB 数据日期 = 最近交易日快照（非机械 T-1, 2026-08-27 固化 / 2026-08-27 修正）

> **ZHB 本地包 = 最后一个已收盘交易日(最近交易日)的快照**, 不是机械地等于"运行日前一天"。
> - **交易日运行(盘中/盘后)**: ZHB 仍是昨日(T-1)收盘数据, 落后于当日 reports(当日报告的
>   涨停池/天梯/行情= T 日实时) → 此时"T-1"成立, 不能拿当日报告对撞当日 ZHB。
> - **休市日运行(周末/节假日)**: 无 T 日新数据, ZHB 日期 = 最近交易日 = 任何报告实际分析的
>   数据日(如周六采集=周五收盘) → 与"当日(休市日)报告"对撞**有效**, "T-1"措辞反而误导
>   (因无 T 日可比, ZHB 日期即报告数据日)。
> **对撞破解的硬规则是"按交易日日期对齐", 不是"按日历 T 禁止同日比"**: 用 ZHB(zhb_date=D)
> 对撞**交易日 D 当日报告**; 若对撞运行日 T 且 T≠D, 须验证字段是否已刷新到 T(涨停族
> type/lianban/count 实测为 T 日盘中值)。
> (2026-08-27 初犯: 交易日用 8/27 天梯对撞 8/27 采集 ZHB(8/26)得 type 0/20 假阴性——因
> ZHB 仍是 T-1。休市日不存在此陷阱, 因 ZHB 日期=报告数据日。)

**正确对撞矩阵（按 zhb_date 对齐, 而非按日历 T）**：
| 采集场景 | ZHB 数据日期(zhb_date) | 应对撞的 reports |
|---|---|---|
| 交易日采集 | 最近交易日 = T-1(前一日) | **T-1 当日报告**(该日涨停池/天梯/连板) |
| 休市日采集(如周六) | 最近交易日 = 周五 | **周五报告**(=该休市日报告实际分析的数据日) |
| 连续采集次日 | zhb_date 推进到新最近交易日 | 对应该 zhb_date 的报告 |

- **核心逻辑**: 连续采集下, "今日最新 ZHB(T-1)" 正好等于 "昨日报告的数据日"——
  用 8/27 采集的 ZHB(8/26 数据) 对撞 8/26 报告, 或对撞 8/27 报告(因 ZHB 涨停族等
  实时字段实际已刷新到今日盘中)——**两条路径都可, 但必须标注所用报告日期**
- **操作规范**:
  1. 每次对撞**先打印 `raw_zhb.json` 的 `zhb_date`** 与所用报告文件名/日期
  2. 若 ZHB 日期(D)≠运行日 T(即 T 为交易日且 ZHB 仍滞后), 优先对撞 **D 当日报告**(日期严格对齐);
     若 D==运行日 T(休市日场景, ZHB 日期=报告数据日), 直接对撞当日报告即可
  3. 若对撞当日报告, 需**验证字段是否实时刷新**(如涨停族 type/lianban/count 实测
     为当日盘中值, 虽快照 date=T-1)——逐字段验证, 不可假设
  4. 结论标注所用 ZHB 日期 + 报告日期(如 "8/27 采集ZHB(8/26) + 8/26报告")
- **例证(2026-08-27 V17.0.10)**: type(Col33)=连板数 的破解正是靠"8/27 采集 ZHB +
  8/27 天梯"得到 20/20 完全匹配; 若误用 8/26 报告则 0/20 全错

## 〇·二、对撞判定标准（用户定义，2026-08-29 固化 / 唯一权威定义）

> **对撞 = 扫描同一日期、不同源返回的「相同数字」的字段。**
> 若其中某一个字段已经被破解，则可**反推**与之同值的未知字段 = 那个已破解字段。

**对用户定义的规则，这就是全部内容，没有第二条。**
唯一证据只有一项：**逐股数值相等**。除此之外（序号、字段名、排列位置、相关性）都**不是**判定证据。

### 边界澄清（助手补充，⚠️ 不是规则，2026-08-29 因表述不当被纠正）

- **序号（列号 / 键名 `fNN` / `[N]` / 数组下标）只是字段的一种表现形式，不是字段本身。**
  - 不能因为两源序号**一致**，就默认它们是同一字段；
  - 也不能因为序号**不一致**，就默认它们不是同一字段；
  - 更不能单独因为"字段名或序号一致"就默认不同源的该序号代表同一个字段。
  - "同序号 = 同字段"只能是对撞成立后的**结果**，绝不能当作推理的**前提**。
- 实测反例（用来说明边界，本身不是规则）：push2 `f85`=流通股本(股)、`f86`=收盘时间戳，
  而腾讯 `[85]`/`[86]` 与二者完全不同 → 这两源**不可按序号互相当锚**（锚定必须走数值对撞）。
- ⚠️ **2026-08-29 事故**：助手曾把上面这条边界澄清写成"**同序号 ≠ 同字段**"并标注为"用户设定的规则"。
  **该表述已撤回**——用户从未设定这样一条规则。用户设定的只有开头那段"相同数字"规则；
  序号相关的一切都属于**对该规则边界的说明**，不是独立规则。

### 日期域、快照择优与历史目录（2026-09-30）

所有采集日期必须区分以下口径，不能把它们都压成一个“日期”：

| 日期 | 含义 | 用途 |
|:--|:--|:--|
| `capture_date` / `run_date` | 采集器实际运行的自然日 | 保留采集溯源；事件源自然日窗口以记录日期为准 |
| `data_date` | 采集数据所属日期，并带 `data_date_domain` | 行情源必须是交易所交易日；纯新闻/公告采集允许自然日 |
| 来源 `as_of_date` | 源本身声明的数据截止日；ZHB 使用 `zhb_date` | 作为该源样本的有效日期，优先于目录名 |
| `run_datetime` / `start` | 实际采集时刻 | 识别盘中样本、比较重复快照质量 |

- 行情窗口按**不同有效交易日**计数，使用项目交易日历并纳入 ZHB 补充假期缓存；不把目录数量或周末调休工作日当成交易日数。
- 新闻、公告和互动问答按每条记录的发布时间/事件时间使用自然日；它们与 `T:YYYYMMDD` 行情样本分开，以 `C:YYYYMMDD` 标识，不能跨日期域误配。
- 目录名表示采集归档位置，应保留作溯源。旧版周末/休市日目录若没有 `data_date`，可把其**行情快照**按交易日历归并到此前最近交易日，并留下告警；若显式 `data_date` 是休市日，则跳过该源并告警。不得删除或原地改名，以免丢失采集时间及事件数据。
- 同一来源、同一有效日期出现多份快照时，按盘后完整性、来源状态、有效记录数、日期来源和采集时间择优；报告必须记录择优与折叠告警。盘中或采集时段未知的行情快照可用于观察性候选，但不计入 L1。
- L1/L1-U 每个独立日期至少需要 **18 个有效配对样本**，并覆盖至少 3 个不同有效日；精确 L1 另要求每日至少 5 个信息配对，信息配对命中率与 L1-U 的有效比例命中率均须达到 90%。已知镜像/别名归为同一证据来源族，同源字段不得组成跨源定案对。
- 日期无效或晚于报告日、源失败/缺失、盘中/未知时段、阶段元数据与采集时刻矛盾、重复 ZHB `zhb_date` 等情况必须在报告中可见；不能静默当作新的一天或静默覆盖。
- AxData 等仍在运行的汇总服务另走接口与来源身份核验轨道；其框架样本不能因接口名称或字段相同就视为独立来源锚。FTShare 旧私有 MCP 服务已退役；公开 REST `A股行情列表` 每日采集，官方定义的字段作为语义契约锚参与对撞。达到强多日匹配门槛的关系列为 `L1-C`，与独立来源 `L1/L1-U` 分开统计。

### L1 信息配对门槛（2026-10-14）

- 精确 L1 每个有效交易日仍要求至少 18 组有效配对；另需至少 5 组信息配对，且至少覆盖 3 个独立日期。
- 两侧同时为零或同时缺失只表示共同默认值/空值，不计入精确命中率；一侧为零、另一侧非零是有效失配，必须计入信息配对分母。
- 精确 L1 的命中率按信息配对计算；L1-U 按有效非零比例样本计算。碰撞 JSON 的 `daily_sample_counts` 是每日完整有效样本数，`daily_informative_sample_counts` 是实际进入对应命中率的信息样本数，`overall_hit` 对 L1 表示信息配对命中率，避免零值把候选推成 L1。
- L1-U 仍按两侧均非零的比例样本和既有每日样本下限校验，不使用双方为零的值反推比例。

### 字母字段名候选（2026-10-14）

碰撞脚本会将当前采样窗口观察到的注册字段路径，与拼音、英文、缩写、CamelCase 和混合命名候选 inventory 做精确 `(source, 完整 code path)` 匹配；未被 inventory 收录的新路径只生成未翻译的字词拆分。候选条目保留当前字典状态、样本日期和原始来源身份，以便结合数值碰撞、上游接口定义和全市场分布继续复核。名称拆解始终只是搜索提示，不会独立定案、提升碰撞等级或写回主字典。报告 JSON 保留完整候选，Markdown 最多显示 100 条。

### 单源上游契约与跨源数值证据分轨（2026-10-18）

未知字段不只有“等到数值碰撞”这一种破解路径，但证据类型不能互相替代：

1. **跨源等价**：由有效交易日对齐的数值碰撞提出候选，继续遵守 L1/L1-U 样本量、来源独立性、信息配对和多日门槛；只有人工确认语义等价后，才可写入跨源 `mappings`。名称猜测、相关性和框架接口名称不代替这些条件。
2. **单源字段定义**：若权威提供方的接口/协议契约能够精确解释一个来源字段，可直接确认该来源的 `(source, 完整 code path)`，不必虚构跨源锚。必须核对项目适配器从原始响应到运行字段的映射，并登记固定版本/有日期文档、文件路径、字段定位和链接。

单源契约核验只确认该逐源记录的定义，不建立跨源映射、不认定来源独立性，也不将客户端/多源聚合库的仓库说明误当成底层提供方证据。字段的 `verified` 状态和来源锚资格是两个独立判断；后者仍由 `source_lineage.json` 控制。名称拆解与历史字段说明只能帮助找到契约位置，不能替代契约本身。登记和应用步骤见 [`ADJUDICATION_WORKFLOW.md`](ADJUDICATION_WORKFLOW.md) 的“单源上游契约核验”。

未知字段队列另将“含义栏有无文字”和“历史状态能否映射到逐源身份”分开统计。文字已填写不等于语义已验证；两组计数是交叉维度，不应相加。日常采集覆盖量用于决定是否有足够实测样本，不阻止直接通过权威契约核验字段定义。

碰撞报告保留 `L1` 作为兼容性原始列表，同时提供 `actionable_L1` 与 `mapped_pair_revalidations`。已在 registry 登记的映射只进入复验栏，不计入新候选数，不进入新的探索候选台账，也不能再次作为定案动作提交；若复验失配，应先核查样本日期、源端状态和映射证据，再通过独立纠错流程处理。

### AxData 日轮验证与 FTShare 契约锚（2026-10-14；状态更新 2026-10-20）

采集后需单独执行 `collide.py`。它读取所选窗口内的 `axdata_validation.json`，按有效交易数据日去重，并汇总 AxData 接口队列、探针请求数与被动比较计数；不复制原始值、不触发网络请求。257 项接口队列仍按公开来源、路由参数、日期口径与限流逐项审定。已确认运行冗余的生产路由从日常采集退出，按参考源有效日期计数并定期复验；细节见 `DAILY_RUNBOOK.md`。

FTShare 私有托管 MCP 集成已于 2026-10-20 退役；这不包括公开 REST 网关。公开 REST `A股行情列表` 已纳入每日采集，输出 `raw_ftshare_rest.json`，官方字段说明登记在 `field_registry.json` 并进入默认碰撞。逐字段语义已由官方契约确认的值可作右侧锚；达到多日统计门槛的强匹配单列为 `L1-C`，其含义是“字段语义有公开契约依据、关系有实测数据支持，但底层来源独立性未确认”。它不应混入独立来源 L1/L1-U、独立来源覆盖统计或自动定案。未在官方返回字段表中定义的 `symbol_id` 仅作为单次响应观察项，不能用作契约锚。旧私有 MCP 的历史 raw、字段路径和元数据只用于显式扩展的历史研究，不进入默认碰撞。

### 执行门槛（务必逐条遵守）

1. **定案门槛唯一以运行时规则为准**：`scripts/collision_rules.py` 及其人读镜像 `COLLISION_RULES.md` 定义精度、每日有效/信息样本、命中率、多日复核和来源独立性；本方法论中的历史例子不得覆盖运行时门槛。
2. **容差分级（按字段类型区分，2026-09-03 修订）**：
   - **整数/枚举/常量码**（状态位、板级码、固定常量如 100）：精确相等（rel_tol=1e-9，防浮点）→ 可判同一字段。绝不套用小数容差，否则相邻码值（如板级 23 vs 24）会误撞。
   - **连续小数值**（价格/成交额/市值/比率/涨幅等）：用**舍入感知容差**（见下「精度对齐对撞 · 通用修订」）→ 仍属「逐股数值相等」范畴，**不是** 1% 同族（比后者严格 2+ 数量级）。
   - 1% 容差命中（对连续值）→ **只能证明"同族"**（同属价格类/股本类），**不能**证明同一字段。
3. **相关性 ≠ 对撞**。相关性只能作为辅助筛选，**永远不能单独作为破解结论**（见下）。
4. **多日复核（2026-08-29 晚增补，PART G 实战固化）**：
   - 有连续采集数据时，任何"对撞命中"必须在 **≥3 个独立采集日重复出现**才可作为候选；
     单日命中一律视为巧合（实测案例：0813 腾讯[85]/[86] 全 0 占位，对 0 值字段造出 19-20/20
     满值假命中，多日一剔除即消失）。
   - 扫描前必须先做**数据质量盘点**：剔除"目标字段全 0/全 None"的采集日（占位零值空撞）、
     跳过采集失败股（键存在但无 fields）。
   - 扫描器必须**排除同源对**（同一响应行内的字段对齐不是跨源对撞证据）。

### 🔴 精度对齐对撞（2026-09-01 新增，血的教训）

**事故**：用 `rel_tol=1e-9` 精确相等做 fuyao（官方锚）× push2 财务字段对撞，
**24 个财务锚只命中 1 个**，假阴性率 96%。差点据此得出"push2 财务字段与 fuyao 不同源"的**假结论**。

**根因**：不同源**发布精度不同**——

| 源 | 财务字段精度 | 实例 |
|:---|:---|:---|
| push2 | **10~12 位全精度** | `f186=89.5552128279`、`f185=-1.951594855028`、`f190` 12 位 |
| fuyao（锚） | **4~6 位小数** | `sale_gross_margin=89.5552`、`-1.951595` |

⚠️ 本字典长期把 `f186` 记作 `89.56`（四舍五入后的**显示值**），照此建锚必然全军覆没。

**规则**：当锚源与目标源发布精度不同时，判据改为——

```
|a − b| ≤ max(5e-5, |a| · 5e-6)      # 允许锚源末位（4~6 位小数）舍入差
```

仍属「**逐股数值相等**」范畴，**不是**相关性、**不是** 1% 容差同族（比后者严格 3 个数量级）。
修正后命中由 1/24 → **6/24**，且全部 20/20 或 19/20。

> **通用要求**：接入任何新锚源前，先抽查其**小数位分布**（如 push2：f184/f186/f187/f188 为 10 位、
> f185/f190 为 12 位、f103/f173 为 2 位），据此设定对齐容差，**不可一律用 1e-9**。

### 🔴 精度对齐对撞 · 通用修订（2026-09-03，舍入感知容差）

**事故（补充）**：上条公式只覆盖"push2 10~12 位 vs fuyao 4~6 位"这一种财务精度差。
实战更普遍的是**连续小数值的源间小数位差**：同一价格字段，A 源报 **2 位小数**、B 源报 **5 位小数**
（如 `12.34` vs `12.34567`）。若仍用 `rel_tol=1e-9` 严格逐位相等，差值 `0.00567` 远超 1e-9 →
**真同字段的对撞失败（假阴性）**——其害与 2026-09-01 财务事故同构，只是量级更常态。

**根因**：不同源**发布/显示精度不同**（2 位 / 5 位 / 全精度），不是字段不同。逐位数字相等是
**显示层巧合**，跨源对撞不能用它当判据。

**规则（通用·按字段类型，2026-09-03 铁律①修订核心）**：

1. **整数/枚举/常量码** → 仍 `rel_tol=1e-9` 严格相等（防相邻码误撞，见容差分级）。
2. **连续小数值** → 用**舍入感知容差**，以**较粗精度源（小数位更少）的舍入单位**为判等上限：

```
ulp(x) = 10^(−d_x)            # d_x = 该源此值的实际小数位（反映发布精度）
|a − b| ≤ max(ulp_a, ulp_b)   # 允许细精度源多出的小数位；较粗源主导容差
```

   - 实例：价格 A=`12.34`（2 位，ulp=1e-2）、B=`12.34567`（5 位，ulp=1e-5）
     → `|12.34 − 12.34567| = 5.67e-3 ≤ 1e-2` → **判同一字段**（✅ 真同字段，不是巧合）。
   - 与上一条财务公式 `max(5e-5, |a|·5e-6)` **完全兼容**：财务场景下 fuyao 4~6 位
     （ulp≈1e-4~1e-6）即落入该区间，二者同构——统一用本通用式即覆盖财务与价格两类。
   - **判等本质不变**：仍是「逐股数值相等」范畴（差值 ≤ 粗精度源一个舍入单位），
     **不是**相关性、**不是** 1% 容差同族（比后者严格 2+ 数量级）。
   - **实现提示**：引擎端若由 float 反推小数位，先 `round(x, 8)` 消除浮点噪声再数小数位；
     或直接按"源×字段类"精度表（fuyao 价格 2 位 / push2 价格 5+ 位 / zhb 码整数）查表取 `ulp` 更稳。
     两值均整数（d=0）时退化为 `1e-9` 严格相等，避免 23 vs 24 这类相邻码误撞。

> 🔴 **铁律①修订一句话**：跨源对撞**不要求逐位数字严格相等**；只要两值之差 ≤ **较粗精度源的舍入单位**，
> 即视为同一字段的数值相等。整数/枚举码除外（仍须逐位严格相等）。

### ⚠️ 财务锚的"独立性"≠ 采集日数（2026-09-01 新增）

**财务指标在同一报告期内是常量**，因此在 5 个采集日重复命中**不构成独立证据**（是同一个常数）。

**真独立性来自【报告期切换】**。规则：

- **行情类锚**（价格/量/额/市值）：逐日变化 → 多日 = 真独立，要求 **≥3 日**。
- **财务类锚**（ROE/增长率/利润率…）：要求 **≥3 日 且 跨 ≥2 个不同报告期**。

**黄金事件窗口**：fuyao `fin_report` 在 **20260825 由 `2026-1` 切换为 `2026-2`**，
0824~0828 期间两期并存（不同股切换节奏不同）——这是**验证财务映射真伪的最佳窗口**，
仅凭"多日命中"无法排除"两个不同量级的常量被错配"。

### ⚠️ 对撞是终判，主动法（非对撞）是生成候选与方向核实的必需前置（2026-09-03 反思）

**用户批评（2026-09-03）**：近期破解把"数据对撞"当成**唯一标准**，丢失了早期会主动使用的
拼音/英文猜测、自行计算推断、配置直解、表头对照、K线时间序列等主观能动性方法——
只因跨源对撞假阴性（未知字段在其它源全空、命中 0）就直接判"未知/收口"，从不主动去证实或证伪。

**定位重述（铁律级）**：
1. **跨源语义等价**按 `COLLISION_RULES.md` 定案；名称、相关性或统计启发不能替代。**单源字段定义**可另按 `ADJUDICATION_WORKFLOW.md` 的上游契约流程确认，但不建立跨源映射或独立锚。
2. **但主动法（非对撞）是定案前的必需前置**，三类职责不可替代：
   - **生成候选**：相关性 / 序位相邻 / 覆盖三角 / 表头拼音英文 / 配置直解 → 列出"可能是什么"。
   - **方向核实（证真）**：自行计算（K线自算 Beta / 衍生价 / 代理量）可在无官方字段表时给出**独立定量证据**，坐实"是什么族/什么量级"。
   - **证伪（排除）**：自行计算也能**否定**错误候选（如 [86] 符号(收>开)与 [86]>0 仅 3/6 一致 → 否定"日内净买"）。
3. **禁止"对撞假阴性即收口"**：跨源未知全空导致对撞命中 0，只能判"暂无对撞证据"，
   **不能**替代主动法。应转用思路④⑥⑦（自算/配置直解）给出候选与置信方向，标注 L3/L4 并显式写"待对撞终判"。

### 通用引擎的候选方法输出（2026-09-30）

`collide.py` 除精确/比值对撞外，还输出不具定案效力的候选：

- **语义标签**：比较来源字段标签的可解释词元；只提示查表/查配置的方向。
- **公式关系**：检测跨样本稳定的仿射关系 `right ≈ a × left + b`，保留系数和拟合样本。
- **逐股时间序列**：比较同一股票跨有效交易日的变化关系，并要求多只股票方向一致。
- **稳健相关**：Pearson 与 Spearman 同号、Spearman 达门槛，且留一法不翻号。

每项候选都必须附有效样本数、样本日期、股票代码示例和两侧来源。相关、公式或标签相似都只是生成候选；只有满足独立来源、每日样本量、多日和精确/比值规则后，才允许输出 L1/L1-U。

数值范围不重叠不得作为跳过条件：不同来源可能以股/万股等单位表示同一字段，也可能存在仿射变换。范围差异只作为报告诊断；精确、比值、相关和仿射方法仍须完整检查。

### 候选覆盖、校准与主动取样（2026-10-20）

通用碰撞报告在保留全局方法候选上限的同时，为每个未知目标保留一条不在全局列表中的最佳候选前沿；JSON 的 `candidate_triage.targets` 记录每个目标的可比较对、血缘/同源跳过数、样本不足数、方法候选数和覆盖摘要。未能保留完整明细的候选仍计入总数和逐目标计数，不得把“未展示”解释为“无候选”。

报告只读每日采集写入 `.tmp/field_evidence_coverage/` 的字段覆盖索引以及窗口内 `meta.json`，映射目标来源的状态、身份和有效日期。独立锚家族另从本轮实际通过来源血缘和字段类型检查的对撞对统计；数值范围差异只作诊断、不排除单位换算或仿射候选，也不把目标字段自身的家族算作锚。索引缺失或字段路径不能映射时会明确标注；它不会触发补采、重试、主字典修改，也不会将未确认血缘的来源提升为锚。

当同一未知字段出现多个方法候选时，报告用按股票分组的留出预测，寻找不同候选映射预测分歧较大的股票，建议下一轮优先复核。它只提供取样优先级，不把候选拟合结果当作验证样本，也不提升碰撞等级。

双输入公式搜索仅使用数值未知目标及其已有方法候选对应的独立锚字段；受限于乘积、两个方向的比值、求和和差值，再拟合一个比例系数与截距。按股票代码固定留出约 20% 样本；至少 36 组样本、10 只股票、3 个日期，留出集至少 3 只股票，验证 R²≥0.985、RMSE 不超过训练目标标准差的 5%，且比最佳单输入线性模型高至少 0.05 才进入报告。此候选搜索用于发现公式线索，未登记量纲和权威公式前不得定案。当前候选输入只从每个目标的前 8 个成对方法候选中选取；无输出不代表未搜索其他公式族。

每轮报告还会用当前窗口内可观测的已登记数值映射作正向候选覆盖检查，并用 `REFUTED_CONCLUSIONS` 中的反例作负向检查。它们用于发现方法候选的漏检和误报倾向，不等于准确率、语义真值或 L1/L1-U 门槛，也不参与定案。

### 完整报告审阅门槛（2026-10-20）

报告的 Markdown 是可读摘要，JSON 是完整机器证据。碰撞器将全量方法候选写入 `method_candidate_inventory`，原 `method_candidates` 仍是全局排名摘要；JSON 的 `report_completeness` 对生成数、保存数、唯一字段对、重复项、缺项及各 Markdown Top-N 截断量逐项对账。`guardrail_hits` 也必须保存在 JSON，不能只出现在 Markdown。

每轮解释结果前必须先验证 `report_completeness.status == "complete"`，并核对候选生成数等于全量明细数、唯一字段对数与缺项/重复数合理。随后要结构化覆盖 JSON 每个结果集合与所有目标，不允许仅看 Markdown 前页、Top-N、候选摘要或历史台账的前段。每个候选必须被归入已审可继续验证、与既有记录重复、样本不足、来源/日期无效、需要外部定义核验或无效反例等处置；各类条数之和须可与清单核对。名称、相关、公式和时间序列候选是排查入口，不能直接升级成语义结论。

若清单缺失、数量不平、报告不含全量明细或审阅覆盖无法对账，该轮结论状态必须标为“审阅未完成”；不得据此断言无候选、无成果、无需补采或可定案。应优先从原始采集文件重建报告和全量候选；原始数据不足时，记录未覆盖字段/候选数、缺失日期及不可恢复原因。旧版报告不能因 Markdown 显示了“前 100 / 共 500”就视为已审全量；例如 2026-10-19 报告 JSON 记载生成 4,376 条方法候选，只保存了全局前 500 条，缺少 3,876 条明细，必须按未完整审阅处理。

#### 1.1 字母字段拆解的执行规则（2026-10-14）

命名拆解用于生成可检索候选，不能单独作为字段定案。每次涉及主字典中的拉丁字母字段时，按完整来源路径逐项保留并记录：

1. **先判记录类型**：区分单字段名、接口/嵌套路径、`f数字` 等序号键、样本值/枚举值和疑似把多字段拼成一个 code 的历史记录。只有字段名进入语义拆解。
2. **保留原始拼写并分层拆解**：分别检查完整拼音、拼音首字母、英文词、英文缩写、大小写/下划线分段及中英拼音混合；多种切分都合理时并列保留，不强行选一项。
3. **明确候选来源**：标出每段是拼音、英文、缩写还是接口惯用词，并写出词面直译。缩写和连写拼音须注明歧义；不能用自动词元拼接生成确定释义。

### 9. 跨源覆盖三角定位 + 表头名称参考（2026-09-03，候选生成/优先级）

> **思路**：一个源提供的字段以常用指标为主、特殊字段少。据此做两件事——

- **（A）表头名称参考（即思路2 的候选生成面）**：项目已收录热门软件表头
  `docs/verify/tdx_headers_definition.md`（通达信）/ `em_tableheader_ids.md`（东财）/ `ths_tableheader_ids.md`（同花顺）。
  未知字段"很可能在表头"——按表头字段名/中文含义做**命名规律猜测**，生成候选名。⚠️ 表头名≠语义（前车之鉴 `fuyao.turnover` 字面换手率实测成交额），须数值对撞确认。
- **（B）跨源覆盖三角（优先级启发）**：若 ≥3 个源都有某基础指标 X，而第4源一直未破解 X，
  **第4源的未知字段"高概率"含 X**（不是"肯定"——第4源可能真无 X，或 X 已破解但被误标名）。
  更精确的法子：**对每个未知字段，先查其语义类的基础指标是否已在所属源破解**——
  - 若该类基础指标**已破解** → 该未知是**专门化/派生字段**，不是那个基础指标（如腾讯现价/开/收/高/低全已破解 → `[85]` 必不是现价，是某派生价格快照；push2 全基础指标已破解 → 其未知 f106/f107/… 是状态码非基础指标）；
  - 若该类基础指标**未破解** → 该未知**可能是那个基础指标**（高优先级，如腾讯缺 Beta 端点 → `[56]` 高概率为 Beta 族）。

> **落地**：`scratch/coverage_candidate_gen.py` 自动建「源×基础指标覆盖率矩阵」+ 对每未知字段生成
> ①覆盖候选（缺失基础指标→候选名）②表头候选名（按语义类搜表头）③序位相邻候选（仅同质子块），输出优先级排序的候选清单喂碰撞引擎。
> **铁律**：本思路与相关性同级，只生成候选 + 排优先级，**不定案**；定案必须走数值对撞（四铁律）。
> ⚠️ 覆盖率缺口对 **ZHB 快照源**例外——ZHB 是离线快照而非实时行情源，缺现价/开/收等行情基础指标是**设计使然**，其未知 Col[22] 是概念码非缺失基础指标，不得据覆盖缺口误判。

- ZHB main_net_buy_amount/1d、hands/1d = **竞价额/竞价量**(键名历史遗留, 非主力)

- **Pearson 会被单点离群绑架**(n=20 时一个大 2 个数量级的样本即可造出 r>0.95 假相关)——必做 Spearman + 留一法

  当 raw 响应字段与公开契约逐项对应（如 FTShare REST 文档字段）时，契约可确认该精确路径的语义并作为日常碰撞锚；契约本身仍不证明底层来源独立。
- 🔴 **财务锚多日命中 ≠ 独立证据**: 同一报告期内是常量, 独立性来自**报告期切换**
  (fuyao `fin_report` 于 20260825 由 `2026-1`→`2026-2`), 要求 ≥3 日**且**跨 ≥2 报告期。
