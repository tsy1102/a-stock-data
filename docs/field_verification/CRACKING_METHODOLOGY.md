### ⚠️ 核心铁律: ZHB 数据日期 = 最近交易日快照（非机械 T-1, 2026-08-27 固化 / 2026-08-27 修正）

> **ZHB 本地包 = 最后一个已收盘交易日(最近交易日)的快照**, 不是机械地等于"运行日前一天"。
> - **交易日运行(盘中/盘后)**: ZHB 仍是昨日(T-1)收盘数据, 落后于当日 reports(当日报告的
>   涨停池/天梯/行情= T 日实时) → 此时"T-1"成立, 不能拿当日报告对撞当日 ZHB。
> - **休市日运行(周末/节假日)**: 无 T 日新数据, ZHB 日期 = 最近交易日 = 任何报告实际分析的
>   数据日(如周六采集=周五收盘) → 与"当日(休市日)报告"对撞**有效**, "T-1"措辞反而误导
>   (因无 T 日可比, ZHB 日期即报告数据日)。
> **对撞破解的硬规则是"按交易日日期对齐", 不是"按日历 T 禁止同日比"**: 用 ZHB(zhb_date=D)
> 对撞**交易日 D 当日报告**; 若对撞运行日 T 且 T≠D, 须验证字段是否已刷新到 T(涨停族
> type/lianban/count 实测为 T 日盘中值)。
> (2026-08-27 初犯: 交易日用 8/27 天梯对撞 8/27 采集 ZHB(8/26)得 type 0/20 假阴性——因
> ZHB 仍是 T-1。休市日不存在此陷阱, 因 ZHB 日期=报告数据日。)

**正确对撞矩阵（按 zhb_date 对齐, 而非按日历 T）**：
| 采集场景 | ZHB 数据日期(zhb_date) | 应对撞的 reports |
|---|---|---|
| 交易日采集 | 最近交易日 = T-1(前一日) | **T-1 当日报告**(该日涨停池/天梯/连板) |
| 休市日采集(如周六) | 最近交易日 = 周五 | **周五报告**(=该休市日报告实际分析的数据日) |
| 连续采集次日 | zhb_date 推进到新最近交易日 | 对应该 zhb_date 的报告 |

- **核心逻辑**: 连续采集下, "今日最新 ZHB(T-1)" 正好等于 "昨日报告的数据日"——
  用 8/27 采集的 ZHB(8/26 数据) 对撞 8/26 报告, 或对撞 8/27 报告(因 ZHB 涨停族等
  实时字段实际已刷新到今日盘中)——**两条路径都可, 但必须标注所用报告日期**
- **操作规范**:
  1. 每次对撞**先打印 `raw_zhb.json` 的 `zhb_date`** 与所用报告文件名/日期
  2. 若 ZHB 日期(D)≠运行日 T(即 T 为交易日且 ZHB 仍滞后), 优先对撞 **D 当日报告**(日期严格对齐);
     若 D==运行日 T(休市日场景, ZHB 日期=报告数据日), 直接对撞当日报告即可
  3. 若对撞当日报告, 需**验证字段是否实时刷新**(如涨停族 type/lianban/count 实测
     为当日盘中值, 虽快照 date=T-1)——逐字段验证, 不可假设
  4. 结论标注所用 ZHB 日期 + 报告日期(如 "8/27 采集ZHB(8/26) + 8/26报告")
- **例证(2026-08-27 V17.0.10)**: type(Col33)=连板数 的破解正是靠"8/27 采集 ZHB +
  8/27 天梯"得到 20/20 完全匹配; 若误用 8/26 报告则 0/20 全错

## 〇·二、对撞判定标准（用户定义，2026-08-29 固化 / 唯一权威定义）

> **对撞 = 扫描同一日期、不同源返回的「相同数字」的字段。**
> 若其中某一个字段已经被破解，则可**反推**与之同值的未知字段 = 那个已破解字段。

**对用户定义的规则，这就是全部内容，没有第二条。**
唯一证据只有一项：**逐股数值相等**。除此之外（序号、字段名、排列位置、相关性）都**不是**判定证据。

### 边界澄清（助手补充，⚠️ 不是规则，2026-08-29 因表述不当被纠正）

- **序号（列号 / 键名 `fNN` / `[N]` / 数组下标）只是字段的一种表现形式，不是字段本身。**
  - 不能因为两源序号**一致**，就默认它们是同一字段；
  - 也不能因为序号**不一致**，就默认它们不是同一字段；
  - 更不能单独因为"字段名或序号一致"就默认不同源的该序号代表同一个字段。
  - "同序号 = 同字段"只能是对撞成立后的**结果**，绝不能当作推理的**前提**。
- 实测反例（用来说明边界，本身不是规则）：push2 `f85`=流通股本(股)、`f86`=收盘时间戳，
  而腾讯 `[85]`/`[86]` 与二者完全不同 → 这两源**不可按序号互相当锚**（锚定必须走数值对撞）。
- ⚠️ **2026-08-29 事故**：助手曾把上面这条边界澄清写成"**同序号 ≠ 同字段**"并标注为"用户设定的规则"。
  **该表述已撤回**——用户从未设定这样一条规则。用户设定的只有开头那段"相同数字"规则；
  序号相关的一切都属于**对该规则边界的说明**，不是独立规则。

### 执行门槛（务必逐条遵守）

1. **门槛**：逐股精确值相等 **≥8/20** 才可宣告"同一字段"。
2. **容差分级**：
   - 精确相等（rel_tol=1e-9）→ 可判同一字段。
   - 1% 容差命中 → **只能证明"同族"**（如同属价格类、同属股本类），**不能**证明同一字段。
3. **相关性 ≠ 对撞**。相关性只能作为辅助筛选，**永远不能单独作为破解结论**（见下）。
4. **多日复核（2026-08-29 晚增补，PART G 实战固化）**：
   - 有连续采集数据时，任何"对撞命中"必须在 **≥3 个独立采集日重复出现**才可作为候选；
     单日命中一律视为巧合（实测案例：0813 腾讯[85]/[86] 全 0 占位，对 0 值字段造出 19-20/20
     满值假命中，多日一剔除即消失）。
   - 扫描前必须先做**数据质量盘点**：剔除"目标字段全 0/全 None"的采集日（占位零值空撞）、
     跳过采集失败股（键存在但无 fields）。
   - 扫描器必须**排除同源对**（同一响应行内的字段对齐不是跨源对撞证据）。

### ⚠️ 相关性陷阱与强制流程（2026-08-29 血的教训）

**事故**: 腾讯[86] 与 level-1 委差 Pearson **r=+0.965**，一度被判为"[86]=委差 L2"。
实际是 **601288（农业银行）单点绑架**——其量级比其余 19 股大 2 个数量级，同时主导了两个变量的方差。

| 检验 | 结果 | 判定 |
|---|---|---|
| Pearson（全样本 n=20） | +0.965 | 假强相关 |
| **Spearman ρ**（秩相关，抗离群） | **−0.012** | 相关性不存在 |
| **留一法 Pearson**（剔除 601288） | **−0.863** | **符号翻转** |
| 符号一致率 | 12/20 | 弱 |
| 对撞精确 / 1% 容差 | **0/20 / 0/20** | 完全不满足 |

→ **结论撤回，[86] 恢复 ❓未知。**

**强制流程**（任何"字段 A ≈ 字段 B"的判定，三条**必须全过**，缺一不可）：
1. **对撞**：逐股精确值相等 ≥8/20（1% 容差仅可标注"同族"）。
2. **相关性**（辅助）：Pearson 与 Spearman **同号**，且 **|Spearman| > 0.6**。
3. **留一法**：剔除任一样本后相关系数**不翻号**。

**相关性只能用来"生成候选"，不能用来"定案"。**

## 一、八大破解思路(按优先级)

### 1. 命名规律(拼音/英文/中英混合)
- 官方字段名=中文拼音首字母(ZAF=涨跌幅/fLianB=量比/fHSL=换手率/Zsz=总市值)
- 纯英文(Average/MainBusiness)、中英混合(FreeLtgb=Free+流通股本/ZTPrice=涨停+Price)
- **后缀族**: Amo=Amount 金额、Z=自由流通、Price/Flag/Num/Date/Vol/Value/PreN/Recent
- 例证: vzangsu=v+涨速→量涨速、gb_info Zgb/Ltgb=总/流通股本、OpenAmo=开盘金额

### 2. 表头说明文件对照

- ⚠️ **腾讯 [6]成交量/[7]外盘/[8]内盘: 科创板(688)单位是「股」, 其余板块是「手」**(2026-08-29 实测: 成交额÷(量×现价) 反推每手股数, 688 段=1.01~1.02, 其余=99~101)。
  凡用成交量做**量级占比**类推理(如"某字段占成交 X%")必须先统一单位, 否则科创板样本会错 100×。
  代码侧已修(V17.0.12): `core/tdx_client.py::_tencent_volume_divisor` + `sc_datasource.get_tencent_quote` ÷100;
  专项测试 `tests/core/test_tencent_volume_unit.py` 8 例全过, 全量回归 277 passed(基线 269+8)。
  ⚠️ 采集脚本 `scripts/capture_field_probe.py` **刻意保持 raw 不归一**——归一会污染字段破解数据。
- **本地 TDX lday 陈旧 + 有缺口**(实测止于 2026-08-14; 2026-07-07 缺失)——日期匹配须用**最近交易日 ±3d 容差**
