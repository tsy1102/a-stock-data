# 待确认字段的每日证据覆盖

## 数据边界

采集完成后，`capture_field_probe.py` 从已有 `raw_*.json` 和 `meta.json` 生成本地覆盖索引。覆盖器不调用数据接口、不读取原始值后落盘，也不修改采集日期、来源日期、缓存或主字典状态。

明细写入 `.tmp/field_evidence_coverage/coverage_YYYYMMDD.json`，该目录由 Git 忽略。当前采集日的 `meta.json` 只保存索引状态、覆盖计数和本地文件路径。相同数据日再次运行会重算并替换同名覆盖文件；较早数据日使用独立文件名，不会覆盖更新日期的索引。

## 身份匹配

- 权威身份为注册表中的 `(source, 完整 code path)`。短 code 聚合只用于兼容视图，不能作为采样归属依据。
- 覆盖器沿用碰撞脚本的原始记录扁平规则，并用 `source_lineage.json` 的运行时别名和路径规范化建立精确映射。
- ZHB 的 `stat`、`stat2`、`tipinfo` 分别映射到对应来源身份；`full` 是合并视图，不计入逐源覆盖。
- 一个运行时别名和字段路径若对应多个注册表身份，会标为歧义并排除计数。找不到身份的路径也会在诊断中列出；不会猜测归属。
- `verified` 但缺少规范名/含义的记录，以及疑似含复合文本的字段会作为补充复核目标；`disproved` 不进入目标队列。

## 日期与覆盖口径

- 行情样本通过 `collision_dates` 校验交易日历并按来源、来源日期去重；覆盖窗口取最近 7 个有效交易日。
- 行情数据必须有明确的来源 `as_of_date`。阶段判定按来源数据日与实际采集日/时刻进行：来源日期早于采集自然日（如盘前采集上一已完成交易日、周末或节假日采集最近交易日）可判为 `closed`；不要求采集发生在 15:30 之后。同一自然日的样本仍需按实际采集时刻/阶段判定。只有筛选器认定为 `closed` 且来源日期有效的样本才计入“来源日期覆盖”；盘中或时段未知数据仅作候选，不冒充来源日期证据。
- 公告、新闻等自然日事件使用记录本身可解析的事件日期；文件夹日期不代替事件日期。
- 每个字段分别记录候选日期、合格来源日期、日期样本数、快照阶段、来源状态和来源独立性。覆盖数表示可审阅样本，不等于语义确认、独立锚或 L1 定案。
- 字段的变化频率与来源日期保障分开分类：逐源策略值见 [`temporal_policy.json`](temporal_policy.json)，运行时资格逻辑见 [`scripts/temporal_policy.py`](../../scripts/temporal_policy.py)。静态/缓变字段可以贡献“仅语义、日期未确认”的 L1 关系；这不会增加“来源日期覆盖”计数，也不能证明数据新鲜度。每日变化及未分类字段仍须有明确来源日期才能计入 L1。
- 历史运行日、逐源采集日、目标数据日和来源日期的只读核验由 [`audit_source_date_mapping.py`](../../scripts/audit_source_date_mapping.py) 完成；它仅读取保留起点之后的 `meta.json`，不会把目录名或通用目标日期补作来源日期；旧记录缺逐源采集日时会标出目录级日期回退依据。

## 五大报告脚本的来源身份边界

五大报告输出是面向阅读的分析 Markdown，不提供与注册表完整路径一一对应的来源证据清单。短线/中线规范数据对象保留运行时 `field_sources`；估值脚本的批量行情缓存也保留内部来源映射。长线、市场状态及最终报告正文没有完整字段路径身份。字段破解所需的原始路径和来源日期由采集归档中的 `raw_*.json`、`scheme` 和 `meta.json` 提供，因此覆盖器读取采集归档，不从报告文本反推来源。

## 生成与核验

```powershell
.\scripts\run_with_system_python.ps1 scripts\refresh_field_registry_projection.py --check
.\scripts\run_with_system_python.ps1 scripts\gen_field_dict.py --check
.\scripts\run_with_system_python.ps1 scripts\registry_parity.py
```

`refresh_field_registry_projection.py` 默认只检查；只有明确使用 `--apply` 才会重建 `fields` 兼容聚合投影。每日覆盖不会调用它，也不会自动写回逐源字段。

## 碰撞报告中的每日汇总源证据

碰撞报告可以汇总采集阶段保存的来源核验记录。这些记录只提供来源身份与接口运行状态证据，不自动确认字段语义、写入主字典或触发网络请求。来源核验的路由、日期匹配和退出/复验条件见 [`scripts/README.md`](../../scripts/README.md)；报告完整性按 [`COLLISION_REPORT_REVIEW.md`](COLLISION_REPORT_REVIEW.md) 审阅，正式裁决按 [`ADJUDICATION_WORKFLOW.md`](ADJUDICATION_WORKFLOW.md) 执行。

## 字母字段名称候选

碰撞 JSON 还会列出所选 raw 窗口中出现、且注册表语义或元数据待审的字母字段。候选清单按 `(source, 完整 code path)` 与 `field_registry.json` 精确关联，并附当前状态、候选拆词、采样日期和来源 inventory。已确认字段仅在规范名、含义或单位存在缺口时作为元数据补录候选。

拼音、英文、缩写、CamelCase 和混合命名的拆词结果都标记为名称线索；它们不是数值证据，也不会进入 L1 锚或自动改变状态。Markdown 为便于阅读最多显示前 100 条，JSON 保存完整候选列表。新字段出现后若不在现有名称清单中，会按运行字段做无翻译的拆词提示；需要新增中文候选时，应先更新审计 inventory，再由人核对。

## 碰撞门槛

L1/L1-U 的有效样本、信息样本、精度、比例和来源资格门槛只在 `scripts/collision_rules.py` 定义；`COLLISION_RULES.md` 是生成镜像。本页说明覆盖索引的日期与身份口径，不复制运行阈值。

## 公开股票页面的佐证边界

每日碰撞审阅后先按来源谱系确认实际数据提供方，再按 [`PUBLIC_WEB_VERIFICATION.md`](PUBLIC_WEB_VERIFICATION.md) 优先使用其官方文档和官网查询页面核验标签与历史值。新浪、同花顺等第三方页面仅在它们是登记来源或官方页面缺少可比资料时作为次级佐证。网页查询属于主动研究记录，不计入采集覆盖数、L1 来源数或独立来源数，也不会更改 `meta.json`、来源日期、raw 或 registry。只有逐样本对齐股票、来源有效日期/报告期、阶段和单位的观察才可作为数值佐证；页面当前值、搜索摘要及单点吻合不证明历史字段含义。

逐候选结果写入带日期的网页核验备忘录，并在现有人工候选审阅记录中引用。原始来源路径仍须通过已定义的碰撞、单源契约或公式裁决路径定案；页面标签不能替代适配器映射证据。

## 实测覆盖与上游契约是两类证据

每日覆盖索引回答“某个精确来源字段在多少个有效数据日有可审阅样本”；它不自动决定含义。跨源相同字段关系仍须达到数值碰撞规则并经人工复核。若某字段没有独立锚，但权威接口/协议契约和项目适配器映射足以定义它，可按 [`ADJUDICATION_WORKFLOW.md`](ADJUDICATION_WORKFLOW.md) 单独走上游契约核验。

单源契约结论只确认字段本身的定义，不声称它与其他来源相同，也不建立 `mappings` 或来源锚资格。`unknown_fields.md` 中“含义栏文本”与“历史状态解析结果”是两个独立维度：已有文字仍可能未验证，状态解析为 `matched` 也不等于语义正确；其分项计数不能相加。
