# 未知字段官方来源网站核验流程

本流程在每日采集和碰撞报告完整审阅后运行，用字段所属提供方的官方文档和官方查询页面核对碰撞或名称拆解提出的字段假设。先按 `source_lineage.json` 确认注册来源对应的实际数据提供方，再查其官方接口文档、字段字典或官网查询页面。新浪、同花顺等页面只有在它们本身就是该字段的登记来源，或原提供方没有可比的公开历史数据时，才作为次级佐证。一般页面观察不会自动证明项目原始路径的身份；精确同日逐值匹配可按 [`ADJUDICATION_WORKFLOW.md`](ADJUDICATION_WORKFLOW.md) 的官方页面观测裁决路径审核。该路径还要求证据备忘录保存规范化 `[observation]` JSON 行，并由应用器核对来源谱系和官方主机名白名单；未满足这些条件不能改写主字典。

## 证据边界

- 证据对象仍是注册表中的精确来源身份，即来源加完整字段路径；不得只按 fNN、别名或中文猜名做全局合并。
- 先核对 [`source_lineage.json`](source_lineage.json) 与 [`source_repository_map.md`](../source_repository_map.md)，区分实际数据提供方、客户端、SDK 和聚合包装层。对每个精确来源路径，优先访问数据提供方自己的官网、官方数据字典、接口文档、公告或登录后查询页面。
- 项目中通达信（TDX）、同花顺、东方财富、新浪、开盘啦（KPL）、开盘红（KPH）等已登记来源，均优先查询其各自官方网站和官方产品页面。具体入口以来源谱系与适配器实际映射为准，不根据简称猜域名或把同一平台的不同接口合并成一个路径。
- 官方接口/协议文档是字段路径、参数、单位与更新规则的首选定义证据；提供方官网的股票查询页面可佐证其公开指标标签和值。交易所、监管机构和上市公司材料可独立核对底层事实，但它们的日期、复权、报告期与厂商字段口径可能不同，比较时须逐项对齐。
- 新浪、同花顺等页面若是当前候选字段的实际登记来源，就属于该来源的官方页面；若候选来自其他提供方，它们才是第三方交叉参照。第三方页面不能替代对应提供方的官方证据，也不能代表其接口契约。搜索摘要、论坛和转载只用于寻找线索。
- 页面显示某项数值与候选原值吻合，可以支持字段含义假设，但该页面可能采用不同上游、计算口径、复权方式或舍入精度。它不能单独证明来源谱系、底层接口映射、来源独立性，也不能代替现有 L1/L1-U、单源契约或公式裁决门槛。
- 报告中的 `candidate_triage.approximate_matches` 是独立的近似数值筛查层，窗口为相对差 0.5% 或原值绝对差 0.01（取较宽者），只负责提示可复核的字段对。它不计入 L1/L1-U、正式候选审阅或注册表证据；筛查命中不证明差异由舍入导致，也不证明字段等价。
- 比较前按目标字段的时间语义分类，不能一律要求网页日期等于采集日：日快照/行情值须对齐股票、市场、来源 `as_of_date`、交易阶段和单位；财报/披露值须对齐报告期、会计口径及披露/更正版本；已完成且结果固定的历史事件（如已实施分红、已完成解禁）按同一事件核对，事件日期不必等于采集日期。币种、复权、精度和舍入口径也须一致或有可复核换算。
- 对已完成的历史事件，至少匹配同一股票、事件类别与状态、事件日期、数值/数量及单位，并确认事件在原始样本截止时已经发生或公开，且没有后续更正、撤销。若字段表示“最近一项”“下一项”或其他有选择规则的事件，必须验证其选择范围和截止日；不能拿任意旧事件或数值巧合充当命中。网页抓取时间只说明何时查看，不能替代事件日、披露日或来源数据日期。
- 当前网页值不能直接证明历史采集时来源曾返回该值。若问题涉及历史可用性或来源当时的状态，还需有截止日前的公告、历史页面/快照或其他时间证据；缺少这类证据时，网页可以支持稳定语义，但不能证明历史可用性。

## 每日执行位置与候选顺序

1. 先完成 [`DAILY_RUNBOOK.md`](DAILY_RUNBOOK.md) 的采集归档核对，再按 [`COLLISION_REPORT_REVIEW.md`](COLLISION_REPORT_REVIEW.md) 审查报告完整性和候选明细。报告缺失、候选集合不完整或数据日期不合格时，不用网页值掩盖采集/报告缺口；可查公开定义，但明确标注这不是历史样本验证。
2. 每轮最多处理 5 个候选路径（包括延续的待补证项），控制重复查询并让待办能跨日推进。先处理有新日期/新假设/新材料可补的 needs_external_evidence 项，再处理本轮有明确数值/公式假设且可在公开页面观察的候选，最后从 unknown_fields.md 按项目脚本消费价值与完整路径顺序继续未研究项。不要只读碰撞报告的 Top-N 摘要，也不要随机抽字段。
3. 对同一来源路径已有研究记录时，只有出现新假设、新有效日期样本或更强证据才重查。每次记录已完成、未决、被反证和本轮停止位置；未处理项留待后续每日运行，不得汇报为全量完成。
4. 优先使用提供方无需登录的官方文档/页面。网页核验使用用户授权的 Chrome 会话；不要以预检 TUN、DNS 或出口路由作为打开页面的前置条件，也不要为此更改 VPN、TUN 或系统代理设置。这一浏览器操作规则不改变生产采集的直连策略；Google Drive 上传仍由其独立配置处理。若官方查询页需登录，只使用用户本人已授权的会话查询公开股票指标和字段资料；不得索取、复制或保存密码、cookie、token，也不得访问个人持仓、订单或账户信息。低频逐项打开并遵守网站访问规则；不得绕过验证码、付费墙或其他访问控制。页面无法访问时标为 `blocked`，不反复试探。

## 单个候选的核验步骤

1. 从完整碰撞报告或未知队列中抄录 candidate_id（若有）、来源、完整字段路径、数据日期、候选解释、替代解释、原始采样值和来源日期。通过 source_lineage 确认实际提供方与官方站点；先写出能区分候选解释的观察条件，避免只寻找支持当前猜测的页面。
2. 优先使用该提供方的官方接口文档和官方查询页。通常用至少 3 只不同股票核对标签和候选值；行情/其他随时间变化字段至少覆盖 2 个有效交易日或报告期；已完成历史事件至少覆盖 3 只股票的不同事件实例，并加入能区分相近事件或数量口径的案例；静态分类字段至少比较 3 个有区分力的案例。单只股票或单一事件的吻合只记为线索。
3. 每条比较记录页面明确显示的名称、值、单位、字段有效日期/报告期/事件日期、事件状态、页面更新时间及原始样本截止日；按字段时间语义与 raw 逐项对齐。必要的单位换算、复权或精度容差写明公式和依据，不得为迎合候选临时放宽。走官方页面精确观测裁决时，原始单位与页面单位不同须在每条结构化观测中填写 `raw_to_display_factor`，由应用器按“原始值 × 换算因子”复核页面舍入刻度；不得只改写原始值来制造数值相等。近似筛查命中还须记录双方原值、误差公式、各自展示精度与来源口径，并保留全部不匹配样本；不能仅凭近似命中进入定案。
4. 页面只显示标签而无值时，结论只能是 `label_only`；日快照/财报期/事件身份无法按其各自时间语义对齐时为 `inconclusive`。若同一事件或同口径样本仍稳定不符，记录 `contradicted` 并检查替代解释；这不自动表示目标字段已被证伪。

## 留证与裁决

每次运行将研究记录写入 `docs/field_verification/adjudications/public_web/YYYYMMDD_public_web_research.md`。一份记录可包含多个候选，但每个候选单独列出：

- 碰撞报告相对路径、报告 SHA-256、candidate_id（如有）、精确来源与完整字段路径；
- source_lineage 解析出的实际数据提供方、官方站点/文档及其与登记来源的关系；若使用第三方页面，写明回退原因和证据等级；
- 候选解释、至少一个替代解释、要验证的区分条件；
- 每个网站的名称、精确 HTTPS 页面链接、带时区的访问时间、页面标签/值/单位/有效日期或报告期；
- 股票代码、raw 来源日期/阶段、页面样本日期/阶段；事件字段另记事件类别、状态、事件日期、截止时是否已公开/完成；以及换算、容差依据和逐样本匹配结果；
- 结果状态：value_corroborated、label_only、contradicted、inconclusive 或 blocked；结论范围、仍缺证据和后续动作。

只摘录复核所需的标签和数值，不整页复制网站内容。候选人工审阅决定的 evidence_refs 同时引用这份本地记录与相关网页链接；理由中写明实际打开页面核对过的内容。网页链接本身不证明内容已审阅，应用工具也不会替复核人访问网页。

公开页面若确认了候选解释，但仍不能把项目字段路径映射到页面指标，候选保持 `needs_external_evidence`，不更新注册表。研究备忘录本身不是定案：用于跨源映射且已有 `candidate_id` 的对象，须按 ADJUDICATION_WORKFLOW 完成人工候选审阅，并引用本地备忘录和相关网页；来源内语义若通过精确同日逐值门槛，可另用 `public_web_observation` 路径定案，不创建跨源映射。已验证字段的补充佐证只记入研究证据，不重复创建映射或注册表变更。网页数据不成为独立碰撞锚，除非来源谱系另有证据确认独立。

每日结果汇报核验了多少个新路径、各状态数量、已形成的证据、未决路径数和下次继续位置；采集失败或网页受限要单独列出，不算作候选已排除。

## Eastmoney 研报记录级观测

`reports::author`、`reports::researcher`、`reports::lastEmRatingName` 与 `reports::emRatingCode` 是不同的原始路径。仅当注册表存在这些路径的参考状态冲突时，才可用裁决模式 `resolve_report_record_conflict`：每个目标至少三只不同股票、同一采集日期，并将官网行与保留的 `raw_reports.json` 记录按 `infoCode`、标题、发布日期逐项精确绑定。采集目录日、网页访问日和研报发布日期分开记载。

证据记录须包含每只股票的准确官方个股研报 URL、带时区的实际访问时间、页面记录行、报告日期、标题链接的 `infoCode`，以及 `[observation]` JSON 行。`reports::author` 核对原始 `ID.姓名` 数组与页面作者链接，并以 `authorID` 数组交叉校验；`reports::researcher` 核对同一顺序的姓名与原始逗号分隔字符串。`reports::lastEmRatingName` 只核对评级未变的记录：页面“东财评级”必须与原始 `emRatingName`、`lastEmRatingName` 相同，页面“评级变动”必须显示“维持”，原始 `ratingChange` 必须为已验证的 `3`。不得用这条规则解释已上调、下调或首次覆盖记录。`reports::emRatingCode` 的代码本身不在网页显示；需将官网当前东财评级名称与同记录的 `emRatingName` 绑定，并扫描完整同日归档验证每个已观测代码是否只对应一个名称。结论仅确认代码字段角色及样本中已见值的关系，不提供完整代码表。空单位必须保留。此证据不证明未公开 API 的完整契约、不生成跨源映射，也不把网页作为独立碰撞锚。

`reports::sRatingCode` 使用独立模式 `verify_report_source_rating_code`，仅针对当前无元数据冲突的未验证字段。核验至少三只不同股票的官方研报详情页，以详情 URL 中的 `infoCode`、标题和日期绑定原始归档行；正文中的机构原始评级文字至少须有两条与同记录 `sRatingName` 精确匹配。文字近似必须独立标记，当前仅允许“买入”与“买入(Buy)”这一明示关系。还须扫描完整同日归档：每个机构+代码只对应一个原始评级名称，同时相同代码跨机构对应多种名称。结果只确认机构原始评级类别代码的字段角色，不建立跨机构码表或跨源映射，不覆盖完整 API 契约。

决策模板：作者/研究员使用 [`public_web_report_record_template.json`](adjudications/public_web_report_record_template.json)；前次评级使用 [`public_web_report_last_rating_template.json`](adjudications/public_web_report_last_rating_template.json)；东财评级码使用 [`public_web_report_em_rating_code_template.json`](adjudications/public_web_report_em_rating_code_template.json)；机构原始评级码使用 [`public_web_report_s_rating_code_template.json`](adjudications/public_web_report_s_rating_code_template.json)。已核验记录示例：[`20261110_reports_authors.json`](adjudications/public_web/20261110_reports_authors.json)、[`20261110_reports_last_rating.json`](adjudications/public_web/20261110_reports_last_rating.json)、[`20261110_reports_em_rating_code.json`](adjudications/public_web/20261110_reports_em_rating_code.json) 与 [`20261110_reports_s_rating_code.json`](adjudications/public_web/20261110_reports_s_rating_code.json)，各自证据文件记录实际网页观测及证据边界。
