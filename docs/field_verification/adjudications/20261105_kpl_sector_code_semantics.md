# KPL `raw_columns.col_19`：稳定分类码语义裁决

## 范围与来源身份

- 身份：`开盘啦(kpl_limit_up_detail)::raw_columns.col_19`，完整路径按 registry 登记。
- 项目适配器 `stock_common/sc_kpl.py` 的 `get_kpl_limit_up_detail()` 从原始响应行构建 `raw_columns` 时保留行号；同一解析器把 `row[19]` 输出为 `sector_code`。
- 独立锚：`开盘红::industry_id`，注册表已有 verified 状态。
- 交易日来自 KPL/KPH 原始记录各自的 `trade_date`，不按采集目录日期对齐。

这三个差异说明不能登记 `raw_columns.col_19` 与 KPH `industry_id` 的逐值等同映射。它们不否定该字段属于行业/板块分类代码：解析器位置映射、字符串代码形态及 417 组同日同股完全对照共同支持该来源内语义；具体分类体系和层级仍未确认。

## 裁决

- 将 KPL `raw_columns.col_19` 登记为 verified：`sector_code`，语义为“行业/板块分类代码（具体分类体系与层级未确认；不与 KPH industry_id 保证逐值等同）”；该字段是分类 ID，不填物理单位。
- 不新增 `mappings`；KPL 与 KPH 的具体分类码仍按来源分别保留。
- 当前日碰撞候选审阅中的 `needs_external_evidence` 仍适用于“两个字段是否逐值等同”的关系，不再阻止 KPL 字段本身的来源内语义进入字典。
- 数据仅覆盖 2026-10-16 以后保留样本。报告：`docs/field_verification/20261105/20261105_collision_report.json`；SHA-256：`e3fd803b1d7129b716a24bbe6a48b2324e852587408e0507d5220cb6d9151af5`。
