# reports::actualLastYearEps / actualLastTwoYearEps：2026-11-12 定向复核（分项裁决）

## 结论

本轮按字段范围分别裁决：`actualLastYearEps` 已定案为研报记录对应的上一完整财年实际 EPS，单位 `元/股`；统一分母算法和历史回溯时点仍未证实，不纳入本次定案。`actualLastTwoYearEps` 继续未验证，因为保留的 8 条记录中它与 `actualLastYearEps` 完全同值，无法证明它确实指向前两年，也无法解释为什么两列重复。

本次结论遵循“先定已证实语义，另列未证实算法”的范围拆分：法定加权平均 EPS 的差异不再单独否决上一年度角色；力合微精确股本时点列为公式待核。相邻字段的待核点则是实际期间值无法区分，需找到能区分上一年度与前两年度的上游定义或有效样本。

## 来源链与样本范围

- 项目 stock_common/sc_datasource/_financials.py::get_reports() 请求东财 https://reportapi.eastmoney.com/report/list，参数 qType=0，保留 API 返回行。
- scripts/capture_context_collectors.py::collect_reports() 调用该函数采集研报。
- 2026-11-12 对此前保留期审计出的 8 个非空 infoCode 做了只读 API 复查，覆盖 4 只股票。8 条当前 API 返回仍均为 actualLastYearEps == actualLastTwoYearEps，且值与先前保留期记录相同。
- 这次请求发生于 2026-11-12；行内 publishDate 是研报发布日期，不证明 API 中两个 EPS 数值在该发布日期即为同一快照。不得把当前查询时间或研报发布日期直接当成字段实际数据日期。

样本明细见 20261112_reports_actual_eps_live_samples.csv。

## 2026-11-12 追加：股本分母复核

此前把“与财报基本/稀释 EPS 不同”直接作为反例过于简单。进一步计算后，样本值与“上一年度归母净利润 ÷ 研报 API 采用的股本分母”呈现强匹配；分母可能在送转、IPO 等股本变化后重算，和财报按加权平均股数列示的法定 EPS 不是同一口径。

`f84` 的证据仅来自东方财富 `https://push2.eastmoney.com/api/qt/stock/get` 的个股 `stock/get` 响应；同名字段在 `ulist.np/get` 列表响应中口径不同，不能混用。查询日为 2026-11-12，因此当前行情响应本身不能证明历史研报 API 当时采用的股本日期。太湖远大的 IPO 股本与发行人 2023 年归母净利润可在北交所招股说明书中逐项复算；力合微的股本变化按其年报及权益分派材料核对。

**更新后的判定：** `actualLastYearEps` 已按“上一年度实际 EPS，元/股”写入 registry；力合微的股本分母日期仍为公式层待核，不推翻已确认的字段角色。`actualLastTwoYearEps` 在 8 条记录上与前者完全重复，尚无一条有效证据能区分前两年值，继续单独未定案。后续应优先找东财对该字段的明确期间定义或出现两年度 EPS 不同且原始值可追溯的记录；不要把公式问题再用作阻止 `actualLastYearEps` 语义落库的条件。

## 判定与下一步

1. `actualLastYearEps` 已定案的范围仅是上一年度实际 EPS 角色和单位；统一分母算法、调整日期与历史回填时点仍未知。
2. **不把全部差异视作舍入误差。** 力合微股数残差保持量化且待核；其他样本的差别按公开股本口径精确复现，均未被当作法定 EPS 等价。
3. 两列不能合并或共用状态。`actualLastTwoYearEps` 的全部当前观测与前者重复，既不能据此验证前两年语义，也不能推导别名。
4. 对 `actualLastTwoYearEps`，需要官方字段释义或能区分两个财年的有效样本；对 `actualLastYearEps`，只有新发现的真实期间反例才会重开语义裁决，分母公式问题继续单独跟踪。
