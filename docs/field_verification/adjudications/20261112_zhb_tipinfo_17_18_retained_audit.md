# ZHB `tipinfo.dat` `[17]` / `[18]` 保留期复核

## 范围与结论

按根目录 `AGENTS.md` 的保留边界，只读取文件名数据日不早于 `20261015` 的 ZHB 压缩包。本机当前共有 17 个日期包，最晚为 `zhb_20261110.zip`。逐包读取 `tipinfo.dat` 后，共检查 96,128 行；每行均有数字股票代码，原始列 `[17]`、`[18]` 的非空值均为 0。逐包日期、行数、文件 SHA-256 和列计数见 [`20261112_zhb_tipinfo_17_18_coverage.csv`](20261112_zhb_tipinfo_17_18_coverage.csv)。

本次复核没有发现可用于解释这两列的新样本，**不改变** `ZHB-tipinfo::[17]` 和 `ZHB-tipinfo::[18]` 的未验证状态。观察窗内为空不能证明永久保留、停用或占位，也不能推导字段语义。

## 复核方法

- 只枚举并读取 `cache/zhb/zhb_YYYYMMDD.zip` 中 `YYYYMMDD >= 20261015` 的包；未读取保留起点以前的 raw、ZHB 包或解析缓存。
- 每个包要求恰有一个 `tipinfo.dat`，以 GBK 严格解码，按 `|` 分列，统计原始列 `[17]`、`[18]` 的非空值；异常会终止审计，不静默跳过。
- 逐包 SHA-256 写入 CSV，便于复算时确认归档输入没有变化。
- 最新项目解析器 [`core/zhb_client.py`](../../../core/zhb_client.py) 记录了 `tipinfo.dat` 的已知位置字段，但没有把 `[17]`、`[18]` 解释为业务字段；该实现状态与本次原始行扫描一致。

## 公开资料核查

- [通达信量化平台官方文档](https://help.tdx.com.cn/quant/docs/markdown/TdxQuant.md/mindoc-1h10m001ic888.html)说明 `get_financial_data` 等量化 API 的财务字段和日期参数；该页面没有定义桌面端 `zhb.zip` 中 `tipinfo.dat` 的原始列 `[17]`、`[18]`，两者不能混作同一接口契约。
- [N2XK/easy-tdx-plus 的数据字典](https://github.com/N2XK/easy-tdx-plus/blob/main/docs/%E6%95%B0%E6%8D%AE%E5%AD%97%E5%85%B8.md)是第三方解析项目，不是通达信官方字段表。其页面把 `get_zhb_positional` 描述为对未确认文本文件的通用 `c0..cN` 位置解析，并明确把 `tipinfo.dat` 列为语义未完全确认文件；因此它没有为本项目这两列提供可采纳的字段定义。
- 对公开代码搜索中的其他 `tipinfo.dat` 行样本只观察到文件布局，未找到能说明 `[17]`、`[18]` 语义的权威注释或字段表。样本行本身不作为定案证据。

## 当前处置

两条路径保持逐源未验证。只有出现非空列样本，或取得明确覆盖这两个原始列的通达信契约，才继续区分实际业务含义与保留/停用列等候选；届时仍需核对完整来源路径，不能只凭短列号写回主字典。
