# 2026-11-17 ZHB-tipinfo `[17]` / `[18]` 低信息样本复核

## 结论

在当前保留窗口内，`ZHB-tipinfo::[17]` 与 `ZHB-tipinfo::[18]` 都没有可用于推断语义的非空观测。两列保持 `unverified`，不填入猜测含义，也不据此标记为永久无用、占位符或 `disproved`。按低信息字段规则，它们暂不参与普通数值碰撞；后续出现有效非空值时再恢复分析。

## 样本范围与质量

- 扫描 ZHB 文件名日期不早于 `scripts/capture_retention.py::MIN_CAPTURE_DATE`（2026-10-15）的全部 `zhb_YYYYMMDD.zip`。按每日运行卡，归档文件名是 ZHB 数据日依据。
- 共扫描 20 个归档，日期范围为 2026-10-15 至 2026-11-13；`tipinfo.dat` 共 113,098 条有效股票行。
- 每行均有 22 列且包含股票代码；短行/缺代码 0 条，重复股票代码行 0 条。
- `[17]` 非空值 0 条；`[18]` 非空值 0 条。没有发生可供日期/数值/枚举分析的变化。
- 每个归档的文件名、归档 SHA-256、行数、列宽和两列非空计数见 [`research/20261117_zhb_tipinfo_17_18_retention_scan.csv`](../research/20261117_zhb_tipinfo_17_18_retention_scan.csv)。该清单 SHA-256：`1852ddbdce11057eb068776cb93a7e28550f8d471b2ffd83f64f80be8beea4a6`。

项目解析器 [`core/zhb_client.py`](../../../core/zhb_client.py) 将原始 `[13]`、`[14]` 等列映射为解禁字段，但没有把 `[17]` 或 `[18]` 暴露为业务字段；本次判断直接基于压缩包内的原始 `tipinfo.dat` 列值，不把解析器未暴露当成字段无意义的证据。

## 官方资料边界

通达信官方[公式函数列表](https://help.tdx.com.cn/gspt/docs/markdown/redword/functionlist.html)把 `DYNAINFO(17)` 定义为量比、`DYNAINFO(18)` 定义为上涨家数。这是公式函数编号，不是 `tipinfo.dat` 的列定义；不得据编号相同推断 `ZHB-tipinfo::[17]` 或 `[18]` 的含义。此次定向查询没有找到能把这两个 `tipinfo.dat` 原始列号直接映射到官方字段名的契约。

## 后续触发条件

当任一列在合格的新 ZHB 归档中出现非空值时，记录归档文件名、完整原始行和列值，并先判断值形态（日期、数值、枚举或文本），再按官方接口/协议、公开财报或事件页面寻找可证伪的语义假设。相同来源日的重复采集不算独立日期样本；在此之前不因持续为空而虚构业务解释。
