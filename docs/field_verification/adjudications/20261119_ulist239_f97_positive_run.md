# Eastmoney Ulist239 `f97` 连续正值长度来源内实证定案

- 复核日期：2026-11-19
- 精确字段身份：`东财-ulist239(np/get)::f97`，原始路径 `stocks[code].data.f97`
- 证据类型：单源实证（`empirical_source_field_semantics`）；不建立跨源映射。

## 结论

在连续、来源日期合格的 Ulist 样本中，`f97` 遵循以下递推关系：

```text
f97(t) = f97(t-1) + 1，若当日 f88 > 0；否则为 0。
```

将精确来源内含义登记为：**从当前数据日起连续统计 `f88 > 0` 的交易日数（含当前日），当前 `f88 <= 0` 时计为 0**。规范名为 `f88_positive_streak_days`，单位为“个交易日”。

这确认的是 Ulist `f97` 对同一 Ulist 响应中 `f88` 的可复算关系；`f88` 的业务标签仍未知。本结论不把 `f88` 称为 DDX，不宣称取得了 Eastmoney 对 `f97` 的接口字段定义，也不推断未观测情形下的服务端回填规则。

公开检索到的[第三方 F 参数表](https://2048ai.net/682d7411606a8318e858a2bb.html)把 `f97` 列为连续飘红天数，但没有找到 Eastmoney 将该标签直接映射到 `ulist.np/get::f97` 的官方字段表。[Eastmoney 官方产品页](https://www.dfcfw.com/static/product/index.html)能确认其提供 DDE 决策功能，不能证明此接口键的标签。因此这些网页仅作术语线索；定案依据是下述原始响应路径与同源逐日递推实证。

## 逐日递推结果与反证控制

2026-11-02 作为已观察序列的左边界，每只股票的初始 `f97` 不用于计算命中。2026-11-03 至 11-10 的六段连续交易日转移，共有 120 个同股相邻日比较：

- 当日 `f88 > 0`：48/48 条均满足 `f97(t)=f97(t-1)+1`。
- 当日 `f88 <= 0`：72/72 条均满足 `f97(t)=0`。
- 合计 120/120 精确符合递推关系，未发现反例。20 只股票在多个相邻日期反复出现，不将 120 项误称为 120 个独立时间序列。
- 阈值控制：把递增条件改为 `f88 >= 0` 得到 119/120；唯一不符为 2026-11-09 的 `920508`，当日 `f88=0`，实际 `f97=0`，而含零模型会递增至 3。改用 `f88 != 0` 仅 49/120 符合。

逐行原值、前日值、递推预测、阈值控制和残差见 [`逐行 CSV`](../research/20261119_ulist239_f97_positive_run.csv)，共 120 行；规范 LF SHA-256：`e938345c991782b7c66168d86e7561e5fea06e4645f40cd0ad21876267c96b47`。2026-11-02 的 20 行用于起始状态，2026-11-17 和 11-18 的 40 行因中间 Ulist 来源日不连续而排除；它们既不计作命中，也不计作反例。可用完整连续窗口不足以对 10 日字段 `f99` 作相同验证，故 `f99` 仍保持未验证。

## 裁决边界

本裁决只确认精确来源路径 `东财-ulist239(np/get)::f97` 的观测公式，不把同号字段扩展到其他接口，不建立 `mappings`，不推断 `f88` 的金融业务含义。相邻日前后递推关系与严格 `>0` 阈值在 120 个合格比较中全部吻合，足以确认该字段是对 `f88` 正值连续段长度的来源内计数；缺失采集日如何由服务端处理仍不在证据范围内。
