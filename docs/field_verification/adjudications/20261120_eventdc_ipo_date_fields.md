# Eastmoney IPO `APPLY_DATE` 与 `LISTING_DATE` 定案

复核日期：2026-11-20

## 定案

- `东财-event_dc(IPO发行记录)::ipo_calendar[].APPLY_DATE`：该 IPO 记录所列的**申购日期**，是发行事件日期；不是采集日、来源数据日或上市日期。
- `东财-event_dc(IPO发行记录)::ipo_calendar[].LISTING_DATE`：该 IPO 记录所列的**上市日期**，不是申购日期或采集日期。

仅登记这两个完整来源路径，不创建跨源映射。页面另有 `SELECT_LISTING_DATE` 等键；即使标签相近，也不据此合并或推定它们与本决定中的字段同义。

## 官方字段标签与项目路径

项目 [`_events.py`](../../../stock_common/sc_datasource/_events.py) 将 `ipo_calendar` 请求映射到东方财富 DataCenter 的 `RPTA_APP_IPOAPPLY`，并把响应行放入 `raw_event_dc.ipo_calendar[]`。东方财富[新股申购数据页](https://datapc.eastmoney.com/da/Purchase/Index)的表格模板将 `item.APPLY_DATE` 放在“申购日期”列，将 `item.LISTING_DATE` 放在“上市日期”列。该页面没有发布带版本号的字段 schema；本次于 2026-11-20 实际核对当前页面模板。

精确采集路径分别为：

```text
_events.py::_EM_REPORTS['ipo_calendar']
  -> RPTA_APP_IPOAPPLY response.data[*].APPLY_DATE
  -> ipo_calendar()
  -> raw_event_dc.ipo_calendar[].APPLY_DATE

_events.py::_EM_REPORTS['ipo_calendar']
  -> RPTA_APP_IPOAPPLY response.data[*].LISTING_DATE
  -> ipo_calendar()
  -> raw_event_dc.ipo_calendar[].LISTING_DATE
```

## 边界线索

同一 20 条样本还包含 `APPLY_DATE_NUM`。20/20 记录满足：

```text
APPLY_DATE_NUM + (APPLY_DATE - 1899-12-30).days = 56346
```

这证明当前样本中的数值可由申购日期精确反向编码，零偏差；但官方页面模板没有解释 `APPLY_DATE_NUM` 的字段定义、固定锚点用途或是否为仅供排序的内部键。故本次**不**据此定案 `APPLY_DATE_NUM`，也不把它误称为 `YYYYMMDD`；保留为待继续核实的接口线索。
