# 东方财富 IPO 日期类字段核验（2026-11-23）

## 核验范围

- 来源身份：`东财-event_dc(IPO发行记录)::ipo_calendar[]`，上游接口 `RPTA_APP_IPOAPPLY`。项目 `stock_common/sc_datasource/_events.py::ipo_calendar()` 通过 `eastmoney_datacenter(columns="ALL")` 读取；适配器保留原始响应键，写入 `raw_event_dc.json`。本次没有运行项目采集器。
- 历史样本：保留期内 20 个 `raw_event_dc.json` 批次（目标数据日 2026-10-16 至 2026-11-19），共 400 行；逐行数据及每批原始文件 SHA-256 见本目录 CSV。
- 网络核验：2026-11-23 13:16（Asia/Shanghai）访问东方财富官方 IPO 详情页，并对同一证券代码 `002520` 做一次公开接口字段核对；这不是项目日常采集。

## `MARKET_CAP_CONFIRMDATE`

- 400/400 行均非空且值唯一：`T-2日(T:申购日)`；20/20 批次无批内冲突。样本证券代码均为深市 `0` 前缀。
- 东方财富官方详情页将相应显示项标为“网上申购市值确认日”，值为 `T-2日(T:网上申购日)`；同代码 `002520` 的官方 `RPTA_APP_IPOAPPLY` 响应键 `MARKET_CAP_CONFIRMDATE` 返回 `T-2日(T:申购日)`。
- 深交所《深圳市场首次公开发行股票网上发行实施细则（2018年修订）》第4条：T 日为发行公告确定的网上申购日，按 T-2 日前 20 个交易日（含 T-2 日）的日均市值计算。
- 结论：该键表达网上申购市值确认日的相对交易日规则，T-2 不是自然日差两天；这是一段规则文本，不是旧 IPO 记录的绝对历史日期、来源更新日或行情观测日。裁决范围限于本批深市样本，不外推北交所。
- 边界：Eastmoney 未发现版本化字段 schema；详情 HTML 的显示节点使用 `OFFLINE_END_DATE` 样式类，因此证据记录的是“同证券代码的官方 API 值 + 官方详情页标签/值 + 深交所规则”的语义闭环，不宣称发现了该 API 的公开 schema 定义。

## `UP_DATE`

- 历史 400 行均有值；20/20 批次各自只有一个批次值，跨批次观察到 20 个不同值（2026-10-16 00:00:00 至 2026-11-20 00:00:00）。
- `UP_DATE` 与目录 `data_date` 相同的批次数：16/20；与实际采集运行 `capture_date` 相同：12/20；与 `event_dc.source_capture_date` 相同：8/20。它不能替代这三种日期中的任何一种。
- 同代码 `002520` 的官方接口记录 `APPLY_DATE=2010-12-01`、`UP_DATE=2026-11-23`；因此它不是该 IPO 的申购日或上市日。其在每批 20 条不同时代证券记录中完全一致，符合上游批次/数据记录更新标记。
- 结论：来源字段可登记为东财 IPO 记录的上游更新日期标记，不能作为行情 `as_of_date`、采集日期或业务事件日期。由于没有版本化字段说明，不能进一步断言这是数据库行级变更时刻还是整个数据集刷新日期；日期值显示午夜 `00:00:00`，不代表精确更新时间。
