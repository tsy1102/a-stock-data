## 0. 评估结论：是否有必要集中建文件？——**有必要，且已实证其必要性**

判定依据（本轮逐项核实刚暴露的问题）：

1. **既有调研报告存在 2 处实质性下标错误**，若直接沉淀进 `field_dict` 的 L1 结论将污染定案：
   - 腾讯 qt：原称"45=流通市值、46=总市值、48=PB" → 实测应为 **44=流通市值、45=总市值、46=PB**。
   - 东财 push2：原称"f44=最高/昨收、f50=PB" → 实测应为 **f44=最高、f60=昨收、f50=量比、f167=PB**；且原稿遗漏了社区文档间 `f116(总市值) vs f84(总市值)` 的**跨源冲突**。
2. **跨源"同号异义"陷阱在社区文档层同样存在**（东财 `f116`=总市值 在 skillsmp 文档中=换手率、`f84`=总市值），只有结构化、带"端点+版本+URL+核实日期"的注册表才能防止误用。
3. **L1 终止器要求可追溯来源**：方法论规定 L1 仅由"同源精确对撞"或"厂商官方字段表"终止，社区表须标注来源与版本方可作强佐证。
4. **腾讯 qt 实际字段数远超旧稿认知**（旧稿称"仅 0~59"）→ 实测延伸至 **~index 90**，旧稿的"schema 不完全对齐"判断需据此修正（见 §5）。

**结论**：建立本中央化文件，每条映射含 `来源/官方性/核实方式/核实日期/置信度/冲突备注`，后续任何 L1 定案必须引用本表条目，禁止凭记忆套用下标。

## 5. 与本项目字段的映射（含旧稿 schema 判断修正）

- `tx[7]`/`tx[8]`=内外盘：与腾讯 qt[7]/[8] **完全一致**（强佐证，已由三源+L1 定案）。
- `tx[45]`=总市值：与腾讯 qt[45]=总市值 **对齐**（但 raw_tencent 与 qt 为**部分同构 schema**，非逐下标等同——见 `tx[83]` 在 qt= -0.10、在 raw_tencent=占位'0'，证明非完全同构）。
- `tx[56]`=Beta：腾讯 qt **无 Beta 字段**（qt 仅基础行情+估值），故**无法经公开表升 L1**；L1 路径仅"同窗口同基准第三方 Beta 精确对撞"（已 Pearson 0.991，依铁律#5 仍非 L1）。
- `tx[85]`=价格类：raw_tencent 与 qt 部分同构，但 `tx[85]` 是否=qt[85] 需实证比对（qt[85] 对茅台为空，与"当前价"语义矛盾，提示非简单同构）→ 见验证计划。
- **schema 判断修正**：旧稿"raw_tencent 与 qt 不完全对齐"成立，但原因不是"qt 仅 0~59"，而是"两者为部分同构的独立契约"；对齐下标有 {7,8,29,45,...}，非对齐下标有 {83,...}。引用时须逐下标实证，禁止整体套用。
