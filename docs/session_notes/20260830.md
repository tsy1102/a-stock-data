### 5. ⚠️ 踩坑记录（防重复，按重要性排序）

1. **Windows 回收站按子目录拆分记录** —— 只扫文件级记录会得出"大量文件永久删除"的
   **错误结论**，进而用 git 覆盖掉未提交编辑。**先整体恢复再比对**。
2. **回收站 `$I` 文件路径提取**：必须按 **UTF-16LE 字节串搜索**路径针，再回溯到盘符、
   前推到 `\x00\x00`；**不要**硬编码 `0x04`/`0x14` 偏移（本机实测取到乱码）。
3. **Git Bash 里 `$Recycle.Bin` 必须转义**成 `\$Recycle.Bin`，否则 shell 展开成 `C:/.Bin/...`。
4. **git status 假阳性**：`core.autocrlf=true` + `.gitattributes`（`*.md text eol=lf`）会让
   `git status` 显示 ` M`，但 `git diff HEAD` 为空、`git hash-object` 与索引 blob 一致。
   **判改动一律用 `git diff --stat`**，不要信 status 的脏标记。
5. **测试计数必须用 pytest 的 `collected`**，不能 `grep -c "def test_"`（漏掉参数化展开）。
6. **mock `asyncio.run` 永不执行协程** → `RuntimeWarning: coroutine was never awaited`。
   统一用 `_closing_run()` 替身先 `coro.close()` 再返回/抛错。
7. **调用次数量级要按函数分别钉**：sht `_get_index_quote` 是 **4 次**（四个指数各一次），
   按"缓存类查询各 1 次"统一断言会假红。
8. **跑测试用 `-m "not real_network"`**；写成 `-m pytest` 会把全部用例 deselect 掉
   （`pytest` 是脚本默认 token，不是 marker）。
9. **先回答基本问题，别先造工具**：本次我先写了备份比对脚本再回答"回收站是否完整"，
   被用户当场打断——**"简单问题复杂化"**。正确顺序：确认完整性 → 整体恢复 → 校验 → 清理。
