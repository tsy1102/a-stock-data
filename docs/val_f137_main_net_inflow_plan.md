# VAL 引擎 · 竞价额集群升级为「真实主力净流入（东财 f137，盘后）」方案

> 数据来源：通达信聚合数据管线（canonical 层含腾讯 / 东方财富 / 同花顺多源，f137 主力净流入取自东方财富主域 `stock/get`）。
> 约束：本报告所有结论均不构成投资建议。
> 适用范围：`get_val_report.py` VAL 全市场发现引擎（当前 23 策略，编号 01–23 连续无空洞）。

---

## 1. 现状与痛点

VAL 引擎当前含一组**竞价额集群**（合并重编号后对应 **策略17【主力净额占比】/ 策略18【量能加速度】/ 策略19【资金动能】**）：

- 这组策略以**盘中竞价额 / 量能 / 加速度**作为主力资金的*弱代理（weak proxy）*。
- 其优势是**盘中可用、实时性强**，但本质是"代理变量"，与机构真实资金动向存在口径偏差。
- 真正的**主力净流入**数据（东方财富 `f137`，单位：元，与现有 canonical `f137` 一致）属于**盘后 datacenter** 数据，当前引擎**未将其作为独立策略维度**纳入发现。

**核心问题**：是否要把竞价额集群"升级替换"为 f137 真实主力净流入？

---

## 2. 决策结论：方案 A（新增 + 正交，非替换）

**结论：不替换，采用方案 A——新增一条盘后「主力净流入」策略，与竞价额集群正交互补。**

理由：

| 维度 | 竞价额集群（策略17/18/19） | 新增 f137 主力净流入策略 |
|------|--------------------------|------------------------|
| 数据时点 | **盘中**实时/准实时 | **盘后**（datacenter 收盘后可得） |
| 变量性质 | 弱代理（竞价额/量能代理资金） | 真值（主力净流入金额） |
| 可用性 | 盘中扫描、盘中预警可用 | 盘后复盘、隔夜选股可用 |
| 互补性 | 捕捉盘中异动 | 补全机构资金维度 |

二者**时间窗口正交、语义正交**，不存在冗余，故应"新增补全"而非"替换替代"。竞价额集群保留作盘中代理，f137 盘后策略补全机构资金真值维度。

## 4. f137 字段语义与数据护栏（关键）

> 依据项目 `working_memory` 既定铁律，取数必须守住以下边界，否则会**静默污染估值字段**。

1. **f137 主域语义**：东方财富主域 `stock/get` 的 `f137` = **主力净流入（元）**，与 canonical 已落地字段一致，可直接经 `get_canonical_stock_data` 读取。
2. **东财跨端点「同号异义」铁律（红线）**：
   - 主域 `stock/get`：`f164 = pe_ttm`（估值），**不可在主域读 f164 当资金流**。
   - `ulist.np` 端点：`f164 = 近5日主力净流入（元）`、`f165 = 占比%`。
   - 若需"近 N 日主力净流入趋势"，**必须显式走 `ulist.np` 端点**（`get_em_fund_flow_multiday`），并在注释写明端点；**严禁**在主域读 `f164` 当资金流（会直接污染 `pe_ttm`）。
3. **跨接口对撞实证**：`f62(ulist) ↔ f137(stock/get) = 主力净`、`f66 ↔ f140 = 超大单净`、`f72 ↔ f143 = 大单净`，可作交叉校验。
4. **真机验证铁律**：凡新增取数封装，必须实跑一次真实接口确认返回非 `None`（类比 TDX 适配器静默失效铁律——f137 走东财 HTTP 非 TDX，但同理需真实验证，离线 mock 抓不到静默失效）。

## 7. 结论

- **不将竞价额集群升级替换为 f137**——二者时间窗口与语义正交，应保留竞价额作盘中代理。
- **采用方案 A：新增盘后「主力净流入」策略（策略24）**，以东方财富 `f137` 盘后真值补全机构资金维度，与竞价额集群（策略17/18/19）正交互补。
- 本方案为**设计文档，非本次实施**；实施时严格按 §5 步骤并守住 §4/§6 护栏，跑通测试防线后方可合入。
